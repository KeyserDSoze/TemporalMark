# API PostgreSQL Entra — explicit Container Apps opt-in and pre-listen SQL privilege gate (#134)

**Scoped prequalification, NOT an authorized Azure deployment or production cutover.** This runbook describes application wiring now present in the .NET 10 API for a *future, independently approved* Entra-only pilot. It does not create a managed identity, make PostgreSQL Entra-only, provision SQL roles, rotate credentials or attest actual Azure connectivity. See [ADR 0100](../adr/0100-explicit-api-entra-postgres-prelisten-privilege-gate.md), [#134](https://github.com/KeyserDSoze/TemporalMark/issues/134), parents [#128](https://github.com/KeyserDSoze/TemporalMark/issues/128) / [#18](https://github.com/KeyserDSoze/TemporalMark/issues/18), [Npgsql token candidate](ENTRA_POSTGRES_NPGSQL_CANDIDATE.md), [ACA token supplier](AZURE_CONTAINER_APPS_POSTGRES_IDENTITY_CANDIDATE.md), [runtime identity Terraform candidate](AZURE_POSTGRES_RUNTIME_UAI_CANDIDATE.md) and [SQL role preflight](POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md).

## Existing default: OSS on-prem and active Azure remain unchanged

When `RegistryPostgres:AuthenticationMode` is **absent**, the API still registers its existing `NpgsqlDataSource.Create(ConnectionStrings:Registry)` and follows the current, independent SQL connection-string credential flow. The explicit literal `Password` selects that same legacy mode. This retains the existing Keycloak/PostgreSQL 17 on-prem development and deployment paths without mandatory Azure dependencies. Any unknown/blank/case-altered mode **fails startup** rather than silently choosing an authentication path. The current Azure Terraform reference does **not** opt in to Entra and **still sets** `azurerm_postgresql_flexible_server.registry.administrator_password = var.postgres_password`; current and historic Terraform state can contain the admin password. The #127 versioned Key Vault API SQL connection-string secret reference does not remove that risk.

## Future, explicitly authorized Container Apps Entra candidate

The API supports only this **literal** opt-in value:

`RegistryPostgres:AuthenticationMode=ContainerAppsEntraCandidate`

It must run with ASP.NET `Production` environment. That environment name is **not** evidence of CAB authorization, SQL grants or a tested cloud production setup; the deployment owner must approve every requirement independently.

| Configuration | Intended source | Constraint |
|---|---|---|
| `RegistryPostgres__AuthenticationMode` | Deployment-approved operator configuration | Exactly `ContainerAppsEntraCandidate` |
| `RegistryPostgres__UserAssignedClientId` | Approved client GUID of a **dedicated PostgreSQL runtime** UAI | Canonical lowercase nonzero GUID, not the Blob system identity or Key Vault identity |
| `RegistryPostgres__ExpectedRuntimeLogin` | Reviewed SQL role map | Exactly matches the explicit connection-string `Username`; no tenant/HTTP-derived role |
| `ConnectionStrings__Registry` | Operator-controlled secret/config reference | Passwordless `Host=<approved>.postgres.database.azure.com;Port=5432;Database=<approved>;Username=<approved-runtime-role>;SSL Mode=VerifyFull;GSS Encryption Mode=Disable` |
| `IDENTITY_ENDPOINT` | **ACA platform-injected process environment only** | Strict HTTP loopback `localhost`/127.0.0.1/::1, explicit port, safe path, no external DNS/IMDS or query |
| `IDENTITY_HEADER` | **ACA platform-injected confidential process environment only** | Required platform header with no controls; never log or check into application settings |

Do not enter actual secret, token, identity header, connection string or customer identifiers in repository files, CI variables, logs or command-line arguments. Above strings are configuration illustrations, **not runnable live credentials**. The root `infra/azure/candidates/entra_postgres` creates a *separate non-applied* UAI metadata candidate (#132); it is **not** attached to the active API and exports only provider-computed IDs, which mock plans cannot verify. Terraform never performs actual SQL role mapping.

### Startup sequence and fail-closed behavior

1. The API reads the opt-in **before DI registration**. Unknown mode is denied immediately; Entra mode is denied outside ASP.NET Production.
2. `ContainerAppsEntraApiRegistryCandidate.Create` validates an independently approved client GUID, exact expected SQL login, canonical Azure PostgreSQL hostname, explicit port/user/database, `SSL Mode=VerifyFull`, GSS disabled and **no Password/Passfile/TLS bypass**, and a strict local ACA identity endpoint/header. It composes the existing Npgsql 10 token provider with the existing ACA local REST client. **Construction makes no HTTP request or PostgreSQL connection**.
3. After `builder.Build()` but **before health endpoint registration, API route mapping or `app.Run()`**, the API sets a 15-second total startup cancellation budget and calls `VerifyAtStartupAsync`. This opens a **real async** Npgsql connection (token request for the fixed `https://ossrdbms-aad.database.windows.net/.default` scope; ACA REST uses `resource=https://ossrdbms-aad.database.windows.net`). Npgsql requires private TLS certificate **VerifyFull** against the approved host.
4. The previously tested `PostgresRuntimePrivilegePreflight.VerifyAsync` executes one **read-only PostgreSQL catalog/ACL SELECT** on that actual connected session, requiring exact `session_user=current_user`, reviewed runtime role membership and necessary SELECT/INSERT privileges; it rejects superuser, built-in/Entra `azure_pg_admin`, provisioner/approver/registrar groups, schema/database CREATE, org/membership mutation and privileged bootstrap EXECUTE. The check is not a DDL or SQL GRANT.
5. If any validation, token, PostgreSQL private connectivity, expiry, TLS, privilege or timeout check fails, the API **aborts before binding an HTTP listener** with one generic error; no inner server/token/hostname details, SQL password fallback, ambient Azure credential or retry. The data source and local HTTP identity client are disposed at stop. A successful one-time preflight **does not prove** that roles cannot drift later or pooled connections are immediately revoked on role/token change.

The API's existing JWT verification, tenant-admin DB checks, private stamp/audit/search endpoints and qualified-issuance denial are unchanged. Migrators, separate provisioner/approver/registrar CLI and reviewer SQL interlocks remain on their existing paths; they are **not** made Entra-aware by this API-only slice.

## Separate approved staging and rollback gates — parent #128 / #18 remain OPEN

Before any real enablement, security/DB/cloud operators must independently verify and approve: Entra tenant, Entra Group administrator custodianship, dedicated UAI **client versus object/principal ID**, Container Apps explicit UAI attachment, **non-admin** PostgreSQL principal in `postgres` via an authorized Entra database administrator, least-privilege SQL grants against the application database and functions, account ownership/default ACLs/role revocation, preflight compatibility, controlled migration-owner and reviewer/registrar identities, private PostgreSQL DNS/TLS and root certificate trust, actual ACA identity endpoint shape, token expiry/re-issuance/pooled session revocation, backup restore and two-tenant regression on a real Azure pilot, break-glass and CAB rollback. Record separate owner sign-offs. If the SQL role is missing, **do not grant admin or disable the preflight to make startup succeed**.

The legacy Azure server/Key Vault reference still uses password authentication and still stores its PostgreSQL bootstrap password in current/historical Terraform state. Production remediation requires separate controlled state access/rotation, historical snapshot review and safe data migration; do not blind-apply an isolated new-server root, destroy a live registry, remove credentials without a rollback plan or equate an Azure plan with production safety.

## Registry/audit table privilege denial at the API Entra startup gate (#141)

Under explicit ContainerAppsEntraCandidate only, the one-time SQL pre-listen check now refuses the application login when effective UPDATE or REFERENCES (table-wide **or any one column**) or DELETE/TRUNCATE/TRIGGER permissions exist on timestamp_registry or tenant_audit_events. Such extra rights must be fixed by approved SQL administrators, never by disabling startup inspection. This is independently exercised using PostgreSQL 17 test-only disposable roles [#141](https://github.com/KeyserDSoze/TemporalMark/issues/141) / [ADR 0106](../adr/0106-postgres-append-only-acl-prelisten.md). Default on-prem Password mode, active Azure Terraform, 20 migrations and production grants remain unchanged. The new checks are not a WORM promise or real Entra UAI staging attestation; #128/#18/#17 remain OPEN. See [preflight runbook](POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md).

## Tenant administrator/membership table ACL hardening (#142 / ADR 0107)

The **explicit**, Production-only `RegistryPostgres:AuthenticationMode=ContainerAppsEntraCandidate` path now fails before HTTP listening if the real PostgreSQL runtime session can UPDATE any organization/membership column, has any REFERENCES privilege on a table or column, or has table TRIGGER rights. These checks use `has_any_column_privilege` and `has_table_privilege` in the one existing read-only prelisten SELECT, in addition to the former INSERT/DELETE/TRUNCATE and org/tenant checks. Test-only disposable roles in real PostgreSQL 17 proved eight missing denies RED before code; see [ADR 0107](../adr/0107-postgres-tenant-invariant-acl-prelisten.md), [#142](https://github.com/KeyserDSoze/TemporalMark/issues/142). These checks do **not** modify PostgreSQL grants or schemas and do not run in default Password mode. Production Azure UAI authentication, private SQL grants, historical Terraform admin password exposure, CAB rollout/rollback and qualified-evidence custody remain independently blocked by #128/#18/#14/#17.

## Runtime Entra candidate startup checks direct V019 quota table privilege (#146)

The explicit Production-only PostgreSQL Entra-candidate API startup SQL preflight now rejects **either** owner-only V019 quota state table when its effective runtime SQL login can directly SELECT tenant/principal information (including column-only actor-subject SELECT), INSERT (including per-column), UPDATE, DELETE, TRUNCATE, REFERENCES or TRIGGER. PostgreSQL 17 `has_any_column_privilege` covers table-wide or per-column SELECT/INSERT/UPDATE/REFERENCES; a table check alone does not suffice. The two protected tables are `public.imprint_search_rate_tenants` and `public.imprint_search_rate_principals`. Existing `EXECUTE public.consume_imprint_search_rate(uuid,text)` **remains permitted** and still operates under a reviewed SECURITY DEFINER policy; actual 12 actor / 30 tenant per fixed database minute enforcement and 429/Retry-After are unchanged. These new conditions are only a read-only *point-in-time* ACL posture check on an authenticated PostgreSQL session; they are **not** SQL role migrations, continuous checks or a live Azure principal test. See [ADR 0111](../adr/0111-search-quota-sql-acl-prelisten.md), [#146](https://github.com/KeyserDSoze/TemporalMark/issues/146) and [preflight runbook](POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md). Real tests-only [RED 44935299721](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44935299721) confirms 18 unexpected preflight acceptances before the minimal [source fix 853eb5d](https://github.com/KeyserDSoze/TemporalMark/commit/853eb5d8768ed929bec9c8fd915d2accdb077814). Azure managed ingress, SQL UAI mapping, Terraform admin-password remediation, owner DDL and incident/CAB remain #128/#18.

## Function EXECUTE denial supplement for explicit Entra API mode (#147)

The same point-in-time, read-only prelisten PostgreSQL ACL check now rejects effective `EXECUTE` granted **directly to the runtime SQL login**, inherited from another group or granted to PUBLIC on seven privileged/owner-only SQL functions. Merely verifying that the API LOGIN is *not a member* of `temporalmark_provisioner_group`, `temporalmark_approver_group` or `temporalmark_credential_registrar_group` does **not** detect such function-level grants. See [ADR 0112](../adr/0112-privileged-function-execute-postgres-prelisten.md) and [#147](https://github.com/KeyserDSoze/TemporalMark/issues/147) for the seven exactly typed signatures, including SECURITY DEFINER enrollment/approver/legacy registrar and SECURITY INVOKER owner-only staging/cleanup. Real PG17 RED [Actions 44942023228](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44942023228) confirmed **7 unexpected preflight acceptances, 139 other tests passing** before minimal source [`4877bc0`](https://github.com/KeyserDSoze/TemporalMark/commit/4877bc003c7a9798f10035bf0ca67a095638c580).

The `public.consume_imprint_search_rate(uuid,text)` function remains intentionally executable by API runtime; SQL V001–V020, GRANT/REVOKE roles, passwordless token-only candidate, TLS, ACA environment and default mode are unchanged. The real cloud SQL identity/PG grants/CI rollout must still be independently validated; #128 and #18 cannot be closed by an offline PostgreSQL17 fixture. Owner and post-start ACL drift are not covered; no CAB approval, WORM, QTSP or GDPR DPIA claimed.

## Sensitive enrollment/reviewer table SQL ACL drift (#149)

The explicitly selected Production `ContainerAppsEntraCandidate` API PostgreSQL pre-listen now additionally denies effective `SELECT/INSERT/UPDATE/REFERENCES` (including one-column GRANTs) and `DELETE/TRUNCATE/TRIGGER` on the migration-owner-controlled V006 `organization_enrollment_requests` and V012 `organization_decision_challenges`. Normal application SQL runtime is **not authorized** to read original pending organizational identities or unconsumed unsigned reviewer challenge nonces directly. The preflight performs only one already-authenticated, read-only PostgreSQL catalog query and never retrieves or edits domain rows. Exact scope in [ADR 0114](../adr/0114-enrollment-review-table-acl-prelisten.md) / [issue #149](https://github.com/KeyserDSoze/TemporalMark/issues/149); real PostgreSQL RED [real PG17 Actions 44952204344](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44952204344) confirmed **18 expected unauthorized-acceptance tests failing with 148 existing passes** before the two-table (14-predicate) SQL source fix. The standard V019 quota function and usual registry/audit INSERT remain allowed, default on-prem/legacy Azure Password mode unchanged. Real Azure Entra credentials/grants, network, UAI attachment and Terraform admin password history still require independent approval (#128/#18), while reviewer WebAuthn human signature, custody/legal status remain #38/#17/#13.


## SET ROLE to arbitrary privileged NOLOGIN PostgreSQL roles (#150)

An explicitly selected Production `ContainerAppsEntraCandidate` API SQL runtime principal must not only lack elevated attributes on its **current** login, it must also lack membership in **any** role having `SUPERUSER`, `CREATEDB`, `CREATEROLE`, `REPLICATION` or `BYPASSRLS` privileges. PostgreSQL can enable the target role through SET ROLE even without inheritance, including indirect memberships. [ADR 0115](../adr/0115-arbitrary-privileged-role-membership-prelisten.md) introduces one conservative read-only `pg_roles` / `pg_has_role(...,'MEMBER')` deny in the already-open authenticated one-shot SQL prelisten. No new SQL connection, role switches, GRANT/REVOKE/DDL, application endpoint, token provider or Terraform changes. Genuine [real PostgreSQL 17 RED CI 44954527922](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44954527922): **7 expected unsafe acceptance assertions failed / 166 existing passes**, real PG17; normal runtime passes without privileged membership. Deployment remains **undeployed** until independently approved Azure Entra UAI, SQL grants, secure admin Terraform state migration and CAB (#128/#18). Neither default Password mode nor privileged CLIs uses this gate, and no signed human reviewer approval, custody/WORM or eIDAS qualification is provided.


## V010 replay proof and V013 registrar intent/RP policy ACL drift (#151)

The explicit Production `ContainerAppsEntraCandidate` API requires owner-only SQL access to `organization_reviewer_decision_proofs`, `reviewer_registration_intents` and `reviewer_registration_rp_policies`. A runtime LOGIN cannot directly SELECT even one proof digest, registrar/reviewer subject, nonce or pinned RP origin, nor INSERT/UPDATE/REFERENCES at table or column granularity, nor DELETE/TRUNCATE/TRIGGER either table. [ADR 0116](../adr/0116-reviewer-replay-registrar-rp-table-acl-prelisten.md) adds **21 fixed, read-only privilege checks** in the existing prelisten catalog query without new SQL connection, any `GRANT` or schema/trigger/function execution. [real PG17 RED CI 44956181715](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44956181715) verified 27 missing-denial cases / 173 previously passing real PG17 tests before the source patch. This guards only **hypothetical SQL ACL drift**, not real Azure Entra SQL grants/certificates, live user identity, independently signed reviewer WebAuthn decision, verifiable registrar credential, or production CAB. #128/#18/#50/#38/#17 remain open; current OSS Password-mode API and Azure Terraform unchanged.


## PostgreSQL V017 candidate evidence and sequence SQL permission drift (#152)

The **explicit Production-only Entra candidate API** prelisten now rejects direct SQL runtime `SELECT/INSERT/UPDATE/REFERENCES` at table-wide or individual-column scope, plus `DELETE/TRUNCATE/TRIGGER`, for V017 owner-only `mds_unapproved_candidate_checkpoints` and `mds_unapproved_candidate_events`. An extra direct GRANT on the V017 `mds_unapproved_candidate_events_event_id_seq` identity sequence `USAGE`, `SELECT` or `UPDATE` is independently rejected; table and sequence rights differ in PostgreSQL17. [ADR 0117](../adr/0117-v017-owner-candidate-sequence-acl-prelisten.md) / [#152](https://github.com/KeyserDSoze/TemporalMark/issues/152): 17 additional static catalog predicates in the **same existing read-only authenticated-session SQL query**, with no SQL role/user DDL, runtime connections, actual candidate reads or tenant data writes. True [real PostgreSQL 17 RED CI 44957628860](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44957628860): **21 missing-denial xUnit failures with 200 earlier passes** before source patch. V017 candidate metadata remains always **UNAPPROVED**, no FIDO device enrollment, independent witnessed monotonicity, real Azure PostgreSQL Entra UAI rollout or CAB is provided. Default OSS Password mode and actual Azure Terraform remain unchanged.


## Future-fail-closed relation ACL inventory (#153)

The **nondefault Production `ContainerAppsEntraCandidate`** SQL admission query now enumerates the PostgreSQL17 `public` schema's catalog relations, not just previously hardcoded V001–V020 sensitive tables. Only `organizations`, `organization_memberships`, `timestamp_registry` and `tenant_audit_events` may have direct runtime table/column ACLs, subject to their existing finer SQL restrictions; any other public table/partition/view/materialized view/foreign table with SELECT/INSERT/UPDATE/REFERENCES (whole or one column) or DELETE/TRUNCATE/TRIGGER is rejected. Any public sequence with USAGE/SELECT/UPDATE is rejected. Existing positive API SQL grants, function execution and owner-only restrictions are preserved and remain the source of truth. [ADR 0118](../adr/0118-public-relation-privilege-inventory-prelisten.md) / [#153](https://github.com/KeyserDSoze/TemporalMark/issues/153); real [real PG17 RED CI 44960966724](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44960966724) before source fix demonstrated **17 missing denials / 221 existing passes** using actual PG17 generated relation fixtures and V004/ledger. No Azure apply, SQL grant or table mutation, default OSS Password-mode change or live Entra UAI verification occurred. A new API-accessible public relation requires explicit review, ADR, migrations and tests before updating the allowlist. This is not protection against new schemas, after-start GRANT drift, SQL owner bypass or qualified eIDAS/WORM trust.


## Entra SQL runtime may not EXECUTE unreviewed SECURITY DEFINER routines (#154)

Beyond the prior named SECURITY DEFINER deny list, the explicitly opted-in Production `ContainerAppsEntraCandidate` SQL prelisten now scans **all non-system PostgreSQL routine catalog entries** `pg_proc.prosecdef` / `prokind=f,p` with `has_function_privilege(oid,'EXECUTE')`, including newly introduced functions/procedures, overloads, distinct non-system schemas, direct role GRANTs and implicit PUBLIC defaults. **Only the exact V019 `public.consume_imprint_search_rate(uuid,text)` OID** remains allowed; existing explicit SQL role/table/sequence/function privilege conditions remain. [ADR 0119](../adr/0119-security-definer-function-execute-inventory-prelisten.md) documents why PostgreSQL defaults to EXECUTE for PUBLIC and why an apparently unprivileged SQL LOGIN must not access an owner-privileged routine. Genuine [real PostgreSQL 17 RED CI 44962732379](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44962732379) proved eight expected missed denials / 239 existing and invoker control successes, after an initial fixture-only SQL quoting repair. The prelisten does not change SQL GRANTs, schema, functions, API routes, Azure Terraform or OSS Password mode. Future V021+ SECURITY DEFINER runtime EXECUTE requires independently reviewed ADR, tests and explicit allowlist change. Real Azure PostgreSQL Entra UAI identity/privilege staging, admin-password state migration, CAB and qualified signing remain blocked #128/#18/#38/#50.
