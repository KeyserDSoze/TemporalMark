# Imprint-search POST pre-auth body budget — Kestrel + pinned Nginx (#136 / ADR 0102)

**Pilot security resource boundary, not WAF/rate-limiter deployment proof, GDPR/DPIA approval, WORM, or legally qualified timestamping.** See [ADR 0102](../adr/0102-scoped-imprint-search-body-budget-kestrel-nginx.md), [scoped issue #136](https://github.com/KeyserDSoze/TemporalMark/issues/136), open parents [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) and [#113](https://github.com/KeyserDSoze/TemporalMark/issues/113), and the separate [distributed PostgreSQL search admission](IMPRINT_SEARCH_RATE_LIMITING.md).

## Intent and exact scope

The existing `POST /api/v1/stamps/search` receives one SHA-256 document digest represented as exactly 64 hex characters, two UTC time bounds and bounded pagination. It **does not receive documents**. Such JSON should fit well within **4,096 bytes (4 KiB)**. Although the request's real signed JWT and DB tenant-admin check precede confidential registry result access, the HTTP server and a reverse proxy may otherwise be forced to ingest an unnecessarily large JSON request. This source change adds a **size resource ceiling**, independent of the existing **12/actor and 30/tenant per fixed SQL minute** limits and their `429`/Retry-After semantics.

**Only one API route:** `POST /api/v1/stamps/search` (Kestrel matches the canonical or single-terminal-slash path case-insensitively and method exactly `POST`, per ADR 0146). No global ASP.NET body limit change, no limit on other API issuance/admin endpoints or future document upload workflows, no changes to PWA/health/OIDC services. `Content-Length` is an untrusted declaration; Kestrel also limits the **actual bytes read** when the client uses HTTP chunked/unknown-length transfer encoding. A 4,096-byte anonymous JSON request still reaches the existing JWT gate and returns **401**. An ordinary 4,097-byte declared request is rejected **before JSON/auth/SQL** with a generic **413** and `Cache-Control: no-store` on direct Kestrel; it cannot read or append tenant registry/audit/quota rows. A signed (real Keycloak JWT) oversized **chunked** JSON request is rejected during body-read with Kestrel HTTP **413**. The 413 body must not echo the digest, tenant ID, bearer, number of matches, response receipt or queried fingerprint.

## Two independent boundaries

1. **Direct .NET 10 Kestrel / Azure API Container App:** `src/backend/applications/TemporalMark.Api/Program.cs` installs a small early middleware **before `UseCors`, `UseAuthentication`, `UseAuthorization` or model binding**. On exact search POST, it requires an available mutable `IHttpMaxRequestBodySizeFeature`, sets `MaxRequestBodySize=4096`, and rejects `ContentLength > 4096` immediately. If the feature is absent or read-only, the request fails closed with no-store **503**, not the Kestrel default of 30 million bytes. A matching endpoint `RequestSizeLimitAttribute(4096)` backs up the limit during endpoint JSON body reads; it is **not** a substitute for the early pre-auth declared-size gate. The existing signed JWT, active DB tenant admin, payload validation, PostgreSQL rate, audit/write failure and eIDAS qualification barriers are untouched.
2. **Pinned Nginx frontend web image / on-prem reference:** `docker/nginx.conf.template` adds a single `location = /api/v1/stamps/search` with `client_max_body_size 4k`, the **same** `proxy_pass ${API_UPSTREAM}`, `Host` and `X-Forwarded-For` as the existing generic `location /api/`. The original **single server-level** `access_log /dev/stdout temporalmark_minimal` applies, emitting only numeric status, HTTP method, duration (ADR 0084). To prevent a *normal 413 Nginx error* from printing a hostile original URI/query into stderr, the **exact route only** has `error_log /dev/stderr crit`. This intentionally suppresses Nginx lower-severity diagnostics on that sensitive location; it does **not** apply globally. Other routes retain the preexisting log behavior.

The on-prem Compose uses this pinned web image in front of the same .NET API. Azure's Terraform reference uses the same frontend image design, but **the API Container App can also be accessed through a different Azure-managed ingress path**, hence the Kestrel check is independent. We have not applied Terraform or verified the effective Azure ingress, WAF, log routing or certificate/managed network behavior.

## Real CI security/regression evidence

Mandatory `.github/workflows/ci.yml` backend source tests `tests/integration/test_imprint_search_body_budget.py` assert both controls, their strict route/method scope, the single inherited minimal Nginx `access_log`, exact 4096-byte Kestrel feature plus endpoint metadata, no fallback and the full CI wiring. Mandatory Docker smoke starts actual pinned API + web containers and calls `TEMPORALMARK_CI_SEARCH_BODY_BUDGET=1 python3 tests/integration/imprint-search-body-budget.py` after health: **both port 8080 and port 3000** must respond **401** at an exact 4096-byte anonymous JSON body and **413** at 4097 bytes, while another POST remains unauthorized **401** (not globally size-limited), both `/healthz` remain **200**, and uppercase route remains limited by direct Kestrel. Actual container stdout+stderr and anonymous 413 responses are checked for synthetic query, fake bearer, referrer, user-agent, SHA-256-shaped imprint and JSON padding canaries, **without printing raw logs or tokens**. Real Nginx 413 must still produce only a minimal `tm_access status=413 method=POST duration=` event.

The existing final signed-tenant integration `tests/integration/api-tenant-isolation.py` adds a real **Keycloak-signed JWT** with deliberately oversized synthetically padded, syntactically valid JSON using **`Transfer-Encoding: chunked` and no `Content-Length`**, aimed directly at Kestrel. It must receive **413**, not 200/401/400 or a database match, so Content-Length-only enforcement cannot pass CI. Existing full two-tenant signed 401/403, valid 200 searches, malformed input 400, 429/no-store/Retry-After, runtime SQL role isolation, MFA browser TOTP/PKCE, 20 immutable migrations, full real PostgreSQL dump/restore, Playwright and mock Terraform tests are unchanged and remain required.

## Residual security gates: parents remain OPEN

- A body-size ceiling **does not** rate-limit requests per IP/connection, incomplete/slow requests, TCP or TLS handshake floods, chunked-discard network consumption, Nginx ingress buffering or CPU, distributed anonymous authentication abuse, tenant/principal quota windows, or malicious clients sending repeated small requests. V019 remains the bounded **post-auth** distributed SQL gate, not an edge WAF.
- Nginx's per-location 413 may generate different error paths for HTTP/2, incomplete chunked streams or custom operator configurations; error-log policy is scoped and loses useful route diagnostics. API direct/managed Azure edge logs, ACA/Log Analytics, external proxies/CDNs/WAF, operator overrides, IdP and third-party instrumentation require independent real deployments/telemetry review; Nginx error paths outside the tested one remain unverified.
- Data minimization, personal actor `sub` retention/erasure from V019/V020 and backups, approved DPIA/retention schedule, multi-region shared writable-primary governance, monitoring and incident/capacity policy remain #115/#113. Changes do not verify independent signed/WORM evidence custody, eIDAS qualified mark, QTSP status, CAB/AgID regulatory approval or real Azure Entra SQL readiness (#17/#13/#15/#128/#18).

Official docs: [ASP.NET Core 10 Kestrel size limits](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/kestrel?view=aspnetcore-10.0) and [Nginx `client_max_body_size`](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size).

## Scoped Nginx burst threshold is distinct from existing 4KiB body budget (#143)

The same shared web Nginx image separately caps **frequency** of anonymous requests for the exact search route (2r/s and 12-request burst **per connected TCP peer and per Nginx instance**) using `limit_req`, returning a fixed privacy-minimized 429/Retry-After 1 for overloaded peers, without weakening the independent **4KiB request-body limit and Nginx 413 error-channel confidentiality**. Application/Kestrel 4KiB still governs direct API. The PostgreSQL 12 actor/30 tenant admission after successful signed JWT is unchanged and its 429 passes through the Nginx location. See [ADR 0108](../adr/0108-nginx-preauth-imprint-search-peer-burst.md), [runbook](NGINX_EDGE_SEARCH_BURST.md) and [#143](https://github.com/KeyserDSoze/TemporalMark/issues/143). An Azure managed ingress or multiple Nginx replicas are not protected by one web container's IP bucket; parent #115/#113 remains OPEN for review of topology, fairness, privacy and independent edge deployment.

## Search POST case-equivalent proxy body/error-log scope (#144 / ADR 0109)

[ADR 0109](../adr/0109-nginx-case-insensitive-sensitive-search-route.md) and [#144](https://github.com/KeyserDSoze/TemporalMark/issues/144) align the Nginx search location with the ASP.NET Core case-insensitive endpoint. Previous lower-case-only Nginx exact match allowed `/api/v1/StAmPs/SeArCh` to reach the same Kestrel search API through generic `location /api/`, skipping Nginx's **own** 4096-byte body/error-log and pre-auth burst rules. Kestrel separately retained its case-insensitive 4096-byte cap, so there was no demonstrated ability to submit an oversized search body to the API. The proxy now uses `location ~* ^/api/v1/stamps/search$` (anchored, case-insensitive, normalized URI), preserving the existing `client_max_body_size 4k`, `error_log /dev/stderr crit`, local `limit_req` and anonymous 429, minimal access logging, and upstream 429 forwarding. The existing source-policy regression for #136 now rejects returning to lowercase-only exact selection; real Docker #143 checks both lowercase and mixed-case bursts. No change to direct Kestrel authorization, signed Keycloak tenant checks, V019 SQL quotas, Azure managed ingress or app/SQL credentials. Actual real cloud ingress/logging policy and other path-normalization aliases remain independently blocked under #115/#113/#18.

## Nginx pre-location 414 response-cache boundary (#145)

A malformed synthetic `GET /api/v1/stamps/search?...(>16KiB)` reaches Nginx's HTTP request-line parser **before** the search-specific `client_max_body_size 4k` and `error_log crit` location. The pinned real Nginx returned 414 but lacked `Cache-Control: no-store` in tests-only [RED CI 44925916344](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44925916344). Following refined [ADR 0110](../adr/0110-nginx-early-414-cache-and-http-error-privacy.md) / [#145](https://github.com/KeyserDSoze/TemporalMark/issues/145), the shared web image maps only **414** to `no-store` via HTTP-scope `map $status` and server-scope conditional `add_header`, leaving 200 SPA/PWA caching, 413 search body limits, 429 anonymous bursts and direct Kestrel independently unchanged. The actual early access log used **method=-** because parsing had not completed; three-field privacy formatting remains. No real log canary leak was observed, so **no broad HTTP-level error suppression** was introduced. Full details in [NGINX_EARLY_414_PRIVACY](NGINX_EARLY_414_PRIVACY.md). Azure external ingress, actual browser caches, CDN/WAF error handling and QTSP/eIDAS still require separate review.
