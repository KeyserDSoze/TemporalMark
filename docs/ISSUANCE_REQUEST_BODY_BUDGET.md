# Unqualified pilot delegated issuance: 4 KiB inbound JSON request budget

**Scope:** current **unqualified** `POST /api/v1/stamps/issue` endpoint, which accepts only JSON `digestBase64` containing a **canonical 44-character standard padded Base64 representation of the original document's SHA-256 digest**, not the document itself. [ADR 0145](../adr/0145-exact-issuance-post-preauth-body-budget.md), child [#187](https://github.com/KeyserDSoze/TemporalMark/issues/187), security parent [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) and delegated-provider [#15](https://github.com/KeyserDSoze/TemporalMark/issues/15).

## Actual API admission boundary

The API's early middleware matches only the **case-insensitive canonical or single-terminal-slash** `POST /api/v1/stamps/issue` (ADR 0146); unrelated GET/POST, all static PWA content and public `/healthz` are unchanged. A JSON request with **exactly 4,096 original HTTP body bytes** is allowed to proceed to JWT and tenant-admin membership checks, canonical digest decoding, and the configured external TSA path. One extra byte is rejected with generic **HTTP 413** before authentication or JSON model binding when `Content-Length` declares oversize. When length is unknown (e.g. `Transfer-Encoding: chunked`), Kestrel's actual `IHttpMaxRequestBodySizeFeature` **read limit** enforces 4,096 bytes during model binding; `RequestSizeLimitAttribute` on the endpoint supplies a second metadata guard. If Kestrel's body-size feature is unavailable or read-only, the API denies with generic 503 rather than silently falling back to its normal much larger body allowance. No SHA256 digest/tenant, Authorization header, request URI or padded JSON is included in the rejection body or request telemetry. Every versioned API response inherits `Cache-Control: no-store` under [ADR 0144](../adr/0144-api-v1-uniform-no-store-http-cache-policy.md).

A **normal signed/authorized digest** within the limit continues to return **503** when no external TSA is configured; that is an upstream dependency refusal, **not** body-size rejection. A small request without a signed JWT still returns **401**. The older `POST /api/v1/stamps/search` has its independent unchanged 4 KiB pre-auth budget, DB-backed quota and privacy-minimized audit. No new SQL migration or issuance revalidation is introduced.

## Out of scope and release stop lines

This cap is **enforced at Kestrel** and measured in original **request body bytes**, not a policy forcing every edge proxy to reject a body before buffering it. The current on-prem Nginx general `/api/` proxy may buffer input under its own configured/default size limit before Kestrel responds. Azure managed Container Apps ingress, WAF/CDN and upstream proxies may have different body/log rules; production **independent edge pre-auth throttling, request-size buffering and actual log/retention/DPIA review** remain #115/#113/#18. A 4 KiB cap does **not** prevent all small-request flooding, external TSA double-billing or ambiguous network retransmission; durable per-request replay/idempotency remains #15. No signed historical QTSP/CMS/CRL/EUTL status, independently signed WORM custody, CAB/AgID/eIDAS qualification or GDPR legal preservation is supplied. Every pilot timestamp remains **`Unverified`**; #15/#17/#13 stay OPEN.
