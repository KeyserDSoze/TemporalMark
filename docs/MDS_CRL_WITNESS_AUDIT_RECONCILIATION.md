# CI-only PostgreSQL witness append-history reconciliation (#73)

**TEST-ONLY / UNAPPROVED / NOT IMMUTABLE OR TRUSTED / NO PRODUCTION SERVICE.** [ADR 0042](../adr/0042-ci-witness-bounded-audit-history-reconciliation.md) scopes [#73](https://github.com/KeyserDSoze/TemporalMark/issues/73) as a narrow child of still-open [#64](https://github.com/KeyserDSoze/TemporalMark/issues/64)/[#61](https://github.com/KeyserDSoze/TemporalMark/issues/61). Existing V001–V017, V015/V016 registrar freeze, API, Azure Terraform and normal on-prem Compose are unchanged.

## Threat and narrow behavior

Prior to #73, the separate CI PostgreSQL witness had an append event history but its .NET read-only preflight checked **only** the latest checkpoint. A witness database superuser could update the latest synthetic checkpoint from serial 4 to 3 while leaving a committed event at 4. A **fully logically restored primary DB** at 3, an older correctly signed original manifest/seal and a downgraded latest witness row then passed the *two-source* preflight as UNAPPROVED, despite an internal audit event disproving latest serial 3.

The updated disposable witness bootstrap creates a second strictly read-only **STABLE SECURITY DEFINER** function, \`public.check_unapproved_witness_history(text,bigint,text)\`, owned by the NOLOGIN/NOSUPERUSER \`temporalmark_witness_data_owner\`. The function has \`search_path=pg_catalog,pg_temp\`, no dynamic SQL and no mutation. Reader has only \`SELECT\` on latest-checkpoint table plus **EXECUTE of this bounded checker**, never raw audit-event SELECT or the writer's EXECUTE; writer can execute its original monotonic append function only, not the audit checker. Default PUBLIC EXECUTE is revoked atomically during the function's creation transaction. Ordinary app/main DB roles do not exist in the second CI PostgreSQL cluster.

In the **same READ ONLY REPEATABLE READ PostgreSQL snapshot**, \`ReviewerMdsIsolatedPostgresWitnessReader\` checks the audit function's owner, SECURITY DEFINER/STABLE flags, restricted EXECUTE ACL and fixed search path. It then matches latest row to all source-scoped events in \`event_id\` order, checking nonempty bounded (max 128), strictly increasing accepted serial, uppercase SHA256, non-decreasing finite observed time, and exact latest version/seal digest. Missing/corrupt history, event deleted or tampered, a single-row rollback inconsistent with retained history, invalid privileges/function config, excessively long history, or PostgreSQL failure denies. Original RSA-PSS signer preflights and V017 primary snapshot comparison remain unchanged. All successful outputs remain **UNAPPROVED**.

## Important unresolved boundaries

This is **internal consistency**, not independent/latest provenance, WORM, legally qualified evidence or an append-only integrity guarantee. The witness PostgreSQL superuser/Docker host still owns the tables, can rewrite **both** checkpoint and events, alter/reinstall the checker, reset the cluster and replace test signing roots and the signed local file. Signed data with caller-chosen test public keys does not establish authentic FIDO MDS R46, all-hop CRL/OCSP, CAB/HSM-approved signer, UTC(k), secure rotations or human WebAuthn credential enrollment. The function bound of 128 is test-only and can deny service after enough valid events; do not deploy this as a production retention policy. No independent physical PITR, region/split-brain evidence or production on-prem OSS/Azure parity is supplied. Keep #64/#61/#57/#55/#53/#44/#50/#46/#38 open and V015/V016 SQL issuance suspended.
