# ADR 0119 — Deny unforeseen SECURITY DEFINER routines available to the Entra API runtime SQL identity

Status: **Accepted for scoped test-first PostgreSQL prelisten security [#154](https://github.com/KeyserDSoze/TemporalMark/issues/154)**, 2026-11-22 (Europe/Rome). Parent #128/#18 real Entra PostgreSQL and Azure production, #14 tenancy, #38/#50 independently approved signer/registrar, #64/#61 independent evidence witness, #17 WORM, #13/#15 eIDAS/QTSP **remain OPEN**. No Azure apply, SQL GRANT, independent human consent, qualified issuer or legal custody is delivered.

## Previous architecture, sources and attack boundary

Reviewed ADR 0099 (an **already-open** SQL session, one read-only catalog prelisten), ADR 0100 (the gate is mandatory only for explicit Production `ContainerAppsEntraCandidate`, never the OSS Password-mode default), ADR 0112/0113 (named privileged FUNCTION EXECUTE ACL denies), ADR 0118 (future-fail-closed public table/sequence relation inventory), `PostgresRuntimePrivilegePreflight.cs`, its real PostgreSQL 17 disposable-LOGIN tests, `docs/POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md`, `docs/API_POSTGRES_ENTRA_PRELISTEN_CANDIDATE.md`, `docs/DATABASE_MIGRATIONS.md`, `docs/OPERATOR_PROVISIONING.md`, `docs/THREAT_MODEL.md` and `docs/ROADMAP.md`. Rechecked **immutable** V005 privilege definer tenant-admin invariants, V008 approved enrollment **10-argument overload**, V010 replay trigger and V019 approved shared tenant/principal quota admission function.

The existing prelisten denies EXECUTE on individually named reviewer/registrar/provisioner functions, but **does not cover every `SECURITY DEFINER` routine**. For example V008 creates `public.approve_enrollment(uuid,text,text,text,text,text,char(64),text,text,bigint)` under separate approver permissions, and the prelisten's named list checks a different historical 7-argument overload, not the current 10-argument one. A mistaken direct GRANT to the SQL API login could thus pass. A newly created future SECURITY DEFINER function or procedure may automatically receive EXECUTE for PUBLIC, independently of other SQL role/group or public-table ACL restrictions. An SQL definer executes with the **function owner's privileges**, so grant approval must not be inferred from an otherwise benign runtime role. This is a **hypothetical accidental grant / future code path**, not evidence the current deployed Azure account has such an allowance.

Official [PostgreSQL 17 pg_proc](https://www.postgresql.org/docs/17/catalog-pg-proc.html) describes `prosecdef` and `prokind` (function `f` / procedure `p`); [PostgreSQL 17 system information functions](https://www.postgresql.org/docs/17/functions-info.html) describes `has_function_privilege(oid, 'EXECUTE')` effective checks including role/PUBLIC grants; [PostgreSQL 17 privileges](https://www.postgresql.org/docs/17/ddl-priv.html) and [ALTER DEFAULT PRIVILEGES](https://www.postgresql.org/docs/17/sql-alterdefaultprivileges.html) explain **default PUBLIC EXECUTE** for newly created functions/procedures unless revoked in the migration transaction. The approved V019 `public.consume_imprint_search_rate(uuid,text)` is also SECURITY DEFINER and remains the **one exact allowlisted routine OID**; it is required by the API to rate-limit searches.

## Decision and test-first acceptance

1. ADR **first on `main`**, before new tests or source patch. Commit a tests-only **8-case real PG17 RED** in the existing xUnit suite:
   - Three direct EXECUTE test grants on existing **SECURITY DEFINER** V008 `public.approve_enrollment(uuid,text,text,text,text,text,char(64),text,text,bigint)`, V005 `public.assert_tenant_has_active_admin(uuid)` and V010 `public.record_enrollment_decision_proof()`.
   - Two new SQL SECURITY DEFINER function cases in `public`: default PUBLIC EXECUTE and explicit PUBLIC revoke + direct per-test LOGIN GRANT.
   - Two new SQL SECURITY DEFINER procedure cases in `public`: default PUBLIC EXECUTE and explicit PUBLIC revoke + direct per-test LOGIN GRANT.
   - One new SECURITY DEFINER function under a freshly created other non-system schema, with isolated per-test schema USAGE and direct EXECUTE; this ensures user-schema coverage instead of only checking `public`.
   - One **positive** synthetic `SECURITY INVOKER` function with default PUBLIC EXECUTE, verifying the new policy rejects *privilege elevation*, not every ordinary routine.
   Each case creates a unique disposable `LOGIN INHERIT` in `temporalmark_runtime_group` only, `Pooling=false`; verifies a clean baseline before extra privilege/function creation; catalog-only verifies effective EXECUTE; then demands generic no-inner/no-password/login/function exception for definer paths, or continued success for the invoker control. **Never call any existing/proposed function/procedure or write tenant/proof rows.** Always undo each temporary SQL grant, function, schema, runtime membership and SQL LOGIN in `finally`, even on intentional RED. Real Docker PG17 RED must show exactly **8 expected missing-denial assertions, 239 passes, 247 total** (238 previously passing plus invoker positive), not compilation, bad test DDL or connection errors.
2. Only **after** real RED add one catalog `AND NOT EXISTS` on `pg_catalog.pg_proc` joined to `pg_catalog.pg_namespace`, for `prosecdef` and `prokind IN ('f','p')`, excluding system namespaces `pg_catalog`, `information_schema` and names starting `pg_`. Deny effective runtime `pg_catalog.has_function_privilege(proc.oid, 'EXECUTE')` on **all** non-system SECURITY DEFINER function/procedure OIDs **except the exact approved `'public.consume_imprint_search_rate(uuid,text)'::pg_catalog.regprocedure`**. Preserve **all** existing fixed named function denies, SQL role, table, sequence, and source allowlist predicates, and normal V019 rate function privilege. One static read-only SQL query on the **already authenticated runtime connection**; no login changes, new Npgsql session, DDL, GRANT, migrations or Terraform modifications.
3. Update this ADR and PostgreSQL/Entra operator runbooks, migration docs, threat model and roadmap with real RED/GREEN. Only close scoped **#154** after independently verified **exact final documentation-inclusive `main` commit** GitHub Actions backend/frontend/terraform/docker-smoke **4/4 SUCCESS**, `ci-verdict` SUCCESS, combined `temporalmark/ci-4-core-jobs=success`, real PostgreSQL17 **247/247**, all original 20 migrations and repeat checksum, real TEST-only `pg_dump/pg_restore` witness rollback checks, Keycloak registrar/reviewer browser TOTP+PKCE and signed tenant A/B HTTP 401/403, Nginx 413/414/429 privacy.

## Stop line

This SQL read-only prelisten is one-time only for explicitly opted-in **Production Entra candidate API**. It cannot prevent after-start GRANT/owner-ALTER/DDL drift, functions outside approved namespace scope (system namespaces excluded), elevation through SQL language extensions, actual Entra SQL role/credential provisioning or production CAB. PostgreSQL SECURITY DEFINER trigger routines may be uncallable directly but a direct EXECUTE grant still violates conservative privilege separation; tests do not exercise their behavior. Do not claim that pass/fail is signed WebAuthn human authorization, an independently signed monotonic witness, FIDO trust, timestamp QTSP/eIDAS qualification, WORM or Azure deploy readiness. All parent blockers remain OPEN.
