# ADR 0120 — Reject ZIP prefix/trailer overlays in offline v1 period export inspection

Status: **Accepted for scoped offline evidence-parser TDD [#155](https://github.com/KeyserDSoze/TemporalMark/issues/155)**, 2026-11-22 Europe/Rome. Parent #17 WORM/complete export, #15 delegated QTSP/CMS, #13 eIDAS/CAB, #61/#64 signed independent monotonic custody, and #18 Azure production remain OPEN. No qualification, actual TSA validation, signed evidence or legal custody is granted.

## Reviewed baseline and ambiguity

Reviewed prior ADR [0076](0076-offline-zip-structure-sha256-self-consistency.md) (stdlib-only bounded v1 metadata/TSR consistency), [0077](0077-zip-compression-unix-special-file-gates.md) (STORE/DEFLATE ordinary-file metadata), [0078](0078-zip-local-central-header-method-flag-binding.md) (local-vs-central flags/method), the actual `tests/integration/verify_period_export.py`, `test_verify_period_export.py`, current `TimestampRegistryService.ExportZipAsync` .NET in-memory ZIP, `docs/OFFLINE_PERIOD_EXPORT_VERIFIER.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md`, CI. Python's [zipfile](https://docs.python.org/3/library/zipfile.html) deliberately supports ZIP files embedded after a prefix (self-extracting stubs) and may tolerate a short trailer. The [PKWARE ZIP APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) defines a local file header `PK\x03\x04`, central directory and 22-byte **End of Central Directory (EOCD)** record `PK\x05\x06` plus optional comment. The ordinary v1 .NET exporter writes only an archive, starting with its first member's local header, a single central directory and final zero-comment EOCD. A v1 ZIP with entirely unchanged manifest, token bytes, SHA-256, CRC, member list and local/central metadata can still have **unreferenced prefix or appended opaque content** accepted by Python's ZIP reader. Such an ambiguous/polyglot envelope should not be reported as the exact v1 structure.

This is a container-profile issue only, not proof malicious bytes are executed, not a forged signature and not evidence that a qualified electronic timestamp was issued. A jointly edited unsigned JSON manifest and DER can still pass the existing hash-only checker.

## Decision — test first, exact standard v1 envelope

1. Commit this ADR **first on `main`**. Then commit Python stdlib unit tests **without changing verifier implementation**: create a valid ZIP with known unchanged v1 `manifest.json` and TSR; show Python `ZipFile` can open/decompress it when (a) bytes are prepended, (b) an opaque trailer is appended, (c) NUL padding is appended, or (d) both prefix/trailer exist. Each must instead fail with generic `ExportVerificationError`; check CLI returns generic nonzero without leaking tenant ID, imprint, archive path or extra bytes. Preserve positives for exact v1 regular ZIP with one and zero receipts, STORE and DEFLATE. Confirm genuine GitHub Actions RED on actual tests — **missing-denial failures**, not bad binary fixtures/import/syntax defects.
2. Only after genuine RED implement an O(1) **fixed-size** ZIP v1 envelope check, *before* parsing/decompressing manifest or DER: require the archive's first 4 bytes to be the local file-header signature `PK\x03\x04`; require the last **exact 22 bytes** to unpack as the classic ZIP EOCD `<4s4H2LH` signature `PK\x05\x06` with zero disk IDs, zero comment length, equal per-disk/total entries equal to `len(ZipFile.infolist())`, valid positive central-directory size and offset and `central_offset + central_size == archive_size - 22`. This excludes unreferenced prefix, trailer, central-directory gap, self-extracting stub, ZIP64 record and multi-disk layouts outside the current small **≤10,001 entries and ≤80 MiB** v1 export. Do not read large portions of input; use the already-opened file-like object, seek and read only 4+22 bytes, no network/third-party dependencies or archive extraction. Bad/short/ambiguous inputs remain generic CLI failures.
3. Retain all ADR 0076/0077/0078 gates (duplicate JSON/member/path, ZIP compression and Unix file types, local/central method and flags, 100ns UTC, canonical SHA256/digest, `Unverified` only, ≤1MiB/TSR, ≤64MiB total DER) and ordinary one/zero-record .NET v1 ZIP compatibility. Update ADR, offline operator guide, threat model and roadmap. Close **only #155** once exact **docs-inclusive `main` SHA** GitHub CI backend/frontend/terraform/docker-smoke 4/4, ci-verdict and aggregate status GREEN, Python source tests and actual .NET/PG/Keycloak/restore/ingress regressions confirmed.

## Limit and operator responsibility

No signer or TSA is authenticated, no DER/CMS signature or historical EUTL status is verified, no manifest is externally signed, no proof of period completeness is established, and no retention hold, WORM write-once storage or independent monotonic witness has been created. The stricter v1 parser intentionally refuses otherwise ZIP-readable non-v1 self-extracting, multi-disk, ZIP64 and commented archives; interoperable formats require independent ADR/fixture review, not automatic acceptance. Parent #17/#15/#13, #61/#64 and #18 remain OPEN.


## Test-first RED and minimal correction — 2026-11-22

- ADR accepted first [`eb9894d`](https://github.com/KeyserDSoze/TemporalMark/commit/eb9894d4e2d1dc5ab3836c5b29ab73a6bd7c62ac), then only tests [`5039e79`](https://github.com/KeyserDSoze/TemporalMark/commit/5039e79ad58b8e186517a83701af51606fd60b48); no source change before real RED.
- [real Python RED 44966967378](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44966967378) backend stdlib unittest ran **29 tests: 5 genuine missing-denial failures and 24 passes**, with no fixture/syntax errors. Four independently stock-`zipfile`-readable v1 ZIPs with prefixed opaque bytes, appended opaque trailer, 1024 NUL padding, and both prefix+trailer were incorrectly accepted (`ExportVerificationError not raised`); the CLI likewise incorrectly returned success on an appended opaque payload (`1 != 0`). Positive one/zero-record exact v1 ZIP passed. Manifest JSON, TSR, hashes and entry layout remained unchanged; no sensitive member was exposed.
- Only after RED, minimal stdlib helper `require_exact_v1_zip_envelope` reads **4 bytes at offset zero and 22 bytes at physical EOF** *before any manifest/TSR decompression*. Requires the first local ZIP header, final zero-comment single-disk conventional EOCD, member-count agreement and a gap-free central-directory offset+size ending precisely before EOCD. Rejects the explicit non-v1 ZIP64, self-extracting, commented, multi-disk and overlay layouts. Keeps previous bounded extraction-free ZIP/DER/UTC/hash checks. Exact final docs-inclusive GitHub CI GREEN and issue closure remain separately verifiable.
