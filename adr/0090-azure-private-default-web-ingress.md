# ADR 0090 — Private-by-default Azure web ingress with explicit, reviewable exposure

Status: **Accepted for scoped prequalification #123**, 2026-11-20. Parents [#18](https://github.com/KeyserDSoze/TemporalMark/issues/18) and [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) remain OPEN.

## Baseline and source review

Reviewed [ADR 0001](0001-architecture-and-deployments.md), [ADR 0084](0084-minimized-nginx-imprint-search-access-log.md), [ADR 0086](0086-api-request-diagnostic-log-minimization.md), [ADR 0087](0087-azure-image-oci-sha256-digest-admission.md), [ADR 0089](0089-azure-oidc-issuer-input-validation.md), Azure `main.tf`/`variables.tf`/`outputs.tf`/`terraform.tfvars.example`, the existing Terraform plan-only mocked-provider regression suite and four-core GitHub Actions CI, `infra/azure/README.md`, docs/THREAT_MODEL.md and ROADMAP.md, and issues #18/#115. Main currently sets `azurerm_container_app.web.ingress.external_enabled = true` unconditionally. API ingress is internal (`false`), and both already set `allow_insecure_connections=false`. A direct Azure reference apply currently makes the publicly addressed web frontend available even though no WAF, approved operating identity, managed public ingress log privacy, risk/DPIA assessment or CAB production change control is in place.

Microsoft documents [Container Apps ingress](https://learn.microsoft.com/en-us/azure/container-apps/ingress) as **two boundaries**: environment accessibility, then per-app internal/external ingress. [Terraform azurerm_container_app](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/resources/container_app) explicitly defines `external_enabled` and `allow_insecure_connections`. Private app ingress means access is limited **to other apps in the same Container Apps environment**, not necessarily to an operator's whole VNet. An external environment may still have a public endpoint even when a specific app is internal; an environment-level external route might expose an internal app in a separately configured routing system. A Terraform plan-only mock **does not prove actual Azure network exposure, WAF, private endpoint, application auth or logging controls**.

## Decision

1. Add `enable_public_web_ingress` (**bool**, default **false**) to the Azure Terraform reference. Set only **web** ingress `external_enabled = var.enable_public_web_ingress`; keep API ingress **always false** and `allow_insecure_connections=false` for both, preserving original target ports and normal internal web→API routing. No Azure-only dependency is introduced to the .NET/React application; on-premises OSS Compose remains unchanged.
2. `frontend_url` output is **null by default** (not a misleading externally accessible URL) and shows `https://<web.ingress.fqdn>` only when web public ingress is explicitly selected. Include `enable_public_web_ingress=false` visibly in the checked-in fictional `.tfvars.example` with a comment stating that the production setting `true` requires external WAF/CAB/log/privacy approval that Terraform cannot verify. An operator with Terraform access can flip the boolean: this is a fail-safe deployment *default and explicit change-diff*, **not a cryptographic, human or CAB authorization gate**.
3. **TDD RED first**: commit a `tests/ingress_boundary.tftest.hcl` using `mock_provider "azurerm"` and `run ... command=plan` with fake values. Assertions on the actual planned API/web ingress blocks verify default web and API **internal**, both **reject insecure HTTP**, correct target ports, and explicit public web override while API stays internal. Check the conditional `frontend_url` output is null in private mode. Wire to core Terraform job after the existing OCI 11 and OIDC 17 tests. Witness expected RED against the present hardcoded public web ingress, before source edits; GREEN on actual Terraform plan-only mock providers with no Azure credentials, secret-bearing state or deploy/apply.
4. Update Azure operator documentation and threat/roadmap with the **release stop-line**: a public web endpoint still lacks real Front Door Premium/WAF/IP policy, private endpoint design, ingress diagnostic data minimization, threat assessment/DPIA, approved registry artifacts, Key Vault/Managed Identity, tenant IAM approval and CAB; a boolean set true alone cannot satisfy these prerequisites. Public HTTPS itself is not a privacy guarantee. Do not claim compliance, qualified timestamping, production readiness, WORM or certified identity.

## Concurrency, compatibility and open work

No changes to the database/20 versioned migrations, rate limiter, tenant policies, #114 append-only audit, #117/#119 container logs, Keycloak/JWT/MFA/WebAuthn V015/V016 issuer or reviewer controls. OSS on-prem deployments remain functionally identical and may use their own approved ingress; Azure behavior changes only in default network reachability, which requires explicit release configuration to publish. The reference does not create Front Door/WAF/private endpoint or prove that internal-only ingress cannot be exposed through unreviewed environment routes. Parent #18/#115/#113 remain OPEN for actual Azure deployment and WAF/log/privacy, #17 for independent signed/WORM custody, #13/#15 for legal qualification.
