# ADR 0102 — 4 KiB search-POST request-body budget at API Kestrel and shared Nginx web proxy

Status: **Accepted solely for scoped security hardening [#136](https://github.com/KeyserDSoze/TemporalMark/issues/136)**, 2026-11-21. Open parents [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) and [#113](https://github.com/KeyserDSoze/TemporalMark/issues/113) remain OPEN for full edge/pre-auth abuse, private ingress, DPIA and retention governance. All eIDAS/WORM/QTSP claims remain blocked.

## Existing architecture and authoritative review

Reviewed ADR 0001, 0082–0085, 0101; docs/COMPLIANCE, IMPRINT_SEARCH_RATE_LIMITING, NGINX_ACCESS_LOG_PRIVACY, THREAT_MODEL, ROADMAP, DATABASE_MIGRATIONS; current `Program.cs` signed JWT and active-tenant-admin `POST /api/v1/stamps/search` handler with 12 per actor/30 per tenant PostgreSQL atomic admission in immutable V019, privacy-minimized #114 search audit in V018, immutable owner-only V020; Npgsql SQL role separation, actual Compose API Kestrel and pinned frontend Nginx reverse proxy `docker/nginx.conf.template`, shared on-prem/Azure frontend image and separate direct Azure Container App API ingress, CI Python source/actual proxy log tests and live signed Keycloak tenant A/B HTTP pipeline. Normal Nginx access logs are constrained to `tm_access status/method/duration`, but Nginx **error** logs may expose original URI/query in exceptional 413 paths. The existing search API validates a tiny JSON object with one document SHA-256 digest, two ISO timestamps and bounded page fields, yet uses the default ASP.NET Core/Nginx body limits rather than a route-specific budget. A hostile caller can submit large invalid JSON before signed authorization or model validation. Redis or an Azure WAF cannot be made mandatory for OSS portability.

Authoritative: [Microsoft ASP.NET Core 10 Kestrel request-body limits](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/kestrel?view=aspnetcore-10.0) and [per-request `IHttpMaxRequestBodySizeFeature`](https://learn.microsoft.com/en-us/aspnet/core/mvc/models/file-uploads?view=aspnetcore-10.0) distinguish early Content-Length from **actual** read-size enforcement (including unknown-length chunked HTTP); [Nginx `client_max_body_size`](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size) allows an exact location's 4k cap and returns 413. Nginx [error_log scope](https://nginx.org/en/docs/ngx_core_module.html#error_log) can override the default request-line-bearing error event on the sensitive route, at the deliberate cost of route-specific diagnostics. A recently reported [chunked-body discard path issue](https://github.com/nginx/nginx/issues/1522) means the Nginx cap alone must NOT be treated as complete payload/DoS protection; ASP.NET Kestrel's read limit must be enforced independently.

## Decision

1. **Only exact search POST** (`/api/v1/stamps/search`, case-insensitive matching on direct Kestrel) is in scope. Adopt an explicit fixed **4,096-byte** budget for UTF-8 JSON body, ample for this 64-char SHA-256 search + two UTC times/offset/limit, but not an arbitrary document upload. Do not cap GET `/stamps/export` or POST `/stamps/issue`, websocket/Keycloak/SPA or other APIs. Do not silently limit an entire tenant, change the number of search results, rate quota or add a global arbitrary upload cap. Content-Encoding request decompression is not currently enabled and enabling it needs an independent security review.
2. At API pipeline **before authentication and HTTP JSON model binding**, for matching POST, ask Kestrel's `IHttpMaxRequestBodySizeFeature` to set `MaxRequestBodySize=4096` before any body read. If missing or `IsReadOnly`, **fail closed** without parsing; no fallback to default 30 MiB. If declared `Content-Length > 4096`, return **generic HTTP 413** immediately, with `Cache-Control: no-store`, no body/URI/tenant/error detail, and without accessing PostgreSQL or its per-tenant counters/audit. **Never rely exclusively on Content-Length**: enforce server read limit for chunked/unknown size when the body is actually consumed by a valid authorized request; Kestrel itself emits 413 on overrun. A small unauthenticated request continues to return signed-JWT `401`. Direct Kestrel is the independent API boundary even if Azure managed ingress or OSS Nginx is absent.
3. For the shared pinned frontend Nginx image used by on-prem Compose and Azure frontend Container App, add an **exact-match location** `location = /api/v1/stamps/search` with `client_max_body_size 4k;` and the same existing `proxy_pass ${API_UPSTREAM}`, `Host` and `X-Forwarded-For`. Preserve the **one inherited server-level** minimal `access_log` (no alternate access stream), other `location /api/`, `/healthz`, static PWA routes and unchanged auth/tenant semantics. Nginx may return **generic 413** before proxying a known Content-Length. In the *exact sensitive location only*, set `error_log /dev/stderr crit;` so an ordinary HTTP 413 error event does not print original query/request line in Nginx stderr; this deliberately suppresses lower-severity logs for **this one exact route**, not other routes or global container. Verify actual real Nginx with synthetic secret/URI/body canaries before claiming limited error confidentiality.
4. Testing must be genuine and **RED-first** before implementation: commit backend mandatory source policy and independent real Docker Kestrel + Nginx boundary probes with 4096-byte anonymous POST -> **401**, 4097-byte -> **413** at both ports, generic no-store API 413, normal SPA/health unaffected, Kestrel case-insensitive API path equivalence, exact Nginx minimal 413 access event plus no printed fake query/header/body canary in web/api container logs. Source-only tests check pre-auth feature, zero use of sensitive `$request`/headers, exact 4k Nginx route and CI wiring. Add valid real signed Keycloak POST with **chunked oversized JSON** to direct Kestrel and require 413 even when client omits Content-Length; verify no matching results and no bypass. This must use the existing **disposable** Keycloak/PG CI tenant fixture, never a live token. Confirm GitHub Actions actual RED before adding source; then minimum implementation. Preserve previous 400/401/403/429/Retry-After and privacy canary tests, full four-job CI.
5. Scope is HTTP resource budget, **not** quota enforcement, IP reputation, global connection/worker/read-time cap, proxy slowloris/chunked network DoS prevention, request-body decompression, Azure managed ingress diagnostics, third-party WAF, GDPR retention approval, independent WORM, EU eIDAS qualification, live Azure deployment or CAB certification. Nginx chunked discard edge cases and buffering may still consume network/CPU; a real Azure and on-prem external-edge inspection remains necessary. Update operator runbook, ROADMAP/THREAT_MODEL and parent issue with residual risks, no unqualified compliance claims.
