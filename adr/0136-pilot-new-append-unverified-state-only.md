# ADR 0136 — Deny unsupported validation/incident states on NEW pilot registry append

**Status:** ACCEPTED for focused direct-`main` TDD [#178](https://github.com/KeyserDSoze/TemporalMark/issues/178), 2026-11-23 Europe/Rome. Child of open #15 (independent qualified QTSP validation) and #17 (evidence custody). No new legal qualification or incident decision is conferred by this ADR.

## Evidence reviewed and scope

Reviewed ADR [0002](0002-qualified-vs-delegated-timestamping.md), [0004](0004-evidence-time-and-retention.md), [0121](0121-pilot-registry-unsupported-validation-state-read-gate.md), [0134](0134-registry-metadata-text-prewire-budgets.md), [0135](0135-issuance-registry-write-budget-parity.md); `TimestampRecord.Validate` and its five state enum values; `TimestampIssueService`, `ProviderTimestamp`, `TimestampRegistryWriteBudget`, `PostgresTimestampWriter.AppendAsync`, `TimestampRegistryService.RequirePilotUnverifiedState`, V001 `timestamp_registry.validation_state` check, `PostgresTimestampWriterAdmissibilityTests` (real PostgreSQL 17), `TimestampIssueServiceTests` and registry/compliance/threat/roadmap operator documentation.

Baseline docs-inclusive `main 8aec36b5ad6479a05188a3c33d2569935845824d` passed [CI 45168121374](https://github.com/KeyserDSoze/TemporalMark/actions/runs/45168121374) including four core jobs, independent verdict and combined status. Only the issuance service constructs `Unverified`. Domain and V001 intentionally permit `VerifiedNonQualified`, `VerifiedQualifiedExternal`, `VerifiedQualifiedOwn` and `AffectedByIncident` for future verified/import/incident processing. ADR 0121 makes pilot Page, Search, Receipt and ZIP reject all four unsupported states. ADR 0135's direct writer admission checks original DER size and text bytes, not status: an internal/direct `ITimestampWriter` caller could append a fresh self-consistent record labelled qualified or incident, rendering it unreadable via current pilot routes. This is a hypothetical write-path inconsistency, NOT a demonstrated false qualification, real incident or malicious SQL operation.

## Decision and TDD order

1. **ADR first, then RED-only tests, only then production.** Add an actual disposable PostgreSQL 17 writer theory that calls `PostgresTimestampWriter.AppendAsync` once per **all four** non-`Unverified` enum values. Each fixture uses an existing authorized tenant, original small DER with matching SHA256, canonical SHA256 imprint, nonempty source policy/provider and UTC time; `record.Validate()` must succeed *before* the writer call. Demand fixed generic `InvalidOperationException` **before opening a SQL connection or executing INSERT**, no state label/tenant/document/DER reflected in error, and zero matching persisted rows. Require an observed real missing-denial RED (not build/fixture failure). Keep the existing direct-writer positives for `Unverified`, exact-budget DER/text and foreign-tenant readback. Add or retain a Business test proving that even a provider identifier suggesting qualified service status has no authority to set a qualified enum: issuance always stores `Unverified`. The provider interface must not accept a status from the caller.
2. Once the real RED is observed, extend the shared `TimestampRegistryWriteBudget.IsNewRegistryRecordAdmissible` with **exact** `record.ValidationState == TimestampValidationState.Unverified`. The current `PostgresTimestampWriter.AppendAsync` budget check remains **before** `record.Validate()`, SQL connection and INSERT. Preserve its **existing sanitized generic error** (`Stored receipt exceeds pilot registry write limits.`) to prevent states or tokens leaking into diagnostics; no second error shape or SQL-side-only denial. Existing issuance already constructs `Unverified`, so do not introduce a qualified flag or public API selector. The current per-row raw DER and UTF8 text budgets remain unchanged.
3. Do **NOT** narrow the Domain enum or `TimestampRecord.Validate`, and do **NOT** alter immutable V001–V020 SQL constraints. Historic rows including four potential future statuses are not rewritten, deleted, downgraded or silently exported. Retain independent read-side `RequirePilotUnverifiedState` and pre-wire size gates. A real verification state transition, incident annotation, corrective append or historical qualification claim requires a **separate approved workflow/ADR**, historical EU Trusted List and trustworthy signing/service validation, authorization, immutable history and audit; this narrow direct-append gate must be revisited only with explicit TDD and governance.
4. Document exact RED then GREEN evidence, operator scope and follow-up risks in this ADR, the registry read-gate operator guide, compliance, threat model and roadmap. Close only #178 after verifying the **exact final docs-inclusive `main` SHA**: GitHub Actions backend/frontend/terraform/docker-smoke four success, ci-verdict and combined success, Business and real PostgreSQL 17 xUnit including new cases, V001–V020/checksums and full logical restore, offline v1 ZIP, actual signed Keycloak A/B, Nginx access/privacy. Do not close parents #15/#17/#13/#18/#61/#64 or WebAuthn trust blockers.

## Threat boundaries and alternatives

- **Domain.Validate rejects all future states:** rejected; it also validates retained/historic data and would erase an intentional future verification/incident representation, breaking existing read-gate semantics.
- **Only reject in the HTTP issuer:** insufficient; real issue is an alternate direct writer. The current issuer already fixes `Unverified`.
- **Only change the PostgreSQL CHECK:** unnecessary scope/risk; immutably checksummed V001 supports future trusted status transitions and historic incident data. DB owner/manual writes/restore remain outside this app-layer admission and require independent controls.
- **Treat qualified/incident labels as proof:** prohibited. The new guard does not perform RFC3161 CMS verification, historical QTSP EU Trusted List validation, signed event custody, WORM/legal hold or eIDAS/CAB/AgID certification. Local SHA256 equivalence is only local byte consistency.
