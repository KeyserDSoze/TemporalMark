# ADR 0046 — CI-only CycloneDX inventory from pinned npm lockfiles

Status: **accepted for disposable CI dependency inventory; not certified production SBOM or build provenance**, 2026-11-16. Child [#77](https://github.com/KeyserDSoze/TemporalMark/issues/77) of open [#20](https://github.com/KeyserDSoze/TemporalMark/issues/20). Reviewed ADR 0001 and 0043–0045, `docs/ROADMAP.md`, `docs/THREAT_MODEL.md`, `docs/NPM_LOCKED_INSTALLS.md`, `docs/CI_ACTION_PINNING.md`, the entire four-job workflow, current lockfile-integrity source policy and both npm v10 v3 lockfiles (475 PWA entries and 9 Playwright entries including their roots). References: [CycloneDX 1.5 JSON schema](https://github.com/CycloneDX/specification/blob/master/schema/bom-1.5.schema.json), [GitHub workflow artifacts](https://docs.github.com/en/actions/using-workflows/storing-workflow-data-as-artifacts).

## Problem

The committed npm lockfiles and `npm ci` guarantee a *dependency-resolution snapshot*, but there is no separately exported inventory that incident responders/CAB can inspect to identify exact package versions and integrity. Existing CI successes contain tests but no npm bill of materials. A reproducible dependency list is useful for later vulnerability analysis; a lockfile-derived list must **not** be mislabeled as a complete deployed binary/container SBOM, security scan or verified artifact provenance.

## Decision

1. Introduce a deterministic, dependency-free Python 3 stdlib generator `tests/integration/generate_npm_sbom.py` for **both** `src/frontend/package-lock.json` and `tests/frontend/package-lock.json`, producing two isolated CycloneDX **JSON 1.5** documents. Each lockfile dependency occurrence maps to exactly one `library` component; preserve nested duplicate paths by unique `bom-ref` built from lockfile path rather than deduplicating identical package name/version. Derive correct `pkg:npm/...` package URLs including encoded `@scope` and version. Convert each actual registry SRI digest into a CycloneDX hexadecimal hash, validating digest length, and include explicit `dev`/`optional` source-lock flags as properties. Include application root metadata, lockfile SHA-256 identity, source and `npm-lockfile-only` provenance. Omit unprovable graph edges, timestamps and serial numbers to avoid inventing installation facts or nondeterminism.
2. Provide a **fail-closed semantic verifier** that independently checks each input package identity, unique bom-ref, `purl`, version, integrity, `dev`/`optional`, correct source lockfile hash and exact package coverage. Detect missing, extra, modified or duplicate entries, incorrect root/scope and malformed BOM. Inputs must remain lockfileVersion 3 and satisfy the existing checked-in manifest policy; no network packages/tools are fetched by generator.
3. Mandatory TDD: commit this ADR before test changes. Add a Python source-policy test that requires the frontend job to generate, verify and upload both CycloneDX documents **after npm ci**, using the pre-existing full-SHA-pinned `actions/upload-artifact`. First commit the source gate and its unit tests against workflow lacking the steps and verify real CI backend **RED** because there is no SBOM evidence, while unit tests pass. Then implement generator/verifier and negative tamper tests, wire the frontend job to emit into `$RUNNER_TEMP/temporalmark-npm-sbom` and upload only two JSON files with 7-day retention. `contents: read` workflow permissions remain; no `id-token: write` or broad new token claims.
4. Close only #77 once final exact-head `main` CI has all **four** successful jobs, including real PostgreSQL full logical restore with separate synthetic witness, PWA service worker navigation tests, Keycloak TOTP/PKCE and Terraform. Update `docs/ROADMAP.md`, `docs/THREAT_MODEL.md` and a runbook, and record RED/GREEN evidence in #77 and #20.

## Nonclaims and outstanding controls

An inventory built from a package-lock tree includes dependencies that might not install on this OS/architecture (e.g. optional macOS-only packages), and may exclude downloads from post-install scripts, browser binaries, NuGet/.NET, OS/container images, Terraform providers and deployment runtime. A registry integrity digest is not a trusted publisher signature or vulnerability assessment. Retained GitHub upload artifacts are **not attested/signed WORM**, independently audited, legally preserved evidence or guaranteed permanent; genuine source-to-artifact provenance, signed attestations, independent SCA/SAST/SBOM for .NET+OCI, secret scans, branch protection, CAB review, mobile PWA installation and tenant isolation remain #20. #64/#61/#57/#17 remain release blockers and V015/V016 reviewer/registrar issuance restrictions stay in force. Never claim FIDO R46 trust, eIDAS qualification or approved QTSP status.
