# ADR 0107 — Deny column-level organization mutation and REFERENCES/TRIGGER grants at Entra PostgreSQL startup

Status: **Accepted, scoped development hardening [#142](https://github.com/KeyserDSoze/TemporalMark/issues/142)** on 2026-11-21. Parent #128/#18 and organization #14 remain OPEN. No Azure provisioning, CAB approval, live Entra SQL principal, legal WORM or eIDAS qualification.

## Existing architecture and evidence

Reviewed ADR 0001 (portable on-prem/Azure .NET 10), ADR 0099 (one read-only open-session PostgreSQL least-privilege preflight), ADR 0100 (mandatory prelisten on *explicit*, Production-only `ContainerAppsEntraCandidate` API mode) and ADR 0106 (#141 evidence/audit update and column-grant fix); `docs/COMPLIANCE.md`, `docs/DATABASE_MIGRATIONS.md`, `docs/POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md`, `docs/API_POSTGRES_ENTRA_PRELISTEN_CANDIDATE.md`, current source and real PostgreSQL test; V001 tenant/admin membership invariants, V004 runtime grants and all 20 immutable applied migrations. Default Password mode, active Azure Terraform and CLI/migrator are not guarded by this opt-in startup query. The existing preflight correctly requires SELECT on `public.organizations` and `public.organization_memberships` and rejects table-level INSERT, UPDATE, DELETE, TRUNCATE, but does **not** reject column-specific UPDATE or effective table/column REFERENCES or table TRIGGER grants on these sensitive tenant-invariant tables. A mis-granted runtime role could pass before serving requests despite the capability to alter tenant administrators or install extra triggers. Unlike #141's prior fixes on evidence/audit tables, org/membership permissions are not yet covered. This affects the prelisten least-privilege check only; the deployed SQL roles already restrict direct mutation and remain unchanged.

PostgreSQL 17 official [system privilege functions](https://www.postgresql.org/docs/17/functions-info.html) state `has_any_column_privilege` returns true for table-wide or **individual-column** UPDATE/REFERENCES; [GRANT](https://www.postgresql.org/docs/17/sql-grant.html) explicitly supports these column grants and table TRIGGER. Table ownership rights to ALTER/DROP cannot be represented as ordinary grants and remain a separate review.

## Decision

1. Retain existing **one parameterized, read-only PostgreSQL catalog/ACL SELECT** and current SQL/user checks. Replace each `NOT pg_catalog.has_table_privilege(table, 'UPDATE')` on `public.organizations` and `public.organization_memberships` with `NOT pg_catalog.has_any_column_privilege(table, 'UPDATE')` to cover whole-table and any column. Add `NOT pg_catalog.has_any_column_privilege(table, 'REFERENCES')` and `NOT pg_catalog.has_table_privilege(table, 'TRIGGER')` for both tables. Keep existing INSERT/DELETE/TRUNCATE denies, required SELECT, runtime group/principal restrictions, no bootstrap EXECUTE, and separate #141 evidence/audit denies.
2. **Test-first real PostgreSQL RED** on `main` before code: add eight xUnit cases to the established Docker PostgreSQL 17 privilege test fixture, using a separate generated disposable LOGIN role **per case**, membership only in `temporalmark_runtime_group` (never grant shared group or change migrations), and verify the role first PASSES the current preflight; then grant a single extra column UPDATE, whole-table REFERENCES, column REFERENCES or TRIGGER privilege to that role, and require the existing preflight to deny with a fixed generic no-inner exception without disclosing role/password. Always revoke extra privilege, membership and drop role in `finally` even on RED. Verify genuine GitHub docker-smoke RED of tests-only SHA (expected missing-denial assertion failures), not just compilation/tool failures.
3. Implement the minimal predicate-only source patch afterward; no other C# modules, SQL schema/migrations, role bootstrap, active Azure Terraform, NuGet deps or OSS on-prem default auth changes. Run final GitHub CI with PostgreSQL (including 20 migrations and restore), browser/Keycloak MFA and signed two-tenant API test.
4. Update preflight/Entra runbooks, THREAT_MODEL and ROADMAP. This is **point-in-time** runtime capability screening, not protection against drift after startup, ALTER/DROP ownership, SECURITY DEFINER or arbitrary future SQL objects. SQL platform authorization and Entra SQL grants must be separately tested and approved. It does **not** prove qualified electronic timestamps, WORM, legal preservation, privacy/DPIA or data locality.
