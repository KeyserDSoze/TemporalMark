# ADR 0040 — PWA navigation fallback must exclude API and control-plane routes

Status: **accepted for a narrowly scoped frontend security regression**, 2026-11-16. Child [#71](https://github.com/KeyserDSoze/TemporalMark/issues/71) of delivery [#20](https://github.com/KeyserDSoze/TemporalMark/issues/20). Reviewed ADR 0001 (deployment parity), ADR 0003 (tenant access), `docs/ROADMAP.md`, `docs/THREAT_MODEL.md`, `src/frontend/vite.config.ts`, production Nginx routing and Playwright/docker CI. Technical authority: [vite-plugin-pwa generateSW route exclusion](https://vite-pwa-org.netlify.app/workbox/generate-sw) and [Workbox GenerateSW `navigateFallbackDenylist`](https://developer.chrome.com/docs/workbox/modules/workbox-build).

## Problem

The PWA's Workbox `navigateFallback: "/index.html"` legitimately handles offline SPA paths, but no route-denylist is configured. A service-worker-controlled *navigation* to a same-origin `/api/...` URL, even when requested with the browser's navigation-oriented `Accept: text/html`, can be served the cached SPA shell instead of the actual backend HTTP response. Workbox navigation handling is distinct from ordinary `fetch` API requests; the existing `runtimeCaching: []` prevents arbitrary runtime cache rules but does not exclude API *navigations* from the shell fallback. Misleading 200/HTML responses can mask authentication errors, complicate incident response, or interfere with integrity/error handling. This does **not** prove API response contents were persisted in CacheStorage.

## Decision

1. Keep `generateSW` and static asset precache. Explicitly set `workbox.navigateFallbackDenylist` to anchored, efficient `/^\/api(?:\/|$)/`, `/^\/healthz(?:\/|$)/`, and `/^\/realms(?:\/|$)/` path patterns. Only actual SPA navigations may be served `index.html`. Never runtime-cache protected API, OIDC, timestamp tokens, exports or user-specific responses. Continue `runtimeCaching: []`. Do not add opaque/credentialed cache handlers.
2. **RED first**: a new Playwright Chromium smoke test runs against the built Nginx/Docker app in the existing `docker-smoke` job, not Vite dev mode (where the production worker may not exist). Confirm a registered, *controlling* worker. Navigate an unauthenticated browser to `/api/timestamps` (same-origin route; precise backend status is implementation-specific) and require that it is **not served the offline HTML SPA shell**; assert no CacheStorage keys reference `/api/`. A normal `/` SPA navigation remains functional. This is an integration test of actual generated Workbox output, not a grep of TypeScript config.
3. After captured CI RED, GREEN `vite.config.ts` policy and rerun all four CI jobs on final main SHA before closing only #71. Document expected offline error/network semantics of excluded routes. Do not cache authorization headers, OIDC callbacks, evidence ZIP or TSV/TSR downloads. Service worker routing **is not a server authorization boundary**; API still enforces authentication, tenant isolation and no-cache response headers.
4. No backend migration, SQL role, V015/V016 release interlock, FIDO metadata trust, reviewer credential enrollment, WORM/eIDAS/QTSP qualification, or change in Azure vs OSS functional contracts. #20 remains open for pinned npm lockfiles, action/container pins, SAST/SBOM, mobile install and wider API cross-tenant coverage.

## Threats and residual controls

An untrusted/stale service worker or attacker with origin XSS remains dangerous; update/recovery, CSP, secure static hosting, HTTP response `Cache-Control: no-store` for sensitive resources and defense-in-depth browser testing still require independent review. Offline API navigation must fail rather than display silently cached app content. No test can infer that an arbitrary browser's pre-existing third-party service worker or browser disk cache is empty; the test creates a clean isolated Playwright context.
