# ADR 0099 — Detached read-only PostgreSQL runtime SQL privilege preflight

Status: **Accepted for scoped, nondeployed child [#133](https://github.com/KeyserDSoze/TemporalMark/issues/133)**, 2026-11-20. #128 Azure PostgreSQL Entra-only migration, #18 Azure production and all legal qualification gates remain OPEN.

## Prior evidence and source review

Reviewed ADR 0001, 0095–0098, docs/COMPLIANCE, ROADMAP, THREAT_MODEL, DATABASE_MIGRATIONS, OPERATOR_PROVISIONING, the isolated PostgreSQL Entra/UAI candidate and detached Npgsql 10/ACA token components, `scripts/apply-migrations.sh`, `scripts/setup-local-db-roles.sh`, V004 roles and V001–V020 immutable migration scripts, the real PostgreSQL 17 Docker Compose stack and existing `TemporalMark.Postgres.Tests` privilege tests. The current Azure reference `infra/azure/main.tf` **still embeds `administrator_password=var.postgres_password` in Terraform state**, and none of the #129–#132 candidates is deployed or wired to the API/Provisioner/migration runner. Runtime (member of `temporalmark_runtime_group`) must not inherit privileged `temporalmark_provisioner_group`, `temporalmark_approver_group` or Azure `azure_pg_admin`. Separate migration-owner controls are not automatically enforced by Azure managed identity.

PostgreSQL 17 [`pg_roles`](https://www.postgresql.org/docs/17/view-pg-roles.html), [`pg_has_role` and `has_*_privilege`](https://www.postgresql.org/docs/17/functions-info.html) enable a **read-only, session-local** check of effective current SQL role, direct+inherited privileges and membership (the latter catches roles that can be enabled using `SET ROLE`). Membership of `pg_read_all_data`, `pg_write_all_data`, `pg_monitor`, `pg_execute_server_program`, `pg_read_server_files`, `pg_write_server_files` and, when it exists, Azure `azure_pg_admin`, must be rejected even if attributes like `rolsuper` are false. Microsoft [PostgreSQL Entra configuration](https://learn.microsoft.com/en-us/azure/postgresql/security/security-entra-configure), [access control](https://learn.microsoft.com/en-us/azure/postgresql/security/security-access-control) and [managed identity login guidance](https://learn.microsoft.com/en-us/azure/postgresql/security/security-connect-with-managed-identity) distinguish an actual PostgreSQL SQL principal from possession of an Entra access token and caution against ordinary work using elevated Entra admin roles. Privileges and ownership can change outside this preflight's lifetime, so this **does not** replace server-side GRANT review or RLS.

## Decision

1. Add only a **detached, opt-in C# helper** `PostgresRuntimePrivilegePreflight.VerifyAsync(NpgsqlConnection connection, string expectedRuntimeLogin, CancellationToken)` to the already locked Npgsql 10 `TemporalMark.Infrastructure.Postgres` library. It must be called only on an already **open** connection. No API/Provisioner startup behavior, on-prem or Azure Terraform, SQL login, container identity, PostgreSQL schema, migration script or connection pool changes. The expected DB login is a fixed, separately approved configuration, **not** a tenant/request/claim-supplied principal.
2. Run a **single read-only PostgreSQL catalog/ACL SELECT**, without `SET ROLE`, `GRANT`, `INSERT`, `UPDATE`, `DELETE`, `CREATE`, `ALTER` or savepoints. Validate `session_user = current_user = expectedRuntimeLogin` to deny impersonation/role switches; the `pg_roles` flags `rolcanlogin=true`, `rolsuper=false`, `rolcreatedb=false`, `rolcreaterole=false`, `rolreplication=false`, `rolbypassrls=false`; member of `temporalmark_runtime_group`, but **not** a member of `temporalmark_provisioner_group` or `temporalmark_approver_group`; never a member of privileged catalog groups `pg_monitor`, `pg_read_all_data`, `pg_write_all_data`, `pg_execute_server_program`, `pg_read_server_files`, `pg_write_server_files`, and conditional `azure_pg_admin` if present. Catalog differences between OSS PostgreSQL and Azure are handled only for **optional** `azure_pg_admin`, not by globally ignoring missing required roles. Also deny database `CREATE`, public-schema `CREATE`, organizations/memberships table mutations, and direct bootstrap-function `EXECUTE`; require public schema `USAGE`, organization/membership `SELECT` and timestamp registry `INSERT`.
3. Input validation: non-empty, bounded, canonical approved PostgreSQL role name, no Npgsql SQL interpolation (parameterize expected value), already opened connection. Re-throw explicit caller cancellation; any other database/transport/permission/catalog exception becomes a fixed generic `InvalidOperationException` **without inner exception**, never exposing connection string, token, SQL role names, catalog SQL text or server errors. Rejection must be no-write and fail closed. The result is only a boolean PASS or generic denial, not a leaked catalog report.
4. **TDD RED first:** commit xUnit tests in existing real `TemporalMark.Postgres.Tests` before implementation, run GitHub CI and demonstrate a compilation failure for the absent helper (not merely a mocked return value). The Docker pipeline supplies existing local runtime/provisioner/approver and admin passwords only within local CI. Positive runtime session must PASS; elevated real PostgreSQL owner/superuser and provisioner/approver sessions must DENY; wrong configured expected login, null/closed connections, invalid identity and cancellation must DENY; confirm no schema-migration count/checksum drift. Then implement minimal library helper, re-run real CI.
5. Record operator usage and limitations in new `docs/POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md`, ROADMAP, THREAT_MODEL, DATABASE_MIGRATIONS and the Azure UAI candidate runbook. This only checks one active SQL session; a future Azure pilot must separately approve the real Entra UAI object ID and client ID, PostgreSQL principal mapping, actual role ownership/GRANTs, private network/TLS, rotation/revocation/timeouts, separate migration/registrar DB logins, safe rollback, run preflight with a **real connected non-admin session** and review privilege drift. Current API/Provisioner **do not invoke** this prototype, so it is not a release-wide enforcement mechanism.
6. Close ONLY scoped #133 after exact final documentation-inclusive `main` SHA's GitHub backend/frontend/terraform/docker-smoke all SUCCESS, real PostgreSQL positive/negative tests plus dump/restore, Keycloak signed two-tenant 401/403 and browser TOTP/PKCE, all Terraform simulated plans, and aggregate exact SHA `temporalmark/ci-4-core-jobs=success`. #128/#18/#115/#17/#13/#15 remain OPEN.

## Explicit nonclaims

No Entra service principal is created, assigned, authenticated or SQL-granted; no Azure token or network test; no Terraform apply; no admin password removed from current/historical state. This preflight is not proof of exhaustive PostgreSQL privilege absence, RLS, immutable legal custody, qualified eIDAS timestamping, QTSP certification or safe live operation.
