## Gap, threat and strict constraints

Synchronous ZIP `ExportZipAsync` asks the registry `ForExportAsync(organizationId, UTC period, ExportLimit + 1=10001)`. Business rejects **>10000 retained records**, **any DER >1,048,576 bytes**, or **aggregate raw DER >67,108,864 bytes**, using `ExportTooLargeException` mapped to **HTTP 413** before creating ZIP or append of `period_export_prepared`. However, `PostgresTimestampRegistry.ForExportAsync` still issues `SELECT ... response_der` for all selected rows and loads every `byte[]` into Npgsql before those checks. A single authorized request could read many gigabytes across wire and managed memory then get 413. #172's `ReadBoundedMetadataAsync` uses a **generic InvalidOperationException** on a failed page/search and cannot directly replace export without regressing its 413 contract.

## Decision — single-statement all-or-none projection for export, preserving 413

1. **Commit this ADR first**; then tests only in `tests/backend/TemporalMark.Postgres.Tests` and a disposable real signed-Keycloak A/B API smoke assertion after the preexisting SHA-consistent oversized A-tenant fixture. Negative PG17 tests with distinct disposable orgs and SHA-consistent bytes: (a) one 1MiB+1 row, (b) 65 different 1MiB rows totaling 65MiB, and (c) 10,001 small rows, each must cause **`PostgresTimestampRegistry.ForExportAsync` itself** to throw `ExportTooLargeException` instead of returning materialized raw DER. Positive: exactly 1MiB and exactly 64MiB across 64 valid receipts accepted with original bytes, UTC ordering, tenant isolation; real `TimestampRegistryService.ExportZipAsync` must still produce a valid ZIP manifest/tokens, or throw `ExportTooLargeException` on each negative; empty export valid. API after adding one malformed A row must return **413** (generic no-private-content) and not append `period_export_prepared` for the refused A download, while B tenant's export remains 200 with its own DER and its prepared audit. Confirm actual GitHub Actions **RED with precise missing-denial failures** (not compiler/fixture/SQL errors) before production code.
2. **After independently confirmed RED only**, implement a dedicated parameterized `BoundedExportSql` and provider method, **not** changing page/search. In one PostgreSQL17 `SELECT`, `chosen AS MATERIALIZED` selects only `id, octet_length(response_der)::bigint AS der_bytes` constrained by `organization_id=@org AND issued_utc >= @start AND issued_utc < @end`, original `ORDER BY issued_utc,id` and caller `LIMIT @limit` (already 10001 in Business). A `guarded AS MATERIALIZED` CTE uses `bool_and(der_bytes BETWEEN 1 AND @max_receipt_bytes) OVER ()`, `sum(der_bytes) OVER ()`, and `count(*) OVER ()` **across all selected rows**, including the row-limit lookahead. Its final same-statement same-snapshot join filters both selected ID and tenant and yields **`CASE WHEN all_receipts_ok AND batch_bytes <= @max_batch_bytes AND row_count <= @max_export_records THEN t.response_der ELSE NULL::bytea END`** in original `response_der` ordinal 9. If **any** selected row or count fails, all rows project `NULL::bytea`, and provider rejects before `GetFieldValue<byte[]>` with the preexisting fixed-message `ExportTooLargeException`. Empty selection remains []. No partial ZIP/metadata, no second-query time-of-check/time-of-use race, no reliance on stored DER SHA256 to establish integrity.
3. Keep `TimestampRegistryService.ExportZipAsync`'s **own count, per-token/aggregate prehash, tenant/period/unique/UTC/`Unverified`, and true DER SHA256** gates as defense in depth. Do **not** change the `ExportTooLargeException` message, HTTP 413 mapping or prepared-audit-before-delivery order. Do not affect `PageAsync`/Search's earlier #172 `InvalidOperationException` or GET receipt 409/no-store. No SQL migrations, extra role privileges, Azure Terraform, browser, or external TSA changes.
4. Update this ADR, `docs/REGISTRY_INTEGRITY_READ_GATES.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md` and issue checklist. Close **only #173** after independently verified exact **last docs-inclusive main SHA** backend/frontend/terraform/docker-smoke **4/4 GREEN**, combined `temporalmark/ci-4-core-jobs=success`, real PG17 all original+new cases, Business 301/301, 20 migrations/full logical restore, real Keycloak A/B HTTP 413/no false audit, legitimate B ZIP, #169 409/404/no audit and #171 A page denial, independent offline ZIP v1 and Nginx privacy.

## Limits, follow-up, nonclaims

This **limits raw DER projected to Npgsql by export SELECT**, not internal PostgreSQL TOAST/sort or query CPU, connection concurrency, accepted ZIP 64MiB memory/copies, legal completeness or 10000-record exports for arbitrary multi-year periods. `FindByIdAsync` still sends a single oversized DER to Npgsql before Business 409, to be tracked separately; it is not silently fixed by #173. No WORM object lock, immutable audit/witness, complete multi-tenant export, qualified TSU/HSM/UTC(k), historical EUTL/CMS issuer validation, CAB/AgID approval or lawful indefinite retention is established. Parent #17, QTSP #15, legal #13, custody #61/#64, Azure #18 and WebAuthn #38/#50 remain OPEN. Pilot records stay `Unverified`.
