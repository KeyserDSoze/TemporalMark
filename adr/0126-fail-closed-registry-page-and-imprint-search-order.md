Exact docs-inclusive prior `main ca6d016` passed [Actions 45054194983](https://github.com/KeyserDSoze/TemporalMark/actions/runs/45054194983/attempts/1): 4/4 core jobs, Business 284/284, real PG17 247/247, full restore and two-tenant Keycloak API ZIP interoperability. There are 26 open parent/security/production issues before this child.

The real PostgreSQL provider implements ordered, bound `ORDER BY issued_utc, id LIMIT @limit OFFSET @offset` both for regular page and exact-imprint search. Business reads validate all retained DER/SHA256, tenant, half-open UTC period, unique receipt IDs, and pilot-only `Unverified`; imprint search also checks SHA256 algorithm+canonical digest and `Count <= limit + 1`. But **PageAsync does not check returned Count <= requested limit** and **neither PageAsync nor SearchByDocumentSha256Async rejects a repository result in descending `IssuedUtc,id` order**. An alternate/buggy provider can return extra metadata beyond a requested page, misreport search `hasMore` through an unordered lookahead row, or cause unstable UI next/previous traversal. This is an authorization-adjacent data-contract integrity gap, not proof of a live tenant breach or complete-period custody.

## Decision — ADR, genuine RED, minimal business validation on main

1. Commit this accepted ADR **alone before test/source**. Add **tests only** to Business xUnit using valid tenant-owned `TimestampRecord`s with intact DER+SHA256 and expected pilot validation status: negative extra `PageAsync` row above requested limit; negative descending issued timestamps on page; negative same-time descending UUIDs on page; negative descending timestamp **lookahead** in exact-imprint search (`limit=1` returning 2 rows); negative same-time descending UUID tie in imprint search; positive sorted same-time UUID pair for both boundaries. The test-only fake repository may return `overridePage` independently of SQL, while real PG tests remain untouched. Insist that each negative fails with absent `InvalidOperationException` and no tenant, provider, imprint or token details leaked. Obtain a genuine GitHub Actions backend RED on the tests-only SHA (not compilation/fixture or old failure).
2. Only **after observed RED**, preserve existing count-limit, tenant, DER, UTC, pilot-status, canonical-imprint and unique-ID checks. In `PageAsync`, reject count above requested page limit **before returning metadata**. After existing record validation in page/search, assert the **whole supplied returned batch**, including the extra search lookahead row, is in strictly ascending `(IssuedUtc, Id)` order. UTC timestamps already require zero offset; use `DateTimeOffset` comparison and for tied timestamps `StringComparer.Ordinal` over canonical lower-case `Guid.ToString("N")`, matching the lexical byte ordering of SQL `uuid`. Strictly ascending IDs at identical timestamps also rejects tie duplicates; existing uniqueness check remains separate.
3. No sorting or truncating an invalid repository batch, no bypass of lookahead check, no sensitive values in exceptions, no SQL/REST/SQL-role/migration or DTO behavior changes, and the same .NET Business component on on-prem OSS and Azure. Existing 200-row list and 50-row exact-search limits stay intact.
4. Document in ADR, registry pagination/runbook, roadmap and threat model with actual RED/GREEN evidence. Close **only #168** on independent full exact docs-inclusive `main` SHA GitHub backend/frontend/terraform/docker-smoke **4/4**, ci-verdict+aggregate, xUnit Business new and existing, Python offline/bridge, real PG17 247/247, 20 SQL checksum migrations, test-only full restore, signed-Keycloak tenant A/B API/search/ZIP and Nginx privacy/429 pass.

## Limit

This is **one-batch** page-contract validation. It does not make offset pagination a stable transactional snapshot under concurrent inserts/deletes; does not prove all receipts across pages or an arbitrary time interval were retained; and does not create WORM/signed manifest, independent witness, qualified RFC3161/CMS/EUTL validation, HSM UTC(k), CAB/AgID certification or production authorization. Open blockers #14/#17/#15/#13/#61/#64/#18/#38/#50 remain OPEN. All pilot records remain `Unverified`.
