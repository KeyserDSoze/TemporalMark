# ADR 0101 — Deterministic PostgreSQL epoch-minute quota test evidence without weakening V019

Status: **Accepted for scoped integration-test repair [#135](https://github.com/KeyserDSoze/TemporalMark/issues/135)**, 2026-11-21. The parent security/privacy issues [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) and [#113](https://github.com/KeyserDSoze/TemporalMark/issues/113) stay OPEN for production-rate, DPIA/retention and gateway controls.

## Evidence and prior decisions

Reviewed ADR 0001/0082/0083/0084/0085, docs/IMPRINT_SEARCH_RATE_LIMITING.md, DATABASE_MIGRATIONS.md, ROADMAP.md, THREAT_MODEL.md, the original immutable PostgreSQL 17 V019 `consume_imprint_search_rate(uuid,text)` and V020 owner-only rate-counter cleanup scripts, real `ImprintSearchRatePostgresTests.cs` / cleanup SQL tests, current Docker GitHub Actions and signed-Keycloak tenant A/B 429/401/403 smoke. The existing #116 SQL contract is **12 admitted searches per authenticated principal and 30 admitted per tenant per PostgreSQL-owned, UTC-aligned epoch-minute**. It uses `floor(extract(epoch from clock_timestamp()) / 60)`, not a rolling 60-second interval, and refuses corruption/clock rollback. Roles, SQL rate table ACLs, data minimization (no SHA-256 imprint/JWT in keys), 429/Retry-After and shared-single-primary constraints must be preserved.

Observed [real GitHub CI 44824634172](https://github.com/KeyserDSoze/TemporalMark/actions/runs/44824634172), job `136594521559`: 94/95 PostgreSQL tests PASS, failure `ImprintSearchRatePostgresTests.TenantAggregateRestrictsRotatingPrincipalsButNotOtherTenants` line 84: after 30 sequential admissions, the 31st returned `Allowed=true` while the test assumed it must be denied. Another unchanged commit passed 95/95. This is a **credible fixed-minute-boundary test failure**, not independently proven to be SQL overadmission: the original test does not query server time or check the counter `window_start`, so existing logs cannot distinguish an epoch-minute rollover from a real quota bypass. It is important **not to close #135 merely on an inferred timestamp**.

Authoritative PostgreSQL 17 [date/time functions](https://www.postgresql.org/docs/17/functions-datetime.html) explain that `clock_timestamp()` reflects the **real changing clock, even within one SQL statement**, whereas `now()` / `transaction_timestamp()` refer to a transaction's start. Database SQL V019 uses real `clock_timestamp()` intentionally. Tests must use the same PostgreSQL epoch-minute source, not `DateTime.UtcNow`, mocked C# clocks, `pg_sleep`, the CI runner clock, or a long SQL transaction with `now()` that cannot detect rollovers.

## Decision

1. **Change integration tests and documentation only**, not any V001–V020 migration checksum/contents, SQL function, API rate middleware, SQL privileges, on-prem/Azure runtime behavior, signed OIDC or tenant access checks. Preserve zero data leaks and fail-closed rate/clock regression coverage.
2. Provide one small **test-only bounded server-minute evidence helper** in the existing `TemporalMark.Postgres.Tests` project. Given a callback reading PostgreSQL `SELECT floor(extract(epoch from pg_catalog.clock_timestamp()) / 60)::bigint` and a fresh-tenant scenario, capture the integer epoch-minute before and after **every scenario**; return its result ONLY when they match. If they differ, discard only that *inconclusive test observation*, not any SQL denial, create a **new disposable test tenant** and retry at most **three total attempts**. On third rollover, throw a clear generic test failure; never infinite-loop, sleep, skip the xUnit test, suppress SQL exceptions, expand/erase quota, or infer production availability. Do not log tenant IDs, principal subjects or response imprint/bytes. A real incorrect denial or overadmission **within a verified identical server minute still fails the test**.
3. Apply to the existing actor-limit, tenant-with-rotating-principals and multi-session concurrency tests. Each scenario's original expected PASS/DENY/Retry counts and persisted SQL `hits` are validated after verifying that the server minute did not advance. The helper's own **synthetic two-sample boundary unit tests** must prove it refuses an inconclusive first attempt and retries, while three sequential shifts fail closed; this pure logic test is *not* proof of an actual minute change in CI. Real PostgreSQL 17 integration tests obtain the bucket from its server and record safe counter/window evidence. No use of a caller-side clock.
4. Add a **real PostgreSQL positive rollover/reset test without waiting for wall time**. On a fresh disposable tenant, use the separately privileged **test-only migration-owner SQL login** to seed the V019 tenant and actor counter rows to the **previous PostgreSQL epoch-minute** at 30/12 hits (test fixture intervention; no production function change); call V019 through the ordinary low-privilege runtime SQL login and require admission with counters reset to one and matching, current PostgreSQL-aligned `window_start`. This demonstrates why the first request of a **new** minute is correctly admitted even after the **old** minute was exhausted. Keep actor names and tenant IDs in test database only; never grant the runtime role direct rate-table modification.
5. TDD: commit ADR 0101 before tests; add real PostgreSQL+xUnit tests that depend on missing helper, confirm actual GitHub Actions Docker **RED compile**; then add minimum helper and refactor existing tests to use it. Confirm GREEN real PostgreSQL and all full CI; no Azure apply or legal qualification claims.
6. After final docs-inclusive exact main SHA passes four core GitHub Actions jobs backend/frontend/terraform/docker-smoke and aggregate `temporalmark/ci-4-core-jobs=success`, record SQL test counts, real Keycloak signed tenant A/B and 429/401/403, 20 checksum-preserved migrations, full pg_dump/pg_restore, Playwright and Terraform mock plans. Close only #135, leave #115/#113 and unrelated #128/#18/#17/#13/#15 OPEN.

## Explicit limitations

A passing fixed-minute test demonstrates rate limits on **one real PostgreSQL instance** under its observed clock; it cannot prove globally synchronized HA/failover, cross-region common primary, edge/pre-auth abuse handling, log governance, GDPR retention/DPIA approval or eIDAS/WORM/QTSP qualification. Clock jumps backwards remain a separate fail-closed SQL policy and other tests must continue to exercise it.
