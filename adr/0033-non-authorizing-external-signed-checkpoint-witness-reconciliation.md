# ADR 0033 — Scoped offline detached signed checkpoint witness reconciliation (test-only)

Status: **accepted for a non-authorizing cryptographic/restore-regression slice**, 2026-11-16. Focused [#63](https://github.com/KeyserDSoze/TemporalMark/issues/63) child of open #61/#57/#55. Reviewed ADR 0025–0032, `docs/MDS_CRL_UNAPPROVED_CHECKPOINT.md`, V017 owner-only SQL and existing xUnit PostgreSQL fixtures.

## Threat boundary

V017 serial/digest claims are **caller supplied** and ordinary PostgreSQL storage can be rolled back by a backup restore or edited by a privileged owner. A previously exported, separately signed witness **could reveal** a mismatching restored database, but only when the true latest witness is obtained **out of band**, its trusted verification key is pinned and the external witness itself cannot be replaced/replayed. None of that custody, freshness, monotonic external governance, FIDO R46 root authenticity, CRL revocation status or legally immutable storage exists in this slice.

A caller can provide its own signing key, sign a forged witness and observe an `UNAPPROVED` result. This result NEVER authorizes reviewer enrollment, SQL privilege, timestamp issuance, FIDO MDS signer identity, WORM, eIDAS or QTSP. CAB/DPIA governance, external high-water-mark storage and cross-region/backup reconciliation remain #61/#57.

## Narrow decision

1. Add an **unwired** `ReviewerMdsOfflineCheckpointWitnessReconciler` in the shared .NET 10 infrastructure assembly. It takes an already opened **migration-owner** `NpgsqlConnection`, an externally supplied bounded manifest, a detached RSA-PSS/SHA-256 signature, a caller-selected **test** public RSA key and explicit UTC time. It creates no production keys, HTTP endpoints, CLI, SQL migrations/permissions, Azure dependencies, witness files or trust anchors. No production FIDO credential or signer can call it.
2. The manifest is strict UTF-8-compatible ASCII with fixed domain-separation header `TEMPORALMARK-UNAPPROVED-MDS-CRL-WITNESS-1`, a 64-uppercase-hex *untrusted* V017 source-policy fingerprint, canonical decimal issued/expiry UTC epoch seconds (observed no earlier than zero, valid for <=24h and not future/expired), and a positive bounded record count. Each record contains exact canonical `kind|issuer_key_sha256|candidate_serial|signed_evidence_sha256`. Kinds are exactly `MDS_BLOB`/`ISSUER_CRL`; values must be positive/canonical and 64-char uppercase hex, records strictly ascending, unique, and no extra/missing/trailing CR/control bytes. Signature verification over **original bytes** via maintained .NET RSA.VerifyData PSS/SHA-256 MUST precede interpretation. No JWT/CRL model parser, insecure JSON normalization, key download or homegrown crypto.
3. Only *after* signature verification, query all V017 checkpoint rows scoped to the witness policy SHA256 in a single `REPEATABLE READ READ ONLY` PostgreSQL transaction; independently check `session_user=current_user=physical table owner`, check row status `UNAPPROVED`, DB observed UTC <= supplied current time, DB expiry > now and manifest expiry <= each DB expiry. Compare the full **scoped** rowset, including count, kinds, issuers, serials and content digests, in deterministic sorted order. Reject wrong/extra/missing rows, restored lower version, equal-version content mismatch, unexpected higher DB version, stale/future manifest, invalid signature, swapped key, missing/corrupt checkpoint and insufficient rights. A witness is **source-policy scoped**, NOT a full-database snapshot. Other policy partitions cannot be inferred.
4. Return only `ReviewStatus=UNAPPROVED`, `PolicyStage=SIGNED_WITNESS_ONLY_EXTERNAL_CUSTODY_UNPROVEN`, count and witness SHA256; no `Verified`, `Trusted`, `Active`, key bytes, raw manifest or digest of actual CRLs. The source-policy fingerprint itself is caller-controlled. Prevent audit confusion: a cryptographic test signature is not a trusted **external high-water-mark**; calling this reconciler on the same mutable storage is not effective backup-restore protection.
5. RED-first xUnit tests against **live PostgreSQL 17** and disposable RSA keys, with positive exact snapshot; forged/tampered signature, wrong test public key, duplicate/unsorted/noncanonical/oversized manifest, missing row, added row, restored stale row, altered digest, future/wrong expiry, owner/role misuse. Then GREEN. Test first commit must fail on missing type; no V017 rewrite or SQL migration change.
6. Four GitHub Actions jobs **successful on exact final main SHA** before closing only #63. Parent #61 remains OPEN for real CAB-pinned independent witness signer and immutable/offline external counter, signed current FIDO R46 MDS+CRL source, trusted time, multi-primary reconciliation, restore procedure, operational audit, attestation and consent. Keep #57/#55/#53/#44/#50/#46/#38 OPEN, preserve V015/V016 and suspended registrar CLI.

## On-prem and Azure parity

The read-only reconciler has no network or cloud dependencies; live PostgreSQL behavior and tests are common. Neither platform is supplied with a production signing key, managed trusted root or external immutable store. Later custody requires separate approved installation, audit, key-rotation and disaster-recovery plans. A REST or SQL role granting operation is explicitly out of scope.
