# ADR 0016 — Unconsumable server-generated reviewer challenge

Status: accepted for **unsigned pilot challenge issuance only**, 2026-11-15. References #39 (child), #38/#35/#31 (parents), ADR 0009–0015.

## Problem

Existing tenant enrollment reviews the original database scope, and a separate OIDC reviewer may approve or reject a request, but **does not sign a one-time decision**. WebAuthn requires an unpredictable challenge generated by the relying party, associated with the intended action, and verified against the registered credential. Issuing such a challenge must never imply a valid signature or authorize any decision.

## Decision

- V012 creates an owner-controlled `organization_decision_challenges` table: **at most one challenge ever per pending request**, including original UUID, pinned issuer, reviewer stable subject, exact canonical SHA-256, intended APPROVE/REJECT, fixed rejection reason, 48-byte nonce, issue/expiry UTC and version 1. Expiry is at most 60 seconds, never beyond the enrollment request. The record cannot be updated or deleted via ordinary SQL triggers; migration owners remain privileged, so this is **not WORM**.
- PostgreSQL generates the nonce using three independent v4 `gen_random_uuid()` calls: 48 bytes with roughly **366 random bits** (six version/variant bits per UUID are fixed), without a pgcrypto extension. Its helper recomputes the original C# `PendingOrganizationReview.ReviewSha256` using built-in SHA-256 over domain-separated UTF-8 length-prefixed fields and UTC expiry ticks, so caller-supplied hashes are **independently checked inside SQL**.
- `issue_reviewer_decision_challenge` is SECURITY DEFINER with fixed search path, row-locks the original pending enrollment and checks its name, issuer, operator, first administrator, expiry and distinct reviewer. EXECUTE is granted **only to the restricted approver group**; no normal SQL role has table SELECT/DML or direct hash-helper EXECUTE.
- `IssueDecisionChallengeAsync` requires a signed OIDC approver JWT with pinned ACR/freshness, RFC7662 live status, CURRENT enabled account/role and original independent DB review. It compares the digest in constant time and rechecks live/current authorization before issuance. The separate non-HTTP CLI command `challenge --request-id UUID --review-sha256 HEX --decision APPROVE|REJECT --reason-code CODE|NONE --approver-token-file PATH` displays the nonce, scope, decision and expiry, always warning **UNSIGNED CHALLENGE ONLY**.
- TDD tests cover wrong scope/role/issuer/decision/reason, 96-character uppercase hex nonce, TTL, duplicate refusal, restricted SQL grants, and no approval, rejection, tenant or audit side effect.

## Mandatory stop line

**#39 does not close #38:** no approved reviewer credential registration, user-facing WebAuthn signature ceremony, RP ID/origin/UV/signCount verification, proof-of-possession, challenge consumption or qualified human approval exists. A challenge is not a decision or a credential. The older restricted SQL approve/reject function grants remain usable and must be removed/replaced in a signature-enforcing trusted transactional process. The demo password-only Keycloak fixture is explicitly non-MFA; the separate real-OTP CI fixture does not demonstrate independent humans/device possession.

This table is ordinary PostgreSQL, **not signed or legal WORM evidence**. Keep #38/#35/#31/#27 and evidence/QTSP #17/#13 OPEN. Production Keycloak/Entra on-prem/Azure requires independent credential enrollment, reviewed policy, device-loss procedures, vault-backed secrets and external assurance.
