## Threat

Current `PostgresTimestampRegistry.PageAsync` and `SearchByDigestAsync` run `SELECT ... response_der`, and Npgsql `GetFieldValue<byte[]>` materializes *all* raw DER bytes before `TimestampRegistryService.ValidateReturnedRecords` enforces #171's post-read size bounds. A 200-row page with 1MiB each can send 200MiB before its 64MiB rejection; one corrupted/legacy multi-megabyte DER is sent before single-row rejection. The real provider is tenant-filtered but lacks a **wire-projection** bound. The SQL roles and database schema already exist and must remain unchanged.

## Decision — same-statement PostgreSQL materialized key/size CTE + guarded bytea projection

1. **Commit this ADR first**. Commit **real PG17 xUnit tests only** under `tests/backend/TemporalMark.Postgres.Tests` for a unique, disposable organization per scenario: a SHA256-consistent 1MiB+1 bytea row must cause **`PostgresTimestampRegistry.PageAsync` itself** to fail closed with constant `InvalidOperationException` (before Business gets a record); exact 1MiB page passes and bytes match; imprint search must reject a valid first row when a second over-budget row is **within the limit+1 lookahead**, while other valid tenant rows remain accessible; ordered 65 rows of 1MiB exceeds 64MiB and is refused **at the provider**, whereas 64 rows of 1MiB remain allowed. Use PostgreSQL `decode(repeat('00',size),'hex')` for disposable records; in-process expected SHA256 over one reusable zero buffer, no customer evidence, no test token/DER/hash logs. One additional test assures `ForExportAsync` retains its original specialized Business `ExportTooLargeException` route and the provider does not remap 413 to generic 500. Confirm genuine GitHub **RED** (expected missing-denial assertions, not test setup, compile or auth failures) before changing source. In parallel keep existing real signed-Keycloak two-tenant A page denial/B valid, GET receipt 409/404/no false prepared audit.
2. **Only after RED**, change **PageAsync and SearchByDigestAsync** to use exactly **one parameterized SQL `SELECT` statement each**, with `WITH chosen AS MATERIALIZED` containing **only selected registry IDs plus `octet_length(response_der)::bigint`**, ordered `issued_utc,id` with original tenant, UTC-period, optional canonical SHA256 digest and `LIMIT/OFFSET` constraints. Do not include raw DER in the CTE's projected columns. In a subsequent materialized aggregate/window CTE calculate `bool_and(der_bytes BETWEEN 1 AND @max_receipt_bytes) OVER ()` and `sum(der_bytes) OVER ()` for the **entire selected batch**, including the search lookahead. Rejoin `timestamp_registry` by ID and *server-filtered tenant* within that **same statement/snapshot** and select **`CASE WHEN all_receipts_ok AND batch_bytes <= @max_batch_bytes THEN t.response_der ELSE NULL::bytea END`** in the original `response_der` ordinal position. All rows project `NULL` for DER if **any** selected row violates per-receipt or cumulative budgets (no partial DER from a failed batch); the provider rejects a NULL payload **before** calling `GetFieldValue<byte[]>`, using a constant generic `InvalidOperationException` without identifiers, digest, sizes or SQL value. No separate count-then-fetch with snapshot race. If selected batch is empty, return an empty list, same as today. Preserve ordered result rows, original SHA256 in Business (independent of stored hash) and all existing tenant/status/digest checks.
3. **Deliberately leave `ForExportAsync` on its existing separate original query**: the synchronous ZIP Business service already applies a specialized 1MiB/64MiB prehash check and maps `ExportTooLargeException` to the original HTTP 413. Altering its exception path or row cap as a side effect of a page/search refactor is unacceptable. Same for `GET /receipt` (409/no-store and exact ID) and dashboard `CountAsync`/`CountByUtcDayAsync`, none changed. Do not change SQL migrations, PostgreSQL runtime grants, HTTP API JSON or roles, PWA, Terraform, Azure candidate, OSS Docker, or enable a qualified timestamp claim. Use constants from `TimestampRegistryService` so no mismatch or new settings are introduced.
4. This SQL-side projection bounds **raw DER in the PostgreSQL result/wire** if data exceeds budgets. It **does not guarantee** that the server never reads TOAST metadata, bound PostgreSQL memory/sort work, handle global concurrency or protect against a fully compromised schema owner, or prove zero network allocation with a profiler; the guarantee is SQL projection returning `NULL::bytea` rather than oversized bytes. Npgsql normally buffers protocol row data; on an accepted batch each row remains <=1MiB and batch <=64MiB. Future large-scale streaming, snapshot pagination and independently sealed WORM evidence remain separate work under #17/#20. No assertion of legal retention or qualified RFC3161/CMS validation.
5. Update ADR 0130, registry runbook, pagination docs, threat model and roadmap. Close **only #172** when independent GitHub Actions on **exact final docs-inclusive `main` SHA** shows all four core backend/frontend/terraform/docker-smoke jobs success, combined `temporalmark/ci-4-core-jobs=success`, Business 301/301, new PG17 xUnit + original 247/247, signed-Keycloak A/B list/search/receipt/audit, 20 migration checksums, real `pg_dump/pg_restore`, proxy log/429/413/414 privacy and CAB nonclaims. Parent #17, qualified QTSP #15, legal #13, signed custody #61/#64, Azure #18, WebAuthn #38/#50 remain OPEN.

## Alternatives rejected

- **Client-only #171 guard:** prevents hashing but not PG wire/materialization; keep defense in depth.
- **Separate SQL metadata preflight, then raw DER fetch in another statement:** can suffer change/race between queries, and doubles DB round trips; a transaction snapshot plus row locks could repair it but increases scope.
- **SELECT one DER at a time with no length projection:** still materializes up to 1GB of one malformed bytea before failure.
- **Trust stored `token_sha256_hex` or run hash solely in PostgreSQL:** weakens independent Business SHA256 self-consistency and implies false qualified issuer verification.
- **Buffer all selected DER and truncate bytes in API:** hides source corruption and can falsely produce valid-looking metadata or incomplete RFC3161 tokens.
