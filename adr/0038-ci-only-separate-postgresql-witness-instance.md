# ADR 0038 — CI-only separate PostgreSQL witness instance, not immutable custody

Status: **accepted only for a test-isolated, non-authorizing witness service regression** — 2026-11-16. Child [#69](https://github.com/KeyserDSoze/TemporalMark/issues/69) of still OPEN #64/#61/#57. Reviewed ADR 0032–0037, `docs/MDS_CRL_FULL_PGDUMP_RESTORE_TEST.md`, V017, existing `MdsFullPgDumpRestorePostgresTests`, Compose CI, PostgreSQL 17 [atomic UPSERT](https://www.postgresql.org/docs/17/sql-insert.html) and [privileges](https://www.postgresql.org/docs/17/ddl-priv.html).

## Problem

#66–#68 prove a full logical PostgreSQL main-DB restore can be compared against signed test evidence held outside that DB in process memory or a normal local file. They do not demonstrate an **independent database instance and least-privilege read-only operator** retaining its latest version when the entire main DB is restored. This increment separates logical failure domains by introducing a second PostgreSQL instance only in the disposable Docker CI profile. It is neither legally protected storage nor production independent operator control.

## Decision

1. Add a **CI-only** `witness-ci` Compose profile containing a separate `postgres:17.6-alpine` container, distinct data volume, database, superuser/owner credentials and externally exposed CI loopback port 5433. It is **not started during the normal on-prem development deployment** and is not an Azure managed service or mandatory production infrastructure. A separate initialization SQL creates one synthetic monotonic witness table and append-event audit, a dedicated reader login, and strictly scoped SQL privileges. No main TemporalMark migrations are changed; V017 remains latest.
2. Test witness owner stages a synthetic source-policy scope at serial 3, then 4, each tied to the SHA256 of the corresponding **already-signed ADR 0034 seal**. The SQL writer function rejects invalid claims, equal/lower serial and same-version equivocation using `INSERT ... ON CONFLICT DO UPDATE ... WHERE new_serial > existing_serial` inside a single atomic transaction with an audit insert. Revoke PUBLIC table/function privileges. Reader has only `CONNECT`, schema `USAGE`, table `SELECT`, no write grants or writer `EXECUTE`. A compromised witness **owner** can still bypass the function, mutate data, reset history, restore its own DB or replace both instances; this is deliberately **not** immutable or independently governed.
3. Add isolated .NET 10 `ReviewerMdsIsolatedPostgresWitnessReader`: require two **already-open** separate NpgsqlConnection objects (primary-DB owner and witness-DB reader). First read the synthetic source-policy latest witness seal SHA from **read-only REPEATABLE READ** snapshot using exact reader/owner role checks and deny missing/revoked/stale/future rows or write privileges. Extract only the claimed source-policy hash from the untrusted seal (no trust assigned), then reuse the *existing* ADR 0034 detached RSA-PSS/SHA256 seal/witness verifier and ADR 0033 primary owner-only snapshot reconciliation. Successful output always `UNAPPROVED/SEPARATE_TEST_POSTGRES_WITNESS_NO_IMMUTABLE_CUSTODY`, never `TRUSTED`, `ACTIVE` or a production FIDO root.
4. TDD: commit ADR then RED missing-type tests. Extend the **mandatory real full logical `pg_dump -Fc/pg_restore`** CI step to start independent witness container/profile, and .NET integration to create disposable signed test seals, stage serial 3→4 on the *separate* witness DB, assert SQL role denial, inspect current primary vs unchanged witness latest and reject old fully restored primary against that latest witness record. An attacker who controls independent witness root / Docker host and restores its old snapshot **still bypasses** this check: document rather than conceal. Test independent witness outage returns denial, no fallback to earlier file or caller latest pin.
5. No automatic source trust: hashes, signer public keys, MDS/issuer CRL status and time are synthetic claims, **not** independently audited FIDO Alliance R46/JWS/x5c signed certificate chains, all-hop CRL/OCSP, qualified TSA, legal immutability or user approval. No SQL privileges on main, no V018, API/CLI activation, reviewer credential status, real Azure dependency or proprietary on-prem runtime requirement. V015/V016 registrar issuance freeze and suspended intent CLI remain. Only #69 may close after **all four GitHub Actions jobs SUCCESS on exact final `main` SHA**; #64/#61/#57/#55/#53/#44/#50/#46/#38 remain OPEN.

## Risk acceptance and next steps

This child narrows scope to a *demonstrated separate test PostgreSQL instance with least-privilege read*, not an approved immutable out-of-band authority. To close #64, an independently administered monotonic witness authority must own the signing key and version outside all app/DB backup domains, enforce immutable/offsite log or object-lock policy, support HSM/CAB key rotation and incident/recovery runbooks, separately secured on-prem OSS and Azure deployments, and real physical PITR/region/clock/split-brain tests. A CI owner/superuser and test password are **not** a secure separation of administrative control.

Official technical reference: [PostgreSQL 17 INSERT](https://www.postgresql.org/docs/17/sql-insert.html), [PostgreSQL 17 roles and privileges](https://www.postgresql.org/docs/17/ddl-priv.html).
