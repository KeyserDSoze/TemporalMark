# ADR 0114 — Deny API runtime direct access to owner-controlled enrollment request and decision-challenge tables at Entra prelisten

Status: **Accepted for scoped test-first PostgreSQL privilege drift hardening [#149](https://github.com/KeyserDSoze/TemporalMark/issues/149)**, 2026-11-21. Parent Azure Entra #128/#18, tenancy #14, reviewer-held signed consent #38/#35/#31, WORM custody #17, eIDAS/QTSP #13/#15 remain OPEN. No live Azure pilot, SQL grants, migration or legal status are changed.

## Evidence reviewed

Existing architecture and ADR 0001/0009/0015/0016/0099/0100/0107/0111/0113, `docs/POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md`, `docs/API_POSTGRES_ENTRA_PRELISTEN_CANDIDATE.md`, `docs/OPERATOR_PROVISIONING.md`, `docs/DATABASE_MIGRATIONS.md`, `docs/ROADMAP.md`, `docs/THREAT_MODEL.md`; immutable V006 (owner-controlled `organization_enrollment_requests`), V010 (rejection metadata, proof fingerprints), V012 (owner-controlled `organization_decision_challenges` with explicit PUBLIC/reviewer/provisioner/runtime REVOKEs), and existing `PostgresRuntimePrivilegePreflight.cs` / real PostgreSQL17 disposable LOGIN tests. V006 stores issuer, operator/admin/reviewer identity, approval and rejection state; V012 stores reviewer, nonce, review digest, intended decision and expiry. Normal API runtime **does not need direct SELECT or DML** against either table. SQL provisioner/reviewer routines are separately controlled and not to be invoked by this preflight.

Official PostgreSQL 17 [access privilege inquiry](https://www.postgresql.org/docs/17/functions-info.html) and [GRANT syntax](https://www.postgresql.org/docs/17/sql-grant.html) confirm `has_any_column_privilege` detects table-wide or individual-column SELECT, INSERT, UPDATE and REFERENCES; `has_table_privilege` detects DELETE, TRUNCATE and TRIGGER. Role membership denial does not detect direct or PUBLIC table ACLs. A hypothetical extra grant to a regular SQL API login can expose personally identifiable enrolled subjects or enable mischief, even when group memberships satisfy all existing startup checks. This is **not** a finding that an actual Azure login has a misgrant.

## Decision and TDD workflow

1. Before any source change, commit **RED tests only** on `main`: 18 static InlineData test cases using the existing PG17 `PostgresRuntimePrivilegePreflightTests` fixture, nine independent direct GRANTs for **each** of `public.organization_enrollment_requests` and `public.organization_decision_challenges`: `SELECT`, one-column SELECT of a reviewer/identity field, `INSERT`, one-column INSERT of id, one-column UPDATE of a sensitive field, `DELETE`, `TRUNCATE`, `REFERENCES(id)`, `TRIGGER`. Each creates an isolated `LOGIN INHERIT` with only the existing runtime-group membership and `Pooling=false`, proves the baseline passes, then grants **one** unsafe privilege only to that test role and asserts generic, no-inner exception without username or password. `finally` revokes that grant and membership, drops role (even on expected RED). No INSERT/SELECT/UPDATE/DELETE of application tables or actual function calls. Require observed real Docker PG17 `18 failed / 148 passed / 166 total` caused specifically by missing-denial assertions; a compilation/runner failure is not a valid RED.
2. Only after observed RED add **14 fixed, effective ACL predicates** to the existing already-authenticated, single read-only `SELECT` in `PostgresRuntimePrivilegePreflight.Sql`. For **both** tables: deny `SELECT`, `INSERT`, `UPDATE`, `REFERENCES` via `NOT pg_catalog.has_any_column_privilege`; deny `DELETE`, `TRUNCATE`, `TRIGGER` via `NOT pg_catalog.has_table_privilege`. Keep prior tenant/evidence/audit/quota checks, reviewer-function EXECUTE checks and intended V019 `public.consume_imprint_search_rate(uuid,text)` allowance. No SQL migrations, role GRANT changes, DDL, API endpoint, downstream CLI, Terraform or default on-prem/legacy Azure `Password` mode change.
3. Update operator and schema docs, this ADR, threat model and roadmap with actual tests. Close #149 only when **exact final documentation-inclusive `main` SHA** GitHub Actions backend/frontend/terraform/docker-smoke all SUCCESS, fifth ci-verdict and aggregate `temporalmark/ci-4-core-jobs=success`; real PG17 166/166, 20 migration checksums, full logical pg_dump/pg_restore, disposable signed Keycloak browser OTP/PKCE, two tenant HTTP 401/403, and Nginx 413/414/429 privacy are independently verified.
4. SQL role correction requires independently approved database owner actions. Never grant API sensitive reviewer-table SQL privileges to make startup succeed.

## Stop line / residual risk

The new guard is a **one-time, point-in-time** SQL privilege review **only** in explicit Production `ContainerAppsEntraCandidate` API startup before HTTP listening; default `Password` mode and CLI do not run it. It does not prevent later GRANT/owner ALTER, DDL bypass, future tables, SQL session/connection revocation delays, a compromised migration-owner or an incorrectly deployed Entra principal. V012 challenge is **unsigned and non-authorizing**. No real independent reviewer WebAuthn proof, security CAB approval, data retention/WORM compliance, Entra production cutover, Terraform-stored admin password elimination or qualified electronic timestamp is established. Parents #128/#14/#38/#18/#17/#13/#15 stay OPEN.
