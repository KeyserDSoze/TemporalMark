# ADR 0122 — Bind v1 ZIP local CRC32 and sizes to central-directory values before parsing content

Status: **Accepted for scoped non-authorizing offline parser TDD [#164](https://github.com/KeyserDSoze/TemporalMark/issues/164)**, 2026-11-22 Europe/Rome. Parent #17 WORM/complete export, #15 delegated QTSP/CMS, #13 legal eIDAS/CAB, #61/#64 custody and #18 production remain OPEN.

## Baseline reviewed

Reviewed ADR [0004](0004-evidence-time-and-retention.md), [0076](0076-offline-zip-structure-sha256-self-consistency.md), [0077](0077-zip-compression-unix-special-file-gates.md), [0078](0078-zip-local-central-header-method-flag-binding.md), [0120](0120-offline-period-zip-strict-envelope.md) and [0121](0121-pilot-registry-unsupported-validation-state-read-gate.md); actual `tests/integration/verify_period_export.py`, existing stdlib `test_verify_period_export.py`, `TimestampRegistryService.ExportZipAsync`, `docs/OFFLINE_PERIOD_EXPORT_VERIFIER.md`, `docs/ROADMAP.md`, `docs/THREAT_MODEL.md` and CI baseline. The current .NET v1 exporter uses `ZipArchive` over a seekable in-memory `MemoryStream`; current exported entries do not need streaming data descriptors or ZIP64.

The offline parser already compares local/central compression method and flags by reading 30 bytes from each local file header. **It does not compare** the local header's 32-bit `CRC32` at offset 14, compressed size at 18 or uncompressed size at 22 with the central `ZipInfo.CRC`, `compress_size`, `file_size`. Python's `zipfile.ZipFile.read()` reads an otherwise intact fixture despite zeroing any of these three local fields; the manifest, DER, central directory CRC and SHA256 stay unchanged. The checker can claim internal structural consistency despite contradictory ZIP descriptions. This does **not** defeat a signature (none exists), prove a forged legal timestamp, or authenticate a manifest.

References: [Python zipfile docs](https://docs.python.org/3/library/zipfile.html), [CPython zipfile implementation](https://github.com/python/cpython/blob/main/Lib/zipfile/__init__.py), [.NET ZipArchiveEntry seekable-header writer](https://source.dot.net/System.IO.Compression/System/IO/Compression/ZipArchiveEntry.cs.html), [PKWARE ZIP APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT).

## Decision — tests first directly on main

1. Commit this accepted ADR **before any tests/source**. Then commit **tests only**, using real existing `build_zip()` with unchanged valid manifest, TSR, central directory and CRC. Modify only one 32-bit local header field in either `manifest.json` or the referenced `tokens/{uuid}.tsr`: CRC32, compressed length or uncompressed length. Verify unmodified Python `ZipFile.read` can still read both members, and require `ExportVerificationError` from offline verifier (six negative subcases). Add CLI redaction/nonzero for one variant and keep positives for zero/one receipt and STORE/DEFLATE. Confirm genuine GitHub Actions **RED missing-denial failures**, not a bad fixture/import/syntax error.
2. Only after RED, extend the **existing fixed 30-byte local-header inspection** with little-endian `<III` at offsets 14,18,22. Require exact agreement with the corresponding central `ZipInfo` CRC32, compressed and uncompressed lengths. For the **current v1 seekable producer**, refuse ZIP general-purpose bit 3 (data descriptor) rather than accept a different layout with unavailable local sizes. No new per-member read, extraction, decompression, network or external dependency. Denial is generic, before JSON or DER decompression.
3. Preserve prior strict outer envelope, local/central flags+method, entry names/types/compression, CRC decompression, SHA256, 100ns UTC, canonical imprint, only `Unverified`, 10,000 members, 8 MiB manifest, 1 MiB/TSR, 64 MiB aggregate DER and 80 MiB ZIP. Failures disclose no path, tenant, DER, hash or appended content. Change no API/DB/SQL/Terraform or credential rules: same artifact contract on OSS on-prem/Azure.
4. Update ADR, offline runbook, roadmap and threat model. Close **only #164** after verification on exact final docs-inclusive `main` SHA: backend/frontend/terraform/docker-smoke **4/4**, ci-verdict and aggregate status green; Python offline suite, real .NET and PostgreSQL/Keycloak/ingress/recovery regressions checked. If not verifiable, leave issue open.

## Limit

A jointly rewritten **unsigned** manifest/DER can still pass. This is a narrow binary ZIP profile consistency test, not external RFC3161/CMS signature validation, qualified service historical Trusted List proof, absolute period completeness, independently signed custody, WORM/legal retention or CAB/AgID qualification. Non-seekable/streaming data-descriptor ZIP variants need a **new independently reviewed format/ADR** before interoperability is claimed. Parent issues #17/#15/#13/#61/#64/#18, and security #38/#50, remain OPEN.
