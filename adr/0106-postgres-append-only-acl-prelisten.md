# ADR 0106 — Deny evidence and audit-table mutation privileges in the PostgreSQL Entra startup preflight

Status: **Accepted for scoped security prequalification [#141](https://github.com/KeyserDSoze/TemporalMark/issues/141)**, 2026-11-21. Parent #128/#18 Azure Entra PostgreSQL, #17 WORM and #13/#15 QTSP/eIDAS remain OPEN. No live Azure, SQL role changes, Terraform apply, CAB production approval or legal custody.

## Reviewed baseline and threat

Reviewed ADR 0001 modular on-prem/Azure portability; ADR 0099 read-only PostgreSQL runtime SQL privilege preflight (#133), ADR 0100 mandatory explicit `ContainerAppsEntraCandidate` prelisten gate (#134) and ADR 0105 hardened Npgsql bearer boundary; `docs/POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md`, `docs/API_POSTGRES_ENTRA_PRELISTEN_CANDIDATE.md`, `docs/COMPLIANCE.md`, `docs/THREAT_MODEL.md`, `docs/DATABASE_MIGRATIONS.md`; real `PostgresRuntimePrivilegePreflight.cs`, its real PostgreSQL 17 integration suite, `scripts/setup-local-db-roles.sh`, V001 baseline and V004 privilege grants (immutable V001–V020). The API Entra mode requires a single open SQL session/privilege check before exposing an HTTP listener; default Password mode and current active Azure Terraform do not use the gate. The SQL predicate denies organization and membership mutation, but for the evidence tables `public.timestamp_registry` and `public.tenant_audit_events` it currently **only requires INSERT** and does not reject UPDATE, DELETE, TRUNCATE, REFERENCES or TRIGGER. A separately mis-granted runtime login could pass the preflight and modify the registry or audit chain; it might inherit table-level access or hold a column-level UPDATE or REFERENCES grant even if its table-level ACL is clean. This limited SQL guard is **not** immutable evidence custody or WORM.

PostgreSQL 17 official [system privilege functions](https://www.postgresql.org/docs/17/functions-info.html) distinguish `has_table_privilege` from **`has_any_column_privilege`**, which checks that the role has a grant on at least one column; [GRANT](https://www.postgresql.org/docs/17/sql-grant.html) documents column-level UPDATE and REFERENCES alongside DELETE, TRUNCATE and TRIGGER table grants; [CREATE TRIGGER](https://www.postgresql.org/docs/17/sql-createtrigger.html) requires TRIGGER privilege. [Role membership](https://www.postgresql.org/docs/17/role-membership.html) permits inherited/transitive role grants; this gate already checks elevated group membership. No app migration or schema grant must change to add read-only ACL inspection.

## Decision

1. In the **existing single parameterized, read-only prelisten SELECT**, require `NOT pg_catalog.has_any_column_privilege('public.timestamp_registry','UPDATE')`, likewise `REFERENCES`, and identical two checks for `public.tenant_audit_events`. `has_any_column_privilege` covers **both table-wide and individual-column** UPDATE/REFERENCES. Also require `NOT pg_catalog.has_table_privilege(table,'DELETE')`, `'TRUNCATE'`, `'TRIGGER'` for both tables. Deny even if a granted UPDATE/DELETE/TRIGGER privilege was not yet exercised and even if no ledger rows exist. This supplements (does not replace) existing mandatory INSERT on both tables and organization/membership anti-mutation checks. Do not weaken or add SQL privileges for default PostgreSQL runtime role.
2. **Real, isolated TDD:** before source changes, add real PostgreSQL xUnit integration tests on `main` that use the existing disposable local *test-only migration owner* SQL connection to create a freshly named `LOGIN` role, grant only `temporalmark_runtime_group` membership, and prove the role PASSes the existing preflight. Individually grant one unauthorized privilege (UPDATE, DELETE, TRUNCATE, REFERENCES, TRIGGER on both tables, plus UPDATE/REFERENCES on one column) to that **test role only**, and require the preflight to deny with its existing fixed generic error, no inner exception, no secrets. Always revoke grants and membership, drop the unique role even when tests fail; do not grant anything to shared `temporalmark_runtime_group`. No production principal or migration touched. Verify actual GitHub `docker-smoke` RED (new negative tests fail, positive baseline passes) before source patch; backend/frontend/Terraform can still be green at that tests-only SHA.
3. Implement **minimal predicate extension only** in `PostgresRuntimePrivilegePreflight.Sql`. Do not add application writes, SQL role alterations, migrations, schema changes, new NuGet dependencies, on-prem/API authentication mode flags, Terraform or deployed Azure resources. Preserve fail-closed generic exceptions and caller cancellation.
4. Update SQL privilege preflight runbook, API Entra operator runbook, THREAT_MODEL and ROADMAP with negative coverage and limitations. A single point-in-time read-only prelisten guard still cannot detect later grants/role drift; PostgreSQL owner/DDL rights, table ownership and `SECURITY DEFINER` logic need independent role review. Do not claim WORM, qualified electronic timestamps, audited real Entra UAI privileges, GDPR-DPIA, CAB production acceptance or live Azure staging.
