# ADR 0029 — Isolated signed MDS JWS/X.509 **cryptographic candidate**, never revocation-complete trust

Status: **accepted ONLY for isolated, non-authorizing testable JWS/chain processing** (2026-11-16). Scoped child [#58](https://github.com/KeyserDSoze/TemporalMark/issues/58) of [#57](https://github.com/KeyserDSoze/TemporalMark/issues/57)/#55/#53, after ADR 0025–0028.

## Source and trust-boundary review

Official [FIDO MDS changelog](https://fidoalliance.org/mds-changelog/) confirms August 2026 GlobalSign **R3 → R46** root migration, August 31 R3→R46 cross-certificate at JWT `x5c[2]`, and expiration of R3 plus cross-certificate **2029-03-18**. [FIDO MDS specification](https://fidoalliance.org/specs/mds/fido-metadata-service-v3.1-ps-20250521.html) requires a signed compact JWS, `x5c` certificate chain, CRL revocation checks, and controls for externally referenced certificates. `iat` in the protected header is a profile requirement. MDS 3.1.1 deprecates reliance on `nextUpdate` alone.

The currently pinned maintained Fido2 **4.3.3** [tagged metadata repository](https://github.com/passwordless-lib/fido2-net-lib/blob/4.3.3/Src/Fido2/Metadata/Fido2MetadataServiceRepository.cs) hardcodes **R3**, and has a system-trusted chain path using `X509RevocationMode.NoCheck` plus a separate CRL-validation path for untrusted roots. It does **not** establish an independently CAB-reviewed universal R46+CRL policy for TemporalMark. The prior #56 `ReviewerMdsMetadataPolicyPreflight` accepts **untrusted model objects** and cannot prove JWS signing provenance.

## Deliberate isolated slice

1. Add a detached, **unwired** .NET 10 `ReviewerMdsJwsSignatureCandidateVerifier` and xUnit tests against **real RS256 signatures** generated by ephemeral test RSA keys and a test-only CA. Use the maintained `Microsoft.IdentityModel.JsonWebTokens.JsonWebTokenHandler` and `Microsoft.IdentityModel.Tokens` to verify signed JWS with the **leaf certificate key from protected `x5c[0]` only**; never use a raw JWT string as a trusted object. No homemade production signature algorithm. No fixed production FIDO roots, MDS network/metadata fetch, cached trust, API/SQL/CLI endpoints.
2. Pin a caller-injected, independently selected X.509 root for **test-only** path evaluation with `X509ChainTrustMode.CustomRootTrust`, `DisableCertificateDownloads=true`, `VerificationFlags=NoFlag`, SHA-256 fingerprint/root byte comparison, bounded depth, and exact certificate-path checks. Never fall back to host CA trust. Reject non-RS256 (this test-only fixture restricts algorithm/profile; production must cover actual official algorithms). Strict header allowlist `alg`, `typ`, `x5c`, `iat`, reject `x5u`/`jku`/`jwk`/`crit`, duplicates, untrusted additional chains, malformed/noncanonical JWT, bad or missing leaf, expired/not-yet-valid leaf, wrong root, signature or serial. Verify signing `iat` against a bounded test-supplied clock and parse only signed serial `no` as minimal evidence. No signature/header/certificate material appears in results.
3. **Explicit uncompromising release stop line:** X509Chain uses `RevocationMode.NoCheck` only to demonstrate **signature and path cryptography in isolation**; this is deliberately *insufficient* for any production trust. Every result is **`UNAPPROVED`**, labelled `JWS_CHAIN_ONLY_REVOCATION_UNVERIFIED`, and never returns parsed metadata entries/certs, signer grants, public key or ACTIVE credential. The caller-supplied test root can be attacker-controlled. **Even perfect positive tests do not establish FIDO MDS root trust or CRL evidence**. Do not connect to #56's model check or Fido2's registration verifier as a credential grant.
4. Versioned FIDO R46 and R3 cross-certificate production compatibility, CRL/OCSP for **all** signer-chain paths, pinned approved roots acquired via secure change control, expiration/distrust/revocation, airgapped trusted CRL distribution, immutable signed monotonic serial and status evidence, R46 transition before 2029-03-18, MDS `x5c` dynamics, and certificate-specific status remain **#57/#55**. CAB/security/DPIA approval is required before production trust. The narrow offline `x5c` test parser is **not** claimed fully interoperable with 2026 MDS R46 cross-certificate chains.
5. TDD mandatory: ADR before RED tests, RED GitHub CI expected failure without implementation, then GREEN, adversarial negative coverage and final exact-main four-job CI. Only #58 may close; parent #57/#55/#53 and #44/#50/#46/#38 stay OPEN. V015/V016 registrar SQL freeze, suspended CLI, no timestamp issuance, WORM or legal qualification change.

## Deployment and privacy

On-prem OSS and Azure compile the **same isolated code**, but this slice provisions neither production roots nor keys and has no network, storage or cryptographic enrollment side-effects. No attestation certificates, signing keys, JWTs or unique device identifiers must be logged in production. Until independent signed metadata/CRL revocation and audited root management exist, reject all attempts to elevate a candidate from `UNAPPROVED`.
