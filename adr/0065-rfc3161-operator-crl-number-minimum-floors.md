# ADR 0065 — Deployment-reviewed CRLNumber floors for every RFC3161 signing-issuer CRL

Status: Accepted, restricted delegated **pilot** control (2026-11-17). [#96](https://github.com/KeyserDSoze/TemporalMark/issues/96), child of open [#15](https://github.com/KeyserDSoze/TemporalMark/issues/15). **This does not establish independently witnessed historical CRL custody or qualified trust.**

## Reviewed background

Read ADR 0002, ADR [0052–0064](0064-rfc3161-intermediate-issuer-complete-crl-coverage.md), [TSA deployment runbook](../docs/TSA_HTTP_TRANSPORT.md), [threat model](../docs/THREAT_MODEL.md), [roadmap](../docs/ROADMAP.md), provider, API, `ExternalRfc3161IssuerCrlPolicy` full-DER ASN.1 decoder and disposable signed CRL tests. #94/#95 verify actual CMS signer PKIX chain and complete issuer-signed CRLs per **actual** issuer (direct root→signer or root→intermediate→signer), with `thisUpdate <= bounded signed genTime < nextUpdate`. Their CRL decoder already parses mandatory `2.5.29.20` `CRLNumber` but **discards its value**. A previously issued, still-current, correctly signed CRL with a lower number may be swapped into server configuration; the signature alone cannot show whether a newer CRL superseded it.

[RFC5280 §5.2.3](https://www.rfc-editor.org/rfc/rfc5280#section-5.2.3) establishes that CRLNumber is a **monotonically increasing per-issuer-and-scope sequence number**, mandatory and **noncritical** in conforming v2 CRLs, with values up to 20 octets that verifiers must handle. It does not offer a trusted monotonic state or prove that the latest CRL was obtained.

## Decisions

1. A configured external TSA requires **server-owned** `TimestampProvider:IssuerCrlNumberFloor`, a canonical **positive decimal** approved minimum root-issued full CRLNumber. If an operator-configured complete intermediate issuer CRL is present, require a **separate** `TimestampProvider:IntermediateIssuerCrlNumberFloor` for that issuer; if no intermediate CRL is present the second floor MUST be absent. An absent/malformed floor, ambiguous leading zeros/whitespace/sign, unsupported range above a 20-byte unsigned integer or mismatch in whether intermediate CRL and floor are provided fails **before outbound HTTP**. Empty/no TSA URL remains disabled without requirements. The operator must authenticate independently where each approved floor came from. No tenant-supplied CRL, floor, URL, ambient OS trust or cloud-only service is introduced.
2. The ASN.1 CRL decoder must preserve `CRLNumber` (up to 20 unsigned octets), require **noncritical** AKI and CRLNumber, and reject duplicates, negative values or non-conforming length. The checked value is taken from **authenticated signed TBSCertList**, not a response header or operator-provided numerator. The existing signature, AKI/SKI, issuer match, `CrlSign`, freshness, revoked serial and strict complete-only RSA SHA256 profile remain required.
3. Per-issuer path verification: for root→signer, the root-signed CRLNumber must be **>= approved root floor**. For root→intermediate→signer, root-signed CRLNumber must meet its own floor **when checking intermediate CA revocation**, and intermediate-signed CRLNumber must meet **its own independently approved floor** when checking signer leaf revocation. Never mix issuer floors. Equal number is accepted to allow repeated reads of the same reviewed CRL; a larger, correctly signed number is allowed with separate operator approval/updating the persistent floor.
4. The floor is a **deployment-managed static reference value**, not automatically monotonic across process restarts, tenant databases or rollback to old infrastructure state. A malicious actor who replaces **both** CRL bytes and floor, or who supplies a different signed CRL with an equal sequence number, can defeat this control. #15 and custody-related #17/#64 must still address **independently controlled monotonic signed witnesses, immutable CRL snapshot history**, historical EU Trusted List qualification, genuine QTSP interoperability, CRL scope/OCSP, UTC(k) and legal dossier #13. Never elevate `Unverified` pilot receipts based on this check.
5. Same code and operator-managed settings for **Azure and on-prem** (environment `TimestampProvider__IssuerCrlNumberFloor`, `TimestampProvider__IntermediateIssuerCrlNumberFloor`). Document operator rotation protocol: independently compare current CRLNumber against previously approved floor, **never reduce it**, audit approval, update CRL and floor atomically, and preserve independent historical evidence. Fail closed if a configured CRL is below the approved floor.
