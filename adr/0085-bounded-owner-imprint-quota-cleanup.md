# ADR 0085 — Owner-only bounded cleanup of idle imprint-search rate counters

Status: **Accepted only for scoped nonqualified [#118](https://github.com/KeyserDSoze/TemporalMark/issues/118)**, 2026-11-19. Parents [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) and [#113](https://github.com/KeyserDSoze/TemporalMark/issues/113) remain OPEN.

## Reviewed baseline

Reviewed [ADR 0004](0004-evidence-time-and-retention.md), [ADR 0005](0005-tenant-audit-mvp.md), [ADR 0082](0082-search-audit-and-abuse-controls.md), [ADR 0083](0083-postgres-atomic-imprint-search-rate-admission.md), docs/IMPRINT_SEARCH_RATE_LIMITING.md, docs/DATABASE_MIGRATIONS.md, docs/THREAT_MODEL.md, original V019 and `ImprintSearchRatePostgresTests`, current PostgreSQL migration-runner and restricted runtime/provisioner/approver roles, four-core-job Docker CI and real signed-Keycloak two-tenant HTTP smoke.

The V019 quota tables contain exact authenticated tenant UUID and OIDC `sub` (personal behavioral metadata), UTC counter window and count. V019 only opportunistically removes 32 stale principal and 16 tenant rows on **another valid lookup**; if a tenant becomes inactive its rows can persist indefinitely. This conflicts with data minimization as a *technical* risk but does not establish an approved retention policy. Timestamp-evidence preservation to a user-selected indefinite horizon is a distinct data purpose and must **not** automatically govern these short-lived quota keys. The schema owner already has unconstrained DML; expose a narrow, bounded path which makes safe manual deletion reproducible without returning subject IDs.

PostgreSQL 17 documents [SELECT FOR UPDATE SKIP LOCKED](https://www.postgresql.org/docs/17/sql-select.html) and [CREATE FUNCTION / SECURITY INVOKER / EXECUTE privileges](https://www.postgresql.org/docs/17/sql-createfunction.html). No production GDPR/DPIA determination is made here.

## Decision and isolation boundary

1. Add immutable **forward-only V020**, leave V001–V019 checksums intact. Install `public.purge_stale_imprint_search_rate_counters(integer)` with default **SECURITY INVOKER**, explicitly `SET search_path=pg_catalog,pg_temp`, qualified table references, and `REVOKE ALL ... FROM PUBLIC` and API/provisioner/approver/credential-registrar groups. **Only the separately controlled migration/schema owner** can execute in the pilot; runtime cannot execute or directly inspect the rate tables. Never expose a public HTTP endpoint or grant public/admin API execution.
2. Require batch size **1..500** (no NULL/default-infinite). Each call chooses UTC bucket from PostgreSQL `clock_timestamp()`, deletes independently at most that many stale principal and tenant counter rows whose `window_start < current_bucket_start - interval '3 minutes'`. Use CTE `SELECT ... ORDER BY window_start FOR UPDATE SKIP LOCKED LIMIT p_batch` then `DELETE ... USING` and collect `ROW_COUNT`. Locked/active rows are skipped. Do not modify receipts, organizations, tenant audit, V019 active SQL function, role memberships, PostgreSQL schema history or WebAuthn V015/V016 constraints.
3. Return only two aggregate counts `principal_deleted` and `tenant_deleted`; no `sub`, organization UUID, document imprint, query result, JWT, period of a specific actor or row details. Treat even counts as operational telemetry requiring minimization. Batch size is fixed by approved operator invocation, not client or end-user input. Repeated invocations permit manual draining of stale rows; absence of a scheduler means **no automated TTL guarantee**.
4. Keep active quota state safe under concurrency with V019's transaction-row locks: rows past cutoff only; `SKIP LOCKED` avoids blocking the shared PostgreSQL primary. A concurrent V019 lookup may retain a locked row for a future pass. A DB clock rollback must not make newer/future rows eligible. SQL permissions/credential changes and backups must follow existing deployment change control. One shared writable PostgreSQL primary is still required for distributed rate enforcement; manual cleanup is not a second primary.
5. No scheduled job, unapproved retention SLA, legal storage policy, GDPR erasure/legal hold, archived/backed-up copy purge, cross-tenant privacy export, Azure automation, production log or CAB approval is claimed. #115/#113 stay OPEN until independent privacy review and production cadence/monitoring/recovery and edge ingress logs are verified; #17/#15/#13 remain legal/trust blockers. All pilot evidence remains `Unverified`.
