# ADR 0044 — Committed npm v10 lockfiles and frozen clean installs for the PWA and browser test suite

Status: **accepted for reproducible npm dependency resolution only**, 2026-11-16. [#75](https://github.com/KeyserDSoze/TemporalMark/issues/75), child of open [#20](https://github.com/KeyserDSoze/TemporalMark/issues/20). Reviewed ADR 0001, 0040, 0043, the CI action SHA policy, src/frontend/Dockerfile, tests/frontend package metadata, `docs/ROADMAP.md`, `docs/THREAT_MODEL.md` and `docs/CI_ACTION_PINNING.md`. Source: [npm ci](https://docs.npmjs.com/cli/v10/commands/npm-ci), [npm package-lock.json](https://docs.npmjs.com/cli/v10/configuring-npm/package-lock-json).

## Problem

Top-level package.json pins exact versions for the React PWA and Playwright runner but does not pin **transitive** dependencies or their registry tarball integrities. The GitHub CI and Docker frontend image currently use `npm install`; the identical TemporalMark main SHA could install different transitive packages at different times, undermining CAB test evidence and repeatability for the PWA navigation security and Keycloak MFA checks. Pinning GitHub Action source commits in ADR 0043 does not fix this dependency tree drift.

## Decision

1. Commit separately generated **npm v10 lockfileVersion 3** `src/frontend/package-lock.json` and `tests/frontend/package-lock.json`. Use Node 22/npm 10 and `npm install --package-lock-only --ignore-scripts --no-audit --no-fund` to obtain actual registry-resolved transitive package versions and `integrity` SHA values, without inventing registry metadata. The constrained environment has no local registry DNS: the temporary GitHub Actions runner's existing npm registry connection will generate the canonical files, printing only public package-lock base64 between explicit markers in its ephemeral CI logs for reviewed exact-byte retrieval. No tokens/credentials or secret files are emitted; remove this temporary bootstrap step in the GREEN commit. GitHub token permission stays `contents: read`.
2. **RED first:** dependency-free Python policy and tests, run in the backend CI job before any build. For BOTH projects require committed lockfileVersion 3, exact root name/version/dependency sets matching the manifest and non-empty package tree, and for every registry package a fixed version with `https://registry.npmjs.org/` resolved tarball and `sha512-` or `sha1-` integrity. Explicit tests for missing lock, manifest drift and tampered/missing integrity. The RED CI must demonstrate absence of committed lockfiles, not an unrelated setup error.
3. **GREEN**: commit actual lockfile bytes, replace all `npm install` in CI and `src/frontend/Dockerfile` with `npm ci --no-audit --no-fund`. Copy both web `package.json` and `package-lock.json` **before** Docker's `npm ci`; perform the existing PWA build as before. Keep Playwright browsers installed under the exact test runner lock, do not remove any current end-to-end tests. Generate and commit both lockfiles so setup-node's npm 10 and Docker node:22-alpine npm agree. Keep use of `npm ci` against a mismatched manifest fail-closed (never auto-update the lock).
4. Run all four CI jobs on the **exact final main SHA** and inspect actual PostgreSQL witness full logical restore, PWA worker and real Keycloak MFA/PKCE tests. Only close #75 after verified evidence; keep parent #20 open for Docker image digests, GitHub runner pinning, SBOM/SAST, attestations, cross-tenant API and mobile PWA install coverage. #64/#61/#57 and reviewer V015/V016 freeze unchanged.

## Remaining risks

A committed integrity-bearing npm lockfile and `npm ci` increase dependency-resolution consistency, but do **not** guarantee bit-for-bit builds, safe packages or immutable upstream registry availability. Node 22 tag, nginx tag, Ubuntu runners, OS package managers, Playwright-managed Chromium, native install scripts and transitive postinstall network fetches remain mutable. Lockfile creation uses registry metadata at one point in time and must be reviewed for changed package versions and vulnerabilities; future changes require fresh `npm ci` on CI. No SBOM, SLSA provenance, signed release, WORM/eIDAS/QTSP qualification, trusted FIDO MDS R46 root or independent monotonically signed high-water witness is claimed.

The RED test and lockfile seed are *test infrastructure*, never application-issued timestamp marks or elevated authorization.
