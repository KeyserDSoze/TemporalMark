The exact final docs-inclusive [`7a33492`](https://github.com/KeyserDSoze/TemporalMark/commit/7a334924ac186c20a676804b6593da3c1ba8f141) [Actions 45053014805](https://github.com/KeyserDSoze/TemporalMark/actions/runs/45053014805/attempts/1) had all 4 core jobs green, 34 Python offline tests, 284 Business, real PostgreSQL17 247, SQL checksums 20, A/B two-tenant signed Keycloak tests and real API ZIP smoke. #166 is closed on that exact SHA.

The real two-tenant API smoke already obtains the **actual current .NET ZIP bytes** through the authenticated `GET /api/v1/stamps/export` for A/B tenant isolation and spoofed organization headers/query. It uses Python's permissive `zipfile.ZipFile` and checks manifest/TSR/tenant; **it does not call the stricter standalone offline v1 verifier**. Separately the offline v1 unit tests construct Python ZIP fixtures; therefore the real .NET producer might silently regress to a structurally ambiguous/unsupported ZIP (e.g., internal unused bytes) without failing the existing integration test, even if all offline unit tests still pass. This is a **missing cross-language CI assertion**, not demonstrated unauthorized timestamp issuance or a signed-token attack.

The strict verifier reports internal local ZIP layout, SHA256 and v1 metadata consistency only. Python `ZipFile.read()` intentionally permits certain unexpected ZIP layouts, demonstrated with bounded synthetic fixtures in ADR 0123. No privileged database data leaves disposable CI.

## Decision, incremental TDD on main

1. Commit this ADR **first**. Add a Python stdlib unittest **before smoke implementation**. Load the actual `api-tenant-isolation.py` module from the repo, stub only its HTTP `api()` response (no network, credentials or SQL) with one valid v1 ZIP and one **stock zipfile-readable** ZIP containing an opaque internal byte gap. The valid ZIP must pass and return expected manifest and TSR bytes; the corrupt-format ZIP must be denied with a generic non-sensitive `AssertionError`, rather than accepted and returned. This tests the *actual API smoke export path*, not a mock verifier implementation. Wire the test to the existing `backend` job in `.github/workflows/ci.yml`, and verify **genuine GitHub RED** due solely to the absent strict verifier bridge (no import/syntax/bad fixture). Do not modify `api-tenant-isolation.py` until RED is confirmed.
2. After RED, in the existing `export(token,extra,headers)` wrapper, before generic ZIP parsing, call `verify_period_export.verify_archive(io.BytesIO(raw))` directly on the **same raw ZIP bytes** received from actual HTTP API. If rejected, raise a short **generic test assertion**, no exception cause/private URI/body/token/tenant/path; never write ZIP bytes to disk, logs or CI artifacts. Compare verifier's receipt count to the later parsed `manifest["count"]` for this source of truth. Since `check_authorized` exercises A/B and spoofed headers/query through the same wrapper, every real API export is covered by the independent checker. Keep all existing API permissions, tenant counts, raw TSR equality and signed Keycloak 401/403 checks intact.
3. Update ADR, runbook, threat model, roadmap. Close **only #167** when the *final documentation-inclusive* exact `main` SHA verifies GitHub backend/frontend/terraform/docker-smoke **4/4 success**, ci-verdict+combined success; Python offline 34/34 and bridge tests; .NET Domain/Business/Provisioner; real PG17 247/247, checksum V001–V020, test-only pg_dump/pg_restore, A/B signed Keycloak API ZIP + spoof and Nginx 413/414/429. If not, leave OPEN.

## Qualification and limits

This builds a **positive real producer-to-offline-checker interoperability gate** and a negative test that the CI wrapper cannot silently accept opaque bytes. It is not a production validator, RFC3161/CMS signer/certificate/nonce/revocation check, historical QTSP/EUTL validation, independently signed WORM custody, proof that all period records were included, or legal eIDAS service qualification. The synthetic CI DER bytes are explicitly **not** genuine qualified TSA evidence. No dependency, ASP.NET API, SQL schema, auth, frontend, OSS or Azure production runtime is changed. Parents #17/#15/#13/#61/#64/#18/#38/#50 stay OPEN.
