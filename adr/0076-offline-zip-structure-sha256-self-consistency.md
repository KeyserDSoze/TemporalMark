# ADR 0076 — Bounded offline structural and hash consistency check for v1 export ZIP

Status: Accepted for **non-authorizing pilot evidence inspection only**, 2026-11-18. Focused [#107](https://github.com/KeyserDSoze/TemporalMark/issues/107) under open evidence parent #17; delegated TSA #15 and legal CAB/AgID #13 remain OPEN.

## Reviewed baseline

Reviewed ADR [0004](0004-evidence-time-and-retention.md), [0074](0074-registry-page-export-integrity-and-unique-ids.md), [0075](0075-synchronous-evidence-zip-byte-budget.md); `TimestampRegistryService.ExportZipAsync` and real `TimestampRecord` schema, `PostgresTimestampRegistry`, `TimestampRegistryServiceTests`; `docs/REGISTRY_INTEGRITY_READ_GATES.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md`, `docs/COMPLIANCE.md`, and pinned `.github/workflows/ci.yml` stdlib Python checks. An exported `temporalmark-period-export-v1` ZIP contains `manifest.json` with `format`, `organizationId`, `fromUtc`, `toUtcExclusive`, `exportedAtUtc`, `count`, `entries`; each entry includes `Id`, `IssuedUtc`, `HashAlgorithmOid`, `DigestBase64`, `PolicyOid`, `ProviderId`, `TokenSha256Hex`, `validationState`, `EvidenceReference`, `responseFile` and raw `tokens/{id:N}.tsr`. While application service prevalidates local DER/SHA and unique ID for that batch, a copied/transferred ZIP currently has no offline *structure-and-hash-only* verifier independent of a live DB.

Authoritative Python [`zipfile`](https://docs.python.org/3/library/zipfile.html) permits accessing ZIP member metadata and notes duplicates require explicit care; Python [`json.object_pairs_hook`](https://docs.python.org/3/library/json.html) permits rejecting duplicate JSON object keys. The tool never extracts ZIP paths, follows embedded paths or trusts archive names as filesystem paths.

## Decision and scope

1. Create a **Python 3 standard-library-only** offline CLI `tests/integration/verify_period_export.py <path.zip>`. It must accept current `temporalmark-period-export-v1` archives and report only **local file/manifest internal structural and SHA-256 consistency**, never `verified qualified`, `timestamp validated`, `signed export` or `WORM preserved`. Error exit is nonzero and generic; no raw DER, imprint, credential, path, hash or tenant ID is echoed to stdout/stderr.
2. Reject malformed ZIP, duplicate/extra/missing archive members, encrypted members, symlinks, directory entries, ambiguous/traversal names, non-v1/duplicate-key/malformed/oversized JSON manifest, bad type/count/unique ID/path mapping, wrong period membership, non-UTC times, unsupported SHA-256 algorithm, noncanonical digest Base64, mismatched declared DER SHA-256 and current pilot **non-`Unverified`** state. No output can authorize a qualified timestamp; later real verification requires separate reviewed schemas and trusted-issuer evidence.
3. Use strictly bounded reads: max **8 MiB** uncompressed `manifest.json`, max **1 MiB** each TSR member, max **64 MiB** aggregate TSR content, max **10,000** rows + exactly one manifest, and max **80 MiB** raw archive file. Check ZIP announced sizes first **and** cap actual decompression reads. An archive's declared sizes/CRC are untrusted parser inputs. The Python code has no network, no extraction and no external packages.
4. Preserve UTC inclusive-from/exclusive-to using .NET DateTimeOffset's **up to seven fractional-second digits (100 ns ticks)**, not lossy float comparisons or implicit timezone conversion. Require real explicit UTC representations `+00:00` or `Z`. UUIDs and paths must correspond exactly to `tokens/{id:N}.tsr`.
5. **TDD:** ADR before tests; RED-first deterministic stdlib unit cases for valid/negative ZIPs, then mandatory test invocation in existing backend source gate; minimal implementation and operator docs. Actual GitHub RED and exact latest docs-inclusive `main` four-job GREEN, plus source/test review required before closing #107.

## Limits

An attacker able to edit **both** manifest and DER files can produce a self-consistent fake archive. This utility cannot authenticate the manifest or determine whether any token was issued by an approved (much less qualified) QTSP, whether all records for a period were exported, whether a CMS signature/nonce/issuer/CRL/UTC(k) is valid, whether the original PostgreSQL state was rolled back, or whether the archive was stored immutably under GDPR-approved legal hold. It is **not** a standalone RFC3161 validator, trusted preservation system, signed custody witness, legal qualification/CAB assessment, or complete-period proof; gaps remain under #17/#15/#13. It does not interact with WebAuthn or relax the V015/V016 registrar stop-line. Works identically for Azure/on-prem export files.
