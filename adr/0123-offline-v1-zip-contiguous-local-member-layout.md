# ADR 0123 — Require contiguous local member layout in offline v1 ZIP exports

Status: **Accepted for scoped offline non-authorizing TDD [#165](https://github.com/KeyserDSoze/TemporalMark/issues/165)**, 2026-11-22 Europe/Rome. Parent #17 immutable WORM/complete period export, #15 delegated QTSP/CMS, #13 eIDAS/CAB, #61/#64 independent custody, #18 production remain OPEN.

## Revisited design and actual baseline

Reviewed [ADR 0004](0004-evidence-time-and-retention.md), [0076](0076-offline-zip-structure-sha256-self-consistency.md), [0077](0077-zip-compression-unix-special-file-gates.md), [0078](0078-zip-local-central-header-method-flag-binding.md), [0120](0120-offline-period-zip-strict-envelope.md), [0121](0121-pilot-registry-unsupported-validation-state-read-gate.md), [0122](0122-offline-v1-local-crc-and-size-directory-binding.md), actual `tests/integration/verify_period_export.py` and its Python stdlib unit tests, `TimestampRegistryService.ExportZipAsync` using .NET `ZipArchive` over seekable `MemoryStream`, `docs/OFFLINE_PERIOD_EXPORT_VERIFIER.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md` and the pinned four-job GitHub CI. [#164](https://github.com/KeyserDSoze/TemporalMark/issues/164) has a verified green 32/32 Python suite and 4/4 jobs on [`52b789e`](https://github.com/KeyserDSoze/TemporalMark/commit/52b789e6a7976850c8b921e9c1a780f42888e405), [Actions 45005222698](https://github.com/KeyserDSoze/TemporalMark/actions/runs/45005222698).

The offline checker accepts a ZIP whose **outer** classic EOCD is at EOF and declares a central-directory offset/size that exactly reaches EOF, and whose *individual* local header flags, method, CRC32 and lengths match central metadata. It does **not** check the interval **between the end of each declared local compressed data region and the start of the next local member or the central directory**. Python's `zipfile` allows opaque bytes inserted between intact members or before the central directory when EOCD central offset and any moved local member offsets are consistently updated. In a small independent synthetic Python fixture, `ZipFile.read` still returned both original member bytes after insertion. This is an ambiguity in local structural inspection, not an assertion of an actual attack or a forged timestamp/signature; the manifest is unsigned.

References: [Python zipfile](https://docs.python.org/3/library/zipfile.html), [PKWARE ZIP APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT), [.NET ZipArchiveEntry](https://source.dot.net/System.IO.Compression/System/IO/Compression/ZipArchiveEntry.cs.html).

## Decision — ADR first, genuine RED before source

1. Commit this ADR alone on `main`. Then commit **only tests**: generate intact v1 `build_zip()` one-receipt and zero-receipt fixtures, insert an arbitrary non-ZIP opaque overlay (a) between the manifest and TSR, (b) after the TSR before central directory, (c) in the empty-period archive after its manifest. Patch EOCD central offset by inserted byte count; patch central-directory local-header offsets for any local members shifted by the insertion. **Do not change** member compressed data, central CRC/size fields, JSON, DER or local/central method/flags. Independently `zipfile.ZipFile.read` all original members successfully. Demand `ExportVerificationError` from verifier, CLI nonzero and no tenant/path/private overlay leak; valid one/zero-record ZIP positives continue. Prove genuine GitHub Actions RED from *missing denial*, not invalid test fixtures, before implementing source.
2. Only after RED, bind all **declared physical intervals** before any manifest or TSR is decompressed: for each local member (order by numerical central-directory `ZipInfo.header_offset`), calculate `local_start = header_offset`, `data_start = local_start + 30 + local_filename_length + local_extra_length` from the existing fixed 30-byte local header, and `data_end = data_start + info.compress_size`. Require each `data_end` equals the following `local_start` and final `data_end` equals the separately checked conventional EOCD `central_offset`. First `local_start` must equal zero, gaps, overlaps and shifted unclaimed bytes must be denied before decompression. Existing ADR 0122 forbids data descriptors (bit 3), so no trailing descriptor region is accepted in current seekable v1.
3. Constrain calculations to existing max 80 MiB outer ZIP and 10,001 total members, and require each end never exceeds verified central offset; no archive member extraction, new per-member data I/O, network or third-party library. Use current generic `ExportVerificationError` and redacted CLI. Preserve ADR 0076/0077/0078/0120/0122 metadata, ZIP type, SHA256/DER, canonical Base64, UTC100ns, `Unverified`, 1 MiB/TSR, 64 MiB total DER, 8 MiB manifest, no extra members. This is an intentionally strict current **seekable .NET v1 profile**; approve any streaming/new-layout format through new ADR/interoperability fixture rather than silently changing current acceptance.
4. Update ADR, operator runbook, threat model and roadmap. Close **only #165** on independently verified final docs-inclusive `main` SHA GitHub CI backend/frontend/terraform/docker-smoke **4/4**, ci-verdict/combined success, actual Python test count, real .NET+Postgres17/Keycloak/restore/ingress regressions. Do not infer success from commits.

## Security/legal stop line

This purely structural ZIP layout rule cannot authenticate a jointly rewritten unsigned manifest/TSR, prove all period records were included, verify RFC3161 CMS/certificates/nonce/revocation/historical EUTL service state, create a legally retained WORM copy or independent high-water signed witness, or grant QTSP/CAB qualification. #17/#15/#13/#61/#64/#18/#38/#50 remain OPEN; the pilot remains `Unverified` and Azure/on-prem application behavior is unchanged.
