# ADR 0081 — Bounded tenant-only exact document SHA-256 imprint search

Status: Accepted for **unqualified pilot evidence lookup only**, 2026-11-18. Focused [#112](https://github.com/KeyserDSoze/TemporalMark/issues/112), child of #14 and related to #17/#15/#13. All those parents remain open.

## Baseline reviewed

Reviewed ADR [0004](0004-evidence-time-and-retention.md), [0072](0072-canonical-sha256-base64-issuance-ingress.md), [0074](0074-registry-page-export-integrity-and-unique-ids.md), [0079](0079-tenant-utc-daily-dashboard-counts.md) and [0080](0080-admin-tenant-registry-pagination-and-stale-request-gate.md), `TimestampRecord`, `ITimestampRegistry`, `PostgresTimestampRegistry`, `TimestampRegistryService`, signed-OIDC `TenantAdminAsync` API, real two-tenant signed-Keycloak/PostgreSQL HTTP CI and existing React IT/EN dashboard/browser tests, `docs/REGISTRY_PAGINATION_UI.md`, `docs/COMPLIANCE.md`, ROADMAP and THREAT_MODEL. Evidence currently stores `hash_algorithm_oid` and `digest_base64`: this is the **document's RFC3161 SHA-256 message imprint**, not the `token_sha256_hex` of the DER timestamp receipt. No exact document-imprint lookup route exists. Documents themselves never transit the API or persist in TemporalMark.

## Decision

1. Provide a read-only, tenant-admin-only **`POST /api/v1/stamps/search`** accepting a JSON body `{fromUtc,toUtcExclusive,digestSha256Hex,offset,limit}`. Use **POST rather than URL query** to keep potentially sensitive document fingerprints out of ordinary proxy URL/history/access logs. Do not echo the raw digest in success/error logs, link filenames or headers. Empty/invalid hex and malformed JSON -> generic HTTP 400. This is **not** a signed or qualified verification request, a mutation, or an RFC3161 nonce lookup.
2. The only accepted search key is exactly **64 ASCII SHA-256 hexadecimal digits**, upper/lowercase allowed and canonicalized to the 32-byte value then `Convert.ToBase64String` (44-character canonical padded Base64) for indexed storage comparison. Reject whitespace, prefixes, URL Base64, overlong strings and nonhex **before any DB call**. Max **50 entries per page**, offset >= 0; load at most **51** rows for a one-element `hasMore` lookahead. Caller may select UTC period but must never supply the tenant; the server derives `organizationId` from the validated signed JWT and active SQL tenant-admin membership, exactly as for `GET /stamps`.
3. PostgreSQL query uses bound parameters `WHERE organization_id = @org AND issued_utc >= @start AND issued_utc < @end AND hash_algorithm_oid = @sha256Oid AND digest_base64 = @digestBase64`, `ORDER BY issued_utc,id LIMIT @limit OFFSET @offset`. The business service revalidates **tenant, half-open period, SHA-256 algorithm and normalized imprint plus retained DER/SHA-256 and unique IDs** for all returned items *before* producing search metadata. If any repository result violates them, fail closed; do not partially return records. No raw `ResponseDer` in JSON. Preserve the existing audited raw TSR download route.
4. Return `{items: [{id, issuedUtc, digestBase64, providerId, validationState, ...safe metadata}], hasMore: bool}`; no separate unbounded count scan. Results capped at 50 and pages navigable via offset. **Offset search is not a snapshot:** inserts/deletes can shift records across pages. UI uses a distinct IT/EN hex search field/submit with separate Next/Previous and receipt download, and guards against stale search results on changed period or token. No new client libraries, cloud dependency, SQL migration, identity privilege or trial-and-error search over all tenants.
5. TDD: commit ADR **before any test/code**. RED-first Business xUnit positive, uppercase/lowercase canonical normalization, lookahead, malformed input/zero tenant/bounds and malicious return; real signed-Keycloak/Pg two-tenant HTTP 401/403/400 + positive/foreign digest/spoofing; genuine browser OIDC checks followed by synthetic search view fixture (UI-only mock; never claim it proves DB isolation). Minimal implementation then README, operator guide, security/roadmap/issue. Close only on verified **exact last documentation-inclusive main SHA** `temporalmark/ci-4-core-jobs=success` with four job records, Python/.NET/browser/real two-tenant HTTP results.

## Residual risk / regulatory stop line

Search discloses whether a requested document imprint is present **to an already authorized tenant administrator**. The imprint is sensitive metadata; access control, least privilege, rate limiting and admin action logging warrant further review; no mechanism here establishes issuer identity, signed custody, WORM, historical qualified QTSP status, CAB/AgID certification, exact issuance reconciliation or proof that matching documents are equal/legally authenticated. Hash collisions are cryptographically unlikely but exact digest equality is not document delivery or timestamp signature validation. `Unverified` records remain unverified; WebAuthn V015/V016 registrar stop line unchanged. Parents #14/#17/#15/#13/#20 stay open.
