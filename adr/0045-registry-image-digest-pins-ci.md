# ADR 0045 — Pin disposable CI Docker images to registry-resolved digests

Status: **accepted only for deterministic container image selection in CI/dev**, 2026-11-16. Scoped issue [#76](https://github.com/KeyserDSoze/TemporalMark/issues/76) is child of open [#20](https://github.com/KeyserDSoze/TemporalMark/issues/20). Reviewed ADR 0001 (dev is not production), ADR 0043 (SHA-pinned GitHub Actions) and ADR 0044 (npm v10 lockfiles); `docker/compose.yml`, both application Dockerfiles, `docs/ROADMAP.md`, `docs/THREAT_MODEL.md` and `docs/NPM_LOCKED_INSTALLS.md`. Technical source: [Docker buildx imagetools inspect](https://docs.docker.com/reference/cli/docker/buildx/imagetools/inspect) and [pin base image versions](https://docs.docker.com/build/building/best-practices/#pin-base-image-versions).

## Problem

Even with immutable workflow action sources and npm lockfile integrity, local/Docker CI uses floating base and sidecar image tags. Today's `postgres:17.6-alpine` on three Compose services, Keycloak 26.4.0, Node 22 Alpine, nginx 1.27 Alpine, and .NET SDK and ASP.NET runtime 10.0 tags can resolve to different manifests for the **same** TemporalMark repository SHA. The witness restore/audit and MFA tests are sensitive to runtime drift; replayability requires documenting exact bytes of the external container manifests, not trusting tag names alone.

## Decision

1. Introduce a dependency-free Python policy `tests/integration/check_container_image_pins.py` covering **all** application Dockerfiles and `docker/compose*.yml|*.yaml`, with Python unit regressions and an enforced backend CI step. Each external `FROM` and Compose `image:` line must have a complete lowercase `@sha256:<64 hex>` digest and an explicit human-readable version tag. A locally defined Dockerfile build stage alias is allowed as a FROM source only after its own pinned external FROM. Fail closed for tag-only, truncated or uppercase digest, expansion/variable/interpolation, unpinned docker URI, malformed source, or missing files. This source test is not a full Dockerfile/YAML interpreter; it deliberately covers the versioned CI/dev sources only.
2. ADR precedes RED tests. First insert the backend policy test while the current images remain floating. The backend job must fail **specifically on the six unique images/eight occurrences** after all policy unit regressions pass. In the independent frontend job, an **ephemeral seed** queries Docker registry manifests with `docker buildx imagetools inspect`, prints **only** six public image tag-to-manifest digest lines, never tokens or registry secrets; remove that bootstrap step immediately after acquiring and verifying digests.
3. GREEN replaces **all** eight image usages with the digest-resolved tag references. The selected SHA is the multi-architecture OCI manifest/index digest returned by the registry, *not an invented per-architecture content hash*. Docker engine still selects its supported platform from that pinned manifest index. Keep `dotnet 10`, PostgreSQL 17.6 and Keycloak 26.4.0 logical versions unchanged; no production API, SQL privileges, Azure service or credential registration workflow changes. Every prospective digest update requires documented upstream tag/version/digest provenance and fresh four-job GitHub Actions CI, including real full PostgreSQL backup/restore, PWA navigation and MFA/PKCE tests on exact final main SHA.
4. Update `docs/`, `docs/ROADMAP.md` and `docs/THREAT_MODEL.md`, and close only #76 when final exact-head CI is complete and GREEN. Parent #20 remains open for pinned runner/toolchain artifact provenance, SAST/SBOM/SCA, signing/attestations, mobile install and true tenant-isolation tests. #64/#61/#57/#17 and V015/V016 frozen registrar issuance are unaffected.

## Risk and limitations

A digest proves selection of a particular registry image manifest but neither the publisher's identity nor image safety. A pinned image can contain known vulnerabilities; the image index may contain different architectures, nested attestations or code run dynamically at build/start. A compromised registry, build tool or runner, transient package downloads, missing/garbage-collected manifests, mutable OS packages, and runner/Playwright Chromium versions remain external dependencies. This change does **not** add signature validation (cosign/Notation), verified SBOM, independent WORM custody, HSM/CAB operations, UTC(k), FIDO Alliance R46 validation or eIDAS qualified status. The Compose stack explicitly remains **disposable development/test**, not production parity or an accredited timestamping system.
