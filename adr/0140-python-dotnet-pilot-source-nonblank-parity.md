## Problem evidenced independently of trust/qualification

The strict unqualified v1 offline ZIP checker refuses `PolicyOid` and `ProviderId` that are only whitespace according to **Python `str.strip()`** (`bool(value.strip())`). Python considers U+001C, U+001D, U+001E and U+001F separator controls whitespace (locally verified with `isspace()`), while **.NET `string.IsNullOrWhiteSpace`** / `char.IsWhiteSpace` does not. See [Python str.isspace official docs](https://docs.python.org/3/library/stdtypes.html#str.isspace) and [Microsoft Char.IsWhiteSpace reference](https://learn.microsoft.com/en-us/dotnet/api/system.char.iswhitespace?view=net-10.0). This **can permit** (a) an app-owned new alternate provider receipt to be marked created even though its generated ZIP will fail the project's checker; (b) a direct new SQL-app writer with C0-only source identities; and (c) a legacy owner-inserted `Unverified` row to be listed, searched, downloaded or archived, despite local DER SHA256, tenant, UTC and other existing read gates. Not a known production incident. For ordinary blank values, ADR 0139 already guards `PolicyOid`, and Domain already guards `ProviderId`; **this mismatch concerns only the four extra Python whitespace characters**.

## Decision: narrow parity without normalizing source

1. **ADR first, then true source-missing test RED.** Commit this decision before tests or source. For real disposable PostgreSQL17, use only test-owner SQL authority to insert otherwise original DER/SHA256-consistent own-tenant UTC `Unverified` V001 historical rows (canonical document SHA256 imprint, nonblank counterpart source field) whose `PolicyOid` **or** `ProviderId` consists of each U+001C–U+001F and mixed Unicode/ordinary whitespace containing C0. Assert `TimestampRecord.Validate` and direct repository projection succeed before testing the independent authorized Page, Search (including limit+1 lookahead), Receipt and ZIP read gates. Assert source field is unchanged after fail-closed and foreign results remain not-found/empty. Test the direct app PostgreSQL writer independently denies **new** rows with C0-only source metadata before SQL INSERT, with original schema and privileges untouched. Independently confirm **real executed missing-denial RED** in PG17 CI, not build failures.
2. Independent Business fake-provider and fake-repository xUnit **test-only RED**: `IssueAsync` calls upstream exactly once then refuses C0-only policy/provider with fixed sanitized provider-response failure before persistence (no TSA retry); read Page/Search/Receipt/ZIP including Search lookahead refuses C0-only historical metadata with generic sanitized fixed policy/provider denial, no tenant or raw metadata; leave 16KiB nonblank original values, ordinary whitespace rules and cross-tenant isolation intact. Observe compiled xUnit RED separately before production source.
3. Add standalone Python v1 ZIP regression cases showing the checker **already refuses** the C0-only/mixed-only original policy/provider metadata, while preserving a real printable policy/provider plus an embedded C0 control. These tests prove the intended parity without loosening the offline verifier and may pass in test-only RED runs.
4. **Only after independently observed PG17 and Business RED**, implement one pure, bounded source-text **pilot nonblank helper** in Business: classify a character as blank exactly if `char.IsWhiteSpace(c)` **or** it falls inclusively in U+001C–U+001F, and require at least one **other** character. Reuse for original `PolicyOid` and `ProviderId` new provider and writer admission, preserving existing original UTF8 16KiB field budget, DER and source text; on historical reads use same helper in existing `RequirePilotNonblankPolicy` and a new source-identity check for `ProviderId` after all tenant/ID/period, pre-wire field/DER/reference budgets, Domain DER SHA, Unverified and canonical SHA256 document-imprint checks and before any metadata/receipt/ZIP or `HasMore` is returned. No untrusted raw data in generic errors. Original SQL rows are not rewritten.
5. Record real RED/GREEN SHAs, CI runs and exact result counts in this ADR, registry/offline-verifier/compliance/threat/roadmap docs and issue. Close **only #182** if independently verified final **docs-inclusive main SHA** has four GitHub core jobs + separate ci-verdict/combined success, actual Business/PG17, offline strict ZIP, 20 V001–V020/full restore, signed Keycloak two-tenant and Nginx 413/414/429 privacy evidence. ## Explicitly rejected changes and limitations

- **Trim/sanitize/rewrite source field** to force ZIP parity: rejected, destroys original historic provenance or changes source identifiers; deny instead.
- **Reject C0 controls anywhere** even when a visible nonblank identifier remains: not part of the current v1 offline specification; avoid unnecessarily changing source metadata accepted by the already deployed checker. Enforce *at least one* nonblank character under the union of the two whitespace definitions, not a general textual character allowlist.
- **Claim string checks validate ASN.1 OID or CMS signer:** false. This is nonblank metadata only, not `TSTInfo.policy`/document `messageImprint` signature binding, qualified signer cert/CRL/EU Trusted List, timestamp UTC(k), WORM/signed evidence, indefinite-retention legality, audit qualification or independent CAB/AgID certification.
- **Unscoped SQL constraints or altering V001–V020:** rejected; historical data remains available for forensic review with authorized response fail-closed. Normal future algorithms or alternate evidence profiles demand separate ADR and tests.
