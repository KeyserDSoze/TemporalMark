# ADR 0118 — Fail closed on any unforeseen runtime SQL access to public PostgreSQL relations and sequences

Status: **Accepted for scoped TDD authorization hardening [#153](https://github.com/KeyserDSoze/TemporalMark/issues/153)**, 2026-11-21. Parent #128/#18 real Azure Entra SQL/CAB, #14 tenancy, #38/#50 independently signed WebAuthn reviewer/registrar, #64/#61 evidence witness, #17 WORM and #13/#15 eIDAS/QTSP **remain OPEN**. No SQL owner grant, Azure apply, production role migration or certification.

## Reviewed sources and architecture

Consulted existing accepted ADR 0099/0100/0114/0115/0116/0117, `docs/POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md`, `docs/API_POSTGRES_ENTRA_PRELISTEN_CANDIDATE.md`, `docs/OPERATOR_PROVISIONING.md`, `docs/DATABASE_MIGRATIONS.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md`, current `PostgresRuntimePrivilegePreflight.cs` and real PG17 disposable LOGIN xUnit fixture. Inspected `scripts/migrations/V004__provisioning_privileges.sql` and V006, and `scripts/apply-migrations.sh`. V004 `public.organization_provisioning_events` stores operator/first-admin identity, original token hash proofs and approval request links; its trigger provides append-only-by-policy but not WORM. The migration runner creates `public.schema_migrations` (20 V001–V020 SHA256 checksums and version ledger) under migration-owner control. Neither object is in previous explicit API prelisten deny list. Moreover, new future public tables, views or sequences could be accidentally GRANTed outside the historic static object list even though the explicit Production Entra API startup identity appears least-privileged. We have **no evidence** a real deployed Azure login has such misgrants.

Official [PostgreSQL 17 pg_class](https://www.postgresql.org/docs/17/catalog-pg-class.html) enumerates relation kinds `r` (ordinary table), `p` (partitioned table), `v` (view), `m` (materialized view), `f` (foreign table), `S` (sequence), with `relnamespace` referencing `pg_namespace`. [PostgreSQL 17 access privilege functions](https://www.postgresql.org/docs/17/functions-info.html) permit OID-based effective `has_any_column_privilege`, `has_table_privilege` and `has_sequence_privilege` checks for current authenticated SQL identity. [GRANT](https://www.postgresql.org/docs/17/sql-grant.html) distinguishes column vs table and sequence rights. A hardcoded list of known sensitive tables does not cover **future** relations.

## Decision: conservative relation inventory alongside explicit positives and negatives

1. **ADR first on `main`**, then **tests-only RED**: 17 real PostgreSQL17 xUnit cases. Exactly nine independent per-login GRANTs against V004/V006 `organization_provisioning_events` (SELECT, SELECT(first_admin_subject), INSERT, INSERT(id), UPDATE(admin_proof_sha256), REFERENCES(id), DELETE, TRUNCATE, TRIGGER); two against `public.schema_migrations` (SELECT, UPDATE(sha256)); two against freshly created empty `public.tm_futureacl_<randomhex>` table (SELECT, INSERT(secret)); one against a newly created constant-only test view (SELECT); three against a newly created isolated sequence (USAGE, SELECT, UPDATE). Each test: unique synthetic LOGIN member only of `temporalmark_runtime_group`, `Pooling=false`, pass original baseline, grant exactly one object/column/sequence privilege **to that test login only**, expect generic prelisten rejection without inner exception, user, password or SQL object name. In `finally` revoke the grant, DROP synthetic object (if any), revoke group membership, DROP LOGIN; no real data rows or sequence movement, owner role change or migration checksum modification. Real RED must be **17 expected missing-denial assertion failures / 221 prior passes / 238 total**, not compiler, permission, syntax or fixture failures.
2. Only after genuine RED add **one catalog-level `AND NOT EXISTS`** to the existing single authenticated and **already open** PostgreSQL runtime prelisten `SELECT`, scoped to **public schema** `pg_catalog.pg_namespace` + `pg_catalog.pg_class`. For `relkind IN ('r','p','v','m','f')` with `relname NOT IN ('organizations','organization_memberships','timestamp_registry','tenant_audit_events')`, reject any effective table-wide or per-column `SELECT,INSERT,UPDATE,REFERENCES` (`has_any_column_privilege(c.oid,...)`) and any `DELETE,TRUNCATE,TRIGGER` (`has_table_privilege(c.oid,...)`). For `relkind='S'`, reject `USAGE,SELECT,UPDATE` with `has_sequence_privilege(c.oid,...)`. All four approved tables retain existing independent **positive** and restrictive **negative** checks; known owner-only table/sequence explicit predicates remain for regression visibility and defense in depth. Only normal V019 `consume_imprint_search_rate(uuid,text)` function execution remains allowed. Zero new database connection/DDL/GRANT, SQL migration, SQL privilege escalation, caller-supplied catalog name, API/CLI endpoint, Azure Terraform or on-prem default Password-mode change. This is intentionally **future-fail-closed**: a new public runtime table/view/sequence needing application rights must first have an independently reviewed architectural ADR and a carefully scoped allowlist change, tests and approved migrations. A failed gate should not be bypassed.
3. Update this ADR, runbooks, migration docs, operator instructions, threat model and ROADMAP with genuine RED/GREEN. Close **only scoped #153** after independently verified exact final documentation-inclusive `main` SHA GitHub Actions backend/frontend/terraform/docker-smoke **4/4**, ci-verdict and combined `temporalmark/ci-4-core-jobs=success`, real PostgreSQL17 **238/238**, 20 original migration checksums, real TEST-only `pg_dump/pg_restore` rollback/witness, Keycloak reviewer/registrar TOTP+PKCE and two-tenant signed HTTP JWT 401/403, Nginx private 413/414/429.

## Scope and limitations

This is a **one-time, read-only catalog ACL prelisten** for explicit Production `RegistryPostgres:AuthenticationMode=ContainerAppsEntraCandidate` only. It deliberately scopes the generic deny to the **public schema** and relation/sequence privileges; it does not evaluate cross-schema grants, ALL possible SQL functions/extensions, ownership/DDL, post-start grants or connection-pool revocation. Existing specific privilege and privileged-role checks remain. There is no live Azure SQL UAI, Terraform admin-password state remediation, production CAB, trusted WebAuthn decision, signed witness, legally immutable WORM or certified qualified electronic timestamp claim. All release blockers #128/#18/#14/#38/#50/#64/#61/#17/#13/#15 remain OPEN.
