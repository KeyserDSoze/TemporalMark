Official [PostgreSQL17 string function documentation](https://www.postgresql.org/docs/17/functions-string.html) documents `octet_length(text)` as **encoded bytes**, not UTF-8 character count (database's supported encoding is UTF8); [PostgreSQL17 conditional expressions](https://www.postgresql.org/docs/17/functions-conditional.html) describes conditional `CASE` evaluation with planner caveats. [RFC3161](https://www.rfc-editor.org/rfc/rfc3161) identifies `MessageImprint.hashAlgorithm` and `TSAPolicyId` as object identifiers, **not** a maximum serialized text-byte limit. The fixed SHA256 algorithm OID and canonical 44-character Base64 digest are generated **on pilot issuance** (`TimestampIssueService`, ADR 0072). Those ingress invariants alone do not constrain legacy restored or owner-altered database rows or future external provider IDs. `token_sha256_hex char(64)` is already physically bounded at V001; `evidence_reference text NULL` was separately bounded in #175/ADR 0133. These four other V001 `text NOT NULL` fields are unbounded.

## Threat and narrow policy

A legacy/owner-modified row can preserve original small self-consistent DER/SHA256, pilot `Unverified` and authorized tenant scope, but have enormous `hash_algorithm_oid`, `digest_base64`, `policy_oid` or `provider_id`. `PostgresTimestampRegistry.MapRecord` eagerly calls `reader.GetString(3..7)`, before verifying the other evidence. #175's DER/reference SQL `CASE` does not hide those metadata fields. This could transmit huge PostgreSQL result values or cause a large page/search JSON/ZIP source allocation **before** the independent bounded v1 manifest serializer. There is no assertion that such an attack happened or that local SHA256 checks authenticate who issued a token.

1. **Pilot-only source UTF8 limits**, independent of previous reference/DER budgets: each of the **four nonnull text fields** `hash_algorithm_oid`, `digest_base64`, `policy_oid`, `provider_id` is admitted iff `octet_length(field) <= 16,384` bytes, inclusive, and across **all four fields of every selected row** the aggregate must be `<= 2,097,152` bytes, inclusive. This deliberately conservative generous field cap does **not** redefine RFC3161 OID syntax, a canonical Base64 validation policy, accepted QTSPs, or how a provider ID is formed. Existing ordinary short values are preserved exactly. Non-null V001 schema invariants remain; NULL is never silently substituted as a valid field. This is an operational pilot budget, not an eIDAS/RFC maximum. The existing separate raw `evidence_reference` 8MiB per-item/batch, DER 1MiB per receipt/64MiB batch, and 8MiB **actual serialized JSON manifest** caps continue unchanged; JSON escaping and concurrent accepted reads remain separate risks.
2. **Commit ADR before tests and source**. Add actual disposable PostgreSQL17 xUnit tests with a unique tenant/authorized self-consistent 4-byte DER and correct SHA256, deliberately malformed-by-size (but not by DER/hash) each of the four text columns at 16KiB+1. A tenant-owned GET must reject at the provider itself with the fixed `ReceiptTooLargeException` (HTTP 409/no-store, no prepared audit), page/search with the existing generic `InvalidOperationException`, export with fixed `ExportTooLargeException` (HTTP 413). For search, match a normal stored SHA256 imprint while inflating provider/policy. Validate UTF8 multibyte (e.g. 'é' * 8193), exact boundary 16KiB, cumulative whole-batch rejection with individually valid text fields (including first row rejection, search lookahead when relevant), NULL not introduced for valid fields, another tenant and absent requested receipt still return null/404. Preserve original 7MiB accepted evidence-reference test and 1MiB DER. Add Business fake-adapter unit tests for all four text fields and four routes, typed/generic error contracts, cumulative budget. Require independently observed **real GitHub Actions tests-only RED** due to missing size denials, not compiler/fixture failures; source must remain unchanged until genuine RED is confirmed.
3. **After observed RED** extend the **existing one-statement tenant/UTC/ID/digest-scoped PostgreSQL17 SQL snapshot**: `chosen AS MATERIALIZED` for page/search/export contains only ID, existing DER/reference octet lengths, and (a) `GREATEST(octet_length(...))` for the largest of the four fields and (b) the `bigint` sum of their four lengths; `guarded` applies `bool_and(max_field_bytes <= @max_metadata_field_bytes) OVER ()` and `sum(metadata_bytes) OVER () <= @max_metadata_batch_bytes`. **Before Npgsql GetString** the final projection must suppress **ALL FOUR** original text columns (positions 3,4,5,6), original DER (9), original reference (10) for **every** row of any invalid selected batch; use `NULL::text` and `NULL::bytea` as internal denial sentinel, not returned data. Detect the sentinel at ordinal 3 and/or 9 before `MapRecord`; keep row count/sort/lookahead and no partial response. Avoid two-query preflight TOCTOU. For single GET use the same parameterized tenant+exact-ID SELECT snapshot and a row-local admission expression that hides all four fields, DER and reference when invalid. A missing/foreign ID still has no row and maps to 404 (not 409). `token_sha256_hex char64` remains unchanged. SQL may still read TOAST metadata internally; no claim of zero PostgreSQL CPU/I/O.
4. **Business defense in depth** for alternate adapter/fakes after tenant & exact ID (GET) or tenant/UTC & existing DER/reference budgets (batch): `Encoding.UTF8.GetByteCount` for each of four fields, reject one over 16KiB or batch sum over 2MiB **before SHA256 or returning any page/export**. Preserve single GET `ReceiptTooLargeException`, ZIP `ExportTooLargeException`, generic page/search `InvalidOperationException` with no sensitive input values; the existing ZIP 8MiB JSON/80MiB physical limits and prepared-audit ordering remain independent. **Do not** alter `TimestampRecord.Validate` issuer behavior, V001–V020 migrations, ORM schema, Entra roles, SQL GRANTs, Azure Terraform, Keycloak or client API schemas.

## Rejected alternatives, boundaries

- Do not truncate source metadata, silently replace malformed text with a short identifier, or mutate the original DER/hash: loses evidence provenance. Decline read and require a documented operator investigation instead.
- A C#-only length check after `GetString` happens **too late** to prevent original PostgreSQL wire materialization; retain independent Business check only as defense in depth.
- Do not use a separate `SELECT octet_length` followed by another fetch; concurrent DB changes can race between statements. One statement/snapshot with a conditional final projection is required.
- Do not declare a huge (but within-size) `policy_oid` or provider ID to be valid, verified or legally qualified: a future distinct issuer/protocol policy should validate canonical ASN.1 OIDs, supported digest and exact issuer/TSR semantics with independent tests, signed QTSP Trusted Lists and qualification state machine under #15/#13.
- This does not impose a new global request/concurrency memory quota, stop arbitrary SQL-owner mutation, prove same-row DER's real RFC3161 trust, immutable WORM custody, signed complete exports, GDPR-approved retention or actual eIDAS CAB certification. All retained pilot receipts remain **Unverified**.
