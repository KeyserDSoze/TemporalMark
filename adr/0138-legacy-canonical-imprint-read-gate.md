## Decision — safeguard responses without rewriting evidence

1. **ADR first; real PostgreSQL17 RED first:** Commit test-only disposable real PostgreSQL17 fixtures using SQL owner/test authority (never application runtime writer or privilege grant) to insert own-tenant `Unverified` rows with original 4-byte DER and matching SHA256, UTC, nonblank source and in-budget raw UTF8 metadata, but either wrong SHA256 OID, nonzero Base64 pad-bit alias (decodes to same bytes), non-32-byte decoded imprint, or ignorable whitespace. `TimestampRecord.Validate` must still pass on the raw repository projection. Assert authorized Page, Receipt, Export all throw generic sanitized `InvalidOperationException` before returning data/bytes/ZIP; assert zero mutation of original SQL data, `FindByIdAsync` foreign returns null, unrelated tenant valid rows and canonical search remain readable. A real compiled and executed missing-denial RED from GitHub Docker PostgreSQL17 is required; build/fixture SQL failures do not count.
2. **Business RED before source:** Add fake-repository xUnit tests across Page, direct Receipt, Export and Search **including search lookahead** for different malformed legacy imprint variants; original retained DER and its SHA256, tenant and UTC all valid, under existing budgets and `Unverified`. Assert no partial records, data, ZIP, hasMore or wrong-tenant disclosure and a fixed redacted `InvalidOperationException`. Existing positive canonical original receipts (including large legal under-budget policy/provider strings) and cross-tenant denials stay green; keep 16KiB per-field, 2MiB batch, DER 1MiB/64MiB, ref 8MiB and ZIP size controls. Business suite will intentionally be RED at this test-only SHA. Document actual logs for both reds separately before production.
3. **After genuine RED(s), minimal source:** Reuse the already-tested canonical SHA256/OID parser from ADR 0137 by exposing a read-only pure helper from the Business stamping layer (do **not** duplicate parser semantics or mutate original data). Invoke at `TimestampRegistryService.DownloadReceiptAsync` **after tenant and exact record ID** and existing resource preflight, before returning receipt bytes; invoke inside `ValidateReturnedRecords` after tenant/period and resource budgets and `record.Validate`, before page/search lookahead/ZIP emission. Continue rejecting unsupported future verification/incident states under ADR 0121. The error remains fixed generic `InvalidOperationException` without tenant, DER, algorithm or imprint. **Do not change the SQL wire-admission budget, database schema, historical stored row, response metadata, issuer, QTSP configuration or external network paths.** For other tenants return ordinary not-found; preserve the specialized `ReceiptTooLargeException` (HTTP 409/no-store) for already over-budget authorized records and related ZIP typed limits. Counts/Daily remain **aggregate** metadata and do not claim individual record verification.

## Limitations and alternative decisions

- **Normalize/rewrite old `DigestBase64` or algorithm OID:** rejected; destroys historical provenance, can fabricate apparently searchable evidence, and bypasses approved incident/forensic workflows. Retain original bytes/metadata for operator investigation.
- **Tighten `TimestampRecord.Validate` or V001 CHECK:** rejected for the scoped pilot: the Domain enum/schema support future legitimately verified/imported algorithms, and existing migration checksums are immutable. Keep parser at the application **read** and **new-write** trust boundaries; future non-SHA256 RFC3161 lookup profiles need independent approval and ADR.
- **Do nothing on read because ingress/writer is strict:** rejected; privileged owner/restore/legacy data bypasses those application write gates.
- **Canonical string implies token is qualified:** false. DER SHA256 consistency does not establish RFC3161 CMS `messageImprint` binding, signer certificate/revocation/Trusted List history, accurate UTC(k), WORM, export completeness, GDPR retention basis or CAB/AgID/eIDAS qualification. An owner who can alter both DER+SHA remains outside this limited gate.
