# ADR 0092 — Private Blob endpoint and DNS for Azure timestamp evidence

Status: **Accepted for scoped prequalification #125**, 2026-11-20. Parents [#18](https://github.com/KeyserDSoze/TemporalMark/issues/18), [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115), [#17](https://github.com/KeyserDSoze/TemporalMark/issues/17) remain OPEN.

## Reviewed baseline, issue and documentation

Read ADR 0001 (on-prem/Azure parity), ADR 0090/0091 (ACA web/app+environment private ingress), `infra/azure/main.tf`, `versions.tf`, `variables.tf`, existing 34 mocked Terraform plan tests, `infra/azure/README.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md`, and GitHub issue parents. Azure Storage Account `evidence` currently has private container, `allow_nested_items_to_be_public=false`, shared access key disabled, TLS minimum 1.2, a versioned Blob container and deliberately **unlocked** immutability policy. However the Storage Account does not explicitly disable **public network access**, and the ACA VNet lacks a Blob private endpoint/DNS path. Container-level anonymous access restrictions and Azure RBAC alone do not close the storage endpoint network surface.

[Microsoft Storage Private Endpoint guidance](https://learn.microsoft.com/en-us/azure/storage/common/storage-private-endpoints) states VNet clients use private IP and DNS and may access public-disabled accounts via Private Link. [Microsoft Storage networking FAQ](https://learn.microsoft.com/en-us/troubleshoot/azure/azure-storage/blobs/networking/storage-network-security-faq) recommends public network access disabled with the `privatelink.blob.core.windows.net` private DNS zone; [AzureRM Storage Account](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/resources/storage_account) and [AzureRM Private Endpoint](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/resources/private_endpoint) document the resources. Storage data-plane provisioning/operations and existing private-network cloud runtime cannot be proved through Terraform mocked plans.

## Decision

1. Make `azurerm_storage_account.evidence.public_network_access_enabled = false` and `https_traffic_only_enabled = true` explicit. Preserve Shared Key disabled, TLS1_2 minimum, container `private`, versioning/change feed, existing unlock state and `prevent_destroy` lifecycle; do not change `evidence_retention_days` or claim a certified WORM store.
2. Create a **dedicated nondelegated** `azurerm_subnet.evidence_private_endpoint` (`10.40.3.0/24`) within the existing VNet (ACA apps `10.40.1.0/24` and Postgres `10.40.2.0/24` stay separate). Create `azurerm_private_dns_zone.evidence_blob` named exactly `privatelink.blob.core.windows.net`, link it to `azurerm_virtual_network.main`, and create `azurerm_private_endpoint.evidence_blob` in the new subnet with a single `private_service_connection` referencing the evidence Storage Account, `subresource_names=["blob"]`, nonmanual connection, plus `private_dns_zone_group` referring to the zone ID. Keep broad public access to other services unchanged; do not re-purpose delegated subnets.
3. To avoid the already-known Shared-Key-disabled `azurerm_storage_container` data-plane authorization conflict, configure `provider "azurerm" { storage_use_azuread = true }` with the existing managed provider. **This does not authorize Terraform identity**: a real apply must run with approved Azure AD/RBAC permissions and **network connectivity from the private VNet** for Blob data plane, or refactor container creation to a separately reviewed ARM control-plane approach. Provisioning order, DNS/link approval and data-plane RBAC propagation can be material and must be tested in a disposable Azure subscription before production. An external GitHub-hosted runner will generally **not** reach public-disabled Blob data-plane endpoints. No actual Azure apply or proof of production deployability is part of #125.
4. TDD RED first: real `mock_provider "azurerm"` `command=plan` asserts public network disabled and HTTPS-only, private container, disabled shared key, Private Endpoint subnet CIDR/nondelegated, DNS zone+VNet link, PE Blob subresource/automatic approval and private zone group. Only compare plan-known values; provider-created IDs may be unknown. Wire a new test in the existing mandatory Terraform CI, keeping prior 34 positive/negative plan scenarios. Observe actual RED from missing public-network denial / endpoint before production changes, then GREEN. Source tests and mocked plans are **not** real TCP reachability, Azure Private Link approvals or evidence object upload.
5. API/pilot PostgreSQL and OSS deployment remain untouched. Preserve data at rest, authentication, tenant isolation, audit, #117/#119 minimal container logs, #124 private ACA environment, V015/V016 reviewer interlocks. A private Blob endpoint must not be mistaken for a separate independent signed WORM custodian, qualified timestamping infrastructure or legally approved indefinite retention.

## Production/qualification gates retained

Actual Azure VNet DNS resolution, private endpoint approval and connectivity from ACA and migration/apply runner, Data-plane RBAC (including Storage Blob Data Contributor and operator AAD), real evidence PUT/GET, versioning/immutability under independent witness, backup/legal-hold and controlled deletion are OPEN #18/#17/#115. Client-side Storage containers and Blob provider operations may fail outside VNet or with missing identity scopes; no external runner exceptions or temporary public network release are authorized by this ADR. Managed Azure ingress/Log Analytics privacy, WAF/CAB release, GDPR-DPIA retention, eIDAS/QTSP #13/#15 and pilot `Unverified` state remain unresolved.

## Closure gate

Close only #125 after independently confirming the **exact final docs-inclusive main SHA** 4/4 core GitHub CI jobs, `temporalmark/ci-4-core-jobs=success`, actual real Terraform mocked Blob private-network tests alongside preexisting 34, and live Docker PostgreSQL/Keycloak signed HTTP/Playwright, log confidentiality and full restore. Never claim Azure deployment or certified legal custody from that CI.
