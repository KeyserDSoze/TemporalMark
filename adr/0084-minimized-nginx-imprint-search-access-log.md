# ADR 0084 — Minimal Nginx access telemetry for imprint-search proxy (pilot)

Status: **Accepted for bounded #117 only**, 2026-11-19. Child of still-open [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) / [#113](https://github.com/KeyserDSoze/TemporalMark/issues/113). No change to eIDAS/QTSP, WebAuthn V015/V016 stop-line or GDPR legal determination.

## Reviewed baseline and security gap

Reviewed accepted [ADR 0001](0001-architecture-and-deployments.md), [ADR 0081](0081-tenant-document-sha256-imprint-exact-lookup.md), [ADR 0082](0082-search-audit-and-abuse-controls.md), [ADR 0083](0083-postgres-atomic-imprint-search-rate-admission.md), `docs/THREAT_MODEL.md`, `docs/IMPRINT_SEARCH_RATE_LIMITING.md`, `docker/nginx.conf.template`, `src/frontend/Dockerfile`, `docker/compose.yml`, `infra/azure/main.tf`, `infra/azure/README.md` and the four-job CI's real Docker/Nginx test steps. Official NGINX documentation: [ngx_http_log_module](https://nginx.org/en/docs/http/ngx_http_log_module.html) and [logging guide](https://docs.nginx.com/nginx/admin-guide/monitoring/logging/).

The web container currently inherits the Nginx default `combined` access format. NGINX's official default includes `$request` (original request line with query), `$remote_addr`, `$http_referer`, `$http_user_agent`. Although `POST /api/v1/stamps/search` sends SHA-256 imprint in JSON rather than the URL, synthetic or misbehaving client requests can still place a potentially linkable imprint, authentication token or other identifier in an URL/query/referrer/user-agent. Custom access formats may leak headers or `$request_body`. The default log does not normally store POST bodies, but reliance on defaults and untested per-container overrides is insufficient.

## Scoped decision

1. Define `log_format temporalmark_minimal 'tm_access status=$status method=$request_method duration=$request_time';` in a new `/etc/nginx/conf.d/00-temporalmark-log-format.conf` file, injected via the **same Nginx frontend image** for OSS Compose and Azure Container Apps. `log_format` belongs to the **http** context, not the `server` context; the packaged `conf.d/*.conf` include is inside `http` for the pinned image. This must fail Nginx config parsing at startup if misplaced.
2. Explicitly set `access_log /dev/stdout temporalmark_minimal;` at the `server` level of `docker/nginx.conf.template`. No per-location `access_log` override is introduced. Each request produces only a fixed marker, numeric status, HTTP method and elapsed response-processing time. **Do not log** raw request line, URI, path, query, client IP, user-agent, referrer, bearer/cookies, `sub`, document imprint, body or response result/count. Deliberately accept reduced operational route/identity traceability; do not claim access logs alone are a legally sealed tenant audit. Authorized search append-only pilot audit stays handled by #114 in PostgreSQL.
3. No application route, header forwarding, JSON payload, authenticated role check, per-tenant rate quota, PostgreSQL migration, WORM or Azure service changes. The web image deployed by OSS and referenced in Azure Terraform gets the identical Nginx access configuration, but **Azure Container Apps edge ingress, fronting gateways/CDNs/WAF, Log Analytics collection, separate API Kestrel logs, Nginx error logs, operator-customized logging and external observability agents are outside this narrowly tested container access stream**. These remain unverified under #115/#113/#18/#19.
4. TDD: first commit Python source tests that require the new format and refuse sensitive Nginx variables, plus a live disposable HTTP+Nginx stdout-access-log test. The latter must submit separate, clearly synthetic query/path/referrer/user-agent/fake-Authorization canaries and JSON-imprint POST; require actual `tm_access` rows with HTTP 200 and unauthorized 401 and absence of all canary bytes or raw original request-line URI in the Nginx **access** log stream. Tests must not print raw captured logs or actual tokens. Then commit the minimal two Nginx files. Wire source test to backend and live test to docker-smoke, update docs and verify all four core jobs on exact final docs-inclusive main SHA before closing **only #117**.

## Residual limitations

Nginx error logs and upstream .NET logs can include request/path context during errors; disabling access variables does not audit third-party proxies or Azure-managed ingress. TLS client identity may remain in edge logs. Nginx access logs are NOT a replacement for a privacy basis, required retention/deletion with backup redaction, independent SIEM change control, signed evidence/WORM or complete per-tenant request accounting. Header/body capture can be re-enabled by an operator with image/config/sidecar privileges. A Docker test cannot independently attest an actual Azure tenant's runtime configuration. Keep #115/#113/#17/#13/#15 OPEN and evidence `Unverified`; do not relax reviewer registrar V015/V016.
