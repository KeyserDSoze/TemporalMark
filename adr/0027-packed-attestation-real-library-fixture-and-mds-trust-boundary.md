# ADR 0027 — Test-only cryptographically signed packed WebAuthn attestation and production trust boundary

Status: **accepted for test-only cryptographic regression coverage, NOT production attestation trust** (2026-11-15). Scope: first increment of #53, following #52 and ADR 0026. Parent #44/#50/#46/#38 remain OPEN.

## Context and decision

The current Fido2 4.3.3 adapter has negative tests against the real maintained verifier and a mock-positive result-shape test, but **no positive cryptographic attestation**. The mock does not prove a genuine `webauthn.create` can verify. W3C WebAuthn Level 3 section 8.2 defines packed basic attestation as a certificate-key signature over `authenticatorData || SHA256(originalClientDataJSON)`; the attestation certificate's provenance is a separate trust decision. Basic attestation returned by a verifier is **not** proof of trusted hardware, vendor approval, reviewer possession, or authorization.

1. Write RED xUnit tests **before** a fixture implementation; run the current real, pinned **Fido2 4.3.3** library. Generate a separate P-256 credential key and ephemeral P-256 attestation signing key **at test runtime**, with an explicitly test-only X.509 v3 leaf bearing `C=IT`, `O=TemporalMark Tests`, `OU=Authenticator Attestation`, `CA=false`, digital signature. No private key/certificate is checked into git. Encode actual COSE EC2/ES256 public key, 37-byte authenticator-data prefix with RP SHA-256, UP+UV+AT bits, AAGUID, credential ID, `webauthn.create` JSON with original 48-byte server challenge, and signed `packed` attestation object. The CBOR writer is **test fixture construction only**; the maintained Fido2 library is the only parser and signature verifier in production/test verification.
2. Require a real-library **positive** result to be exactly `UNAPPROVED` hashed-only candidate, never raw key or ACTIVE credential. Negative mutation tests must separately exercise wrong challenge, origin, RP hash, UP/UV flags, modified original authenticator bytes, and invalid signed certificate/signature. No fake `IFido2` positive is accepted as cryptographic evidence. An in-memory unique-ID callback is **test-only**, not a production credential registry.
3. Certificate acceptance by the library with no Metadata Service is NOT independent chain validation. The temporary test signing CA/leaf must never be wired to app, production config, Azure Key Vault, SQL grants or real MDS roots. Keep V015/V016 freeze, suspended CLI, no HTTP endpoint and no new SQL migration. This work cannot remove direct reviewer approval SQL grants.
4. Before a genuine device can be trusted, independently approve RP origin and trust anchors for **both** on-prem and Azure; validate the FIDO MDS BLOB JWT signature and certificate path to pinned FIDO MDS roots, freshness (`nextUpdate`), monotonic serial, revocation and rollback; map AAGUID to metadata/trust-path and certified authenticator model, reject REVOKED / USER_VERIFICATION_BYPASS / security-status downgrade and unapproved/unknown devices, verify certificate renewal and acceptable revocation-check failure policy (fail closed). A production metadata outage or expired metadata must **not** result in acceptance. The actual accepted-device policy, audit, procurement, recovery and attestation CA validation require independent review and additional code/tests; none are implemented by this test fixture.
5. Attestation certificates, AAGUID, device serials and metadata can enable user/device tracking. Enforce privacy/DPIA, minimum logging and access controls before live enrollment. Test-only generated keys are discarded when the test ends. Neither mocked nor self-generated certificates imply FIDO certification, physical possession, qualified timestamping, WORM or eIDAS compliance.

## Evidence and completion rule

A RED commit and subsequent GREEN commit to `main`, followed by four exact-head GitHub CI jobs, are required to record the focused cryptographic fixture as complete. #53 stays open until its broader independently validated MDS metadata/trust implementation and all remaining acceptance are satisfied. No production operation is unlocked.
