# ADR 0128 — Bind the returned receipt identity to the requested ID before DER delivery and audit

Status: **Accepted for incremental RED-first hardening [#170](https://github.com/KeyserDSoze/TemporalMark/issues/170)**, 2026-11-22 Europe/Rome. Child of open #17 (independent WORM and complete-period evidence); QTSP #15, CAB/AgID #13, independent signed custody #61/#64, Azure #18 and WebAuthn #38/#50 remain OPEN.

## Baseline, source review and specific gap

Reviewed [ADR 0004](0004-evidence-time-and-retention.md), [0074](0074-registry-page-export-integrity-and-unique-ids.md), [0121](0121-pilot-registry-unsupported-validation-state-read-gate.md), [0127](0127-pilot-single-receipt-download-der-byte-bound.md), actual `TimestampRegistryService.DownloadReceiptAsync`, `TimestampRecord.Validate`, `ITimestampRegistry.FindByIdAsync`, the real parameterized `PostgresTimestampRegistry.FindByIdAsync`, Business xUnit `FakeRegistry` and `MaliciousRegistry`, signed-Keycloak two-tenant disposable API smoke, API `GET /api/v1/stamps/{id}/receipt` and its `ReceiptDownloadPrepared` append after successful DER read, the registry operator guide, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md` and exact source-integrity CI.

Exact preceding docs-inclusive `main 44f83d70850e274fae20f98afec4994f5fdd0b3f` [Actions 45062977133](https://github.com/KeyserDSoze/TemporalMark/actions/runs/45062977133/attempts/1) has backend/frontend/terraform/docker-smoke 4/4 success, Business 293/293, PG17 247/247, all 20 migrations, real Keycloak A 409/B 404 and no prepared audit for oversized DER, and is the exact-green basis for closed #169. There are 26 open issues before this child.

The production PostgreSQL adapter correctly queries **both organization ID and requested record ID** in its prepared SQL. The shared Business service subsequently checks returned `record.OrganizationId == organizationId`, stored DER SHA256, pilot-only `Unverified`, and <=1MiB size, **but not returned `record.Id == requested recordId`**. Thus a broken or malicious `ITimestampRegistry` adapter can return an entirely self-consistent **different** receipt within the correct tenant for a requested ID; a higher API layer then records `ReceiptDownloadPrepared` referencing the *requested* ID even though it is serving different raw DER. This is a **misassociation/data-integrity and audit-provenance** hazard, not an actual demonstrated failure of the real PostgreSQL adapter, cross-tenant authorization or an eIDAS incident.

## Decision — genuine RED then minimal production repair on main

1. **Commit this ADR first**, before test or code modifications.
2. **Tests-only Business xUnit commit**: malicious `FindByIdAsync` returns an intact `TimestampRecord` in authorized tenant A, with distinct, nonempty `Id` from requested one, SHA256 matching original DER and `Unverified`; demand generic `InvalidOperationException`, no returned bytes or identifier/hash/provider content in failure. Repeat with distinct returned ID and >1MiB, correct SHA256, requiring the identity mismatch be denied **before** `ReceiptTooLargeException` so even within-tenant wrong-ID rows do not reveal byte-budget status. Existing correct ID positive, foreign tenant denial, empty ID validation and no-row null continue. Confirm **real GitHub Actions backend RED** shows only missing-denial assertions, not compilation, fixture or infrastructure failures.
3. **Only after RED**, add a constant-message `if(record.Id != recordId) throw new InvalidOperationException(...)` immediately after the existing tenant equality check in `DownloadReceiptAsync` and **before** size, hashing and pilot-status checks. Keep `FindByIdAsync` parameterized SQL, no data rewrite, no masking with 404 for repository corruption, no mutation of JWT/tenant selection, and all original DER returned unchanged for legitimate success. No new exception type or HTTP route handling: existing generic error path fails closed before the API prepares a misleading audit event.
4. Update ADR, `docs/REGISTRY_INTEGRITY_READ_GATES.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md` (and README if warranted). Close **only #170** on independent **exact docs-inclusive main SHA** backend/frontend/terraform/docker-smoke **4/4**, ci-verdict and combined green, Business new+existing, Python offline/bridge and psql-audit tests, real PostgreSQL17 247/247 and 20 checksums/full test-only restore, signed-Keycloak dual-tenant HTTP (including #169 oversized 409/404/no-audit), Nginx privacy/429.

## Limits and release stop-line

Checking one returned ID does **not** prove that a receipt was actually issued by a qualified QTSP, that all period receipts are present, that the registry and external object storage are immutable or witnessed, that the audit ledger is independently signed, that GDPR indefinite retention is lawful, or that a compromised SQL owner could not rewrite both DER and hash. No real signatures, TSU/HSM UTC(k), CMS or EUTL historical validation are added. Pilot records remain **`Unverified`**; #17/#15/#13/#61/#64/#18/#38/#50 remain OPEN.
