# ADR 0109 — Match all case variants of sensitive search route at the Nginx pre-auth boundary

Status: **Accepted for bounded security regression [#144](https://github.com/KeyserDSoze/TemporalMark/issues/144)** on 2026-11-21. Parent #115/#113 still OPEN. #18 Azure ingress, #17 WORM and #13/#15 eIDAS/QTSP remain blocking independent release decisions. No deployment/CAB, legal custody or privacy-policy approval.

## Reviewed state and mismatch

Reviewed accepted ADR 0001 (open-source on-prem and Azure app parity), ADR 0083 (distributed PostgreSQL authenticated 12 actor/30 tenant per minute quota), ADR 0084 (minimal Nginx stdout access fields), ADR 0102 (4096-byte pre-auth request body budget on independent Kestrel and Nginx), ADR 0108 (single-instance pre-auth per-TCP-peer Nginx search burst 2r/s, burst 12), docs/NGINX_EDGE_SEARCH_BURST, IMPRINT_SEARCH_BODY_BUDGET, NGINX_ACCESS_LOG_PRIVACY, THREAT_MODEL, COMPLIANCE, ROADMAP, actual Docker shared frontend image, `docker/nginx.conf.template` and the live `imprint-search-nginx-edge-limit.py`, `imprint-search-body-budget.py`, source-policy tests and GitHub docker-smoke. The current Nginx **`location = /api/v1/stamps/search`** matches one lowercase URI only. ASP.NET Core 10 routing is case-insensitive, and direct Kestrel's pre-auth request size check deliberately uses `StringComparison.OrdinalIgnoreCase`. Since Nginx's generic `location /api/` proxies mixed-case suffixes to the same ASP.NET route, an anonymous `/api/v1/StAmPs/SeArCh` request avoids **Nginx's own** burst and route-specific body/error-log limits even while Kestrel separately enforces 4KiB and its signed-JWT gate. No evidence of a real production exploit or request to bypass authentication is claimed.

Authoritative [Nginx core module location matching](https://nginx.org/en/docs/http/ngx_http_core_module.html) specifies exact `=` vs case-insensitive regex `~*`, anchoring and normalized URI. Official [ASP.NET Core 10 routing](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/routing?view=aspnetcore-10.0) states text matching is case-insensitive. Matching policy must not depend on URL casing chosen by an unauthenticated client.

## Decision

1. Only the **existing sensitive Nginx location matcher** changes from `location = /api/v1/stamps/search {` to a full-path **anchored, case-insensitive regex** `location ~* ^/api/v1/stamps/search$ {` in the same shared pinned web-image Nginx server template. `~*` matches a normalized URI without query; both anchors forbid prefix and suffix requests, retaining no path rewriting and preserving the current backend `proxy_pass ${API_UPSTREAM};`, forwarded Host/XFF, fixed 4KiB Nginx size limit, local per-`$binary_remote_addr` 2r/s burst12 429, Retry-After1/no-store internal handler, `proxy_intercept_errors off` for genuine SQL 429 and `error_log crit` secrecy. Default SPA, other API routes, Kestrel direct 4096-byte body check and signed OIDC tenant 401/403 remain unchanged. Proxy configuration is shared by OSS Docker/on-prem and the Azure **web image** only; nothing governs actual ACA managed ingress or a directly exposed API.
2. **TDD RED first on main**: extend the existing real Docker-only Nginx anonymous burst script with an independent 48-request barrage to a **mixed-case route** using the same physical loopback TCP peer and varying synthetic `X-Forwarded-For`. It must get at least one genuine Nginx-local 429 with generic non-cacheable Retry-After, no fake SHA/bearer/query metadata in response or actual Nginx logs, and must leave the original lowercase 429 + direct Kestrel 401 + unrelated API/SPA/health behavior intact. Test the previous exact-location version on actual GitHub docker-smoke and observe missing mixed-case 429 after successful baseline lower-case test, before source change. Do not weaken or simulate the auth boundary.
3. After RED, change **one** Nginx location matcher and update **both existing mandatory source-policy tests** so they explicitly require `~*` and exact beginning/end anchors. Verify the existing Kestrel/Nginx body-budget and confidentiality live probes still pass; no other Nginx, .NET, proxy topology, identity, SQL quota, Terraform, role grants or migrations change.
4. Document all decisions and remaining limitations in Nginx search burst/body runbooks, THREAT_MODEL and ROADMAP. One Nginx instance's per-peer IP bucket is not distributed across frontend replicas, may group unrelated users behind NAT/ingress, cannot substitute for independent ACA ingress policy/WAF/preauth network controls, and does not seal audit, satisfy GDPR DPIA, eIDAS or QTSP. Unreviewed client IP headers remain untrusted. Parent #115/#113 must remain open.
