# ADR 0096 — Detached Npgsql 10 Entra PostgreSQL token data-source candidate

Status: **Accepted for scoped prequalification [#130](https://github.com/KeyserDSoze/TemporalMark/issues/130)**, 2026-11-20. Existing Azure PostgreSQL admin password / full migration [#128](https://github.com/KeyserDSoze/TemporalMark/issues/128) and Azure production [#18](https://github.com/KeyserDSoze/TemporalMark/issues/18) remain OPEN.

## Baseline and reviewed authoritative behavior

Reviewed [ADR 0001](0001-architecture-and-deployments.md) (on-prem/Azure same app), [ADR 0094](0094-azure-api-keyvault-bootstrap-secret-reference.md) (runtime DB secret presently outside Terraform), [ADR 0095](0095-isolated-entra-only-postgres-candidate.md) (an isolated **non-applied** Entra-only *new* server), `src/backend/applications/TemporalMark.Api/Program.cs`, `src/backend/applications/TemporalMark.Provisioner/Program.cs`, PostgreSQL infrastructure and `Npgsql 10.0.0` in `src/backend/infrastructures/TemporalMark.Infrastructure/TemporalMark.Infrastructure.csproj`, the existing xUnit Provisioner tests, `scripts/apply-migrations.sh`, `docs/DATABASE_MIGRATIONS.md`, `docs/AZURE_POSTGRES_ENTRA_CANDIDATE.md`, `docs/THREAT_MODEL.md`, Azure Terraform and parent #128/#18.

Microsoft [PostgreSQL managed identity documentation](https://learn.microsoft.com/en-us/azure/postgresql/security/security-connect-with-managed-identity) requires a separately provisioned database principal and accepts a Microsoft Entra access token in the PostgreSQL password protocol. The audience/scope is **`https://ossrdbms-aad.database.windows.net/.default`**; possessing an Azure identity does NOT grant SQL database role permissions. Npgsql [security docs](https://www.npgsql.org/doc/security.html), [NpgsqlDataSourceBuilder](https://www.npgsql.org/doc/api/Npgsql.NpgsqlDataSourceBuilder.html) and [connection string reference](https://www.npgsql.org/doc/connection-string-parameters) support `UsePasswordProvider(sync, async)`, invoked when a new **physical** connection is opened; a synchronous callback can explicitly reject `Open()` to avoid fallback. `UsePeriodicPasswordProvider` has background token refresh and caching, so timing/expiry must be reviewed before a real app migration. Npgsql 10 defaults to `GSS Encryption Mode=Prefer`, which can take precedence over TLS; pin `GSS Encryption Mode=Disable` and `SSL Mode=VerifyFull`, not `Require`. Neither mock tests nor pure source checks prove live TLS or token acceptance. No new Azure NuGet dependency is introduced in this slice.

## Decision

1. Provide **detached, explicitly opt-in** `TemporalMark.Infrastructure.Postgres.EntraPostgresDataSourceCandidate` under existing Infrastructure project. It builds an `NpgsqlDataSource` via Npgsql 10 `NpgsqlDataSourceBuilder.UsePasswordProvider` with **synchronous callback always throwing `NotSupportedException`** and asynchronous callback calling a caller-supplied trusted `Func<string, CancellationToken, ValueTask<string>>` token supplier. The `string` passed to the delegate is the fixed PostgreSQL Entra scope `https://ossrdbms-aad.database.windows.net/.default`; never derive it from tenant, input, user, DB, URL or caller. The caller must supply a reviewed Azure credential/Managed Identity implementation in a future slice. No token is persisted in connection string, Terraform state, config, logs or disk; do not add Azure SDK/dependencies or use Azure CLI/ambient public dev credential in this candidate.
2. Require an explicit **single Azure PG** `<servername>.postgres.database.azure.com` FQDN (not public/private alias, arbitrary DNS, loopback, public IP, multihost, unix socket), exact `Port=5432`, nonempty explicit canonical `Username` (dedicated reviewed least-privilege Entra SQL role name) and `Database`, no `Password` or `Passfile` field, no `Trust Server Certificate` bypass or client-key, **`SSL Mode=VerifyFull`**, **`GSS Encryption Mode=Disable`**. No fallback to PostgreSQL SQL password even if token request fails. TLS trust chain/SSL Root Certificate file custody and live DNS/private access must be validated on a separately authorized runner.
3. Token supplier invocation is **asynchronous per physical open**. It is caller-supplied (no built-in cache or periodic scheduler), to avoid distributing potentially stale tokens to new connections. The caller's credential library may cache valid tokens internally; it must never return blank/expired/revoked tokens. A blank token or any unexpected supplier error fails with a single **fixed generic exception without inner exception**, avoiding propagation of bearer-token values in exception messages/stack. Preserve explicit cancellation when caller's token is signaled. Do not log tokens or database connection strings. Although Npgsql's callback is used by new physical connections, existing pooled sessions and token revocation/expiry semantics still require real Azure soak/restart/role testing. No claim of instant revoke on sessions.
4. **TDD**: add xUnit positive and negative tests first in existing Provisioner.Tests project (references Infrastructure transitively). Confirm actual CI **RED** on missing type before source implementation, then implement guarded builder/token method with NUnit-free xUnit test fixtures and locked NuGet restore. Test source policy for no API/Provisioner wiring (optional regression) and explicit no password fallback. Use no Azure test account, no real JWT, no DB, no additional dependencies.
5. Do **not change** `src/backend/applications/TemporalMark.Api/Program.cs` existing password-based `NpgsqlDataSource.Create`, provisioning/registrar `NpgsqlDataSource.Create`, the 20 checksummed migrations, Azure Terraform `postgres_password`, Keycloak live tests, REST routes, on-prem deployment or WORM policy. This candidate is not run by the actual applications until approved separate deployment, migration and C# token provider integration. Parent #128/#18 remain OPEN for live Entra-managed identity configuration, SQL principal/grants, real PostgreSQL/TLS connection and time-of-expiry tests, private VNet + DNS, migration runner, zero-password Terraform, historical state custody/rotation, CAB approval and rollback.
6. Complete #130 only on **final docs-inclusive exact main SHA** with all four GitHub CI core jobs backend/frontend/docker-smoke/terraform SUCCESS, combined `temporalmark/ci-4-core-jobs=success`, xUnit true red/green, real PostgreSQL migrations/dump/restore, Keycloak MFA/current role/signed two-tenant API HTTP isolation, privacy log canaries and previous Terraform 59 simulated plan cases. A provider-agnostic detached candidate **is not production ready**, Azure applied, eIDAS/QTSP qualified or evidence-custody safe.

## Scope and legal considerations

A token as a DB password at protocol level is an opaque bearer: no token bytes may be echoed, logged or copied into user-facing exception chains. Fail closed on local invalid configuration. TLS `VerifyFull` ensures hostname+certificate validation only when run against real endpoints and trusted roots; private network reachability/DB role authorizations are NOT established by configuration tests. Keeping the existing password-mode API intact is essential for OSS on-prem and reversible production migration planning; it does not imply the existing Azure server password-in-state issue was fixed.
