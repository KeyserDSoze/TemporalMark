# ADR 0093 — Read-only live Azure Blob Private Link runner preflight (scoped #126)

Status: **Accepted for prequalification tooling**, 2026-11-20. Child [#126](https://github.com/KeyserDSoze/TemporalMark/issues/126); parents [#18](https://github.com/KeyserDSoze/TemporalMark/issues/18), [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) and [#17](https://github.com/KeyserDSoze/TemporalMark/issues/17) remain OPEN.

## Context / reviewed boundaries

ADR 0001 (Azure/on-prem parity), ADR 0090–0092 (private web app, internal ACA environment, private evidence Blob network), `infra/azure/main.tf`, `versions.tf`, mocked Terraform tests, [Azure Blob runbook](../docs/AZURE_EVIDENCE_BLOB_PRIVATE_LINK.md), [THREAT_MODEL](../docs/THREAT_MODEL.md), roadmap and the tracked issue parents distinguish **mocked Terraform configuration** from live deployment. #125 configured public access denial, a Blob Private Endpoint, private DNS link and AAD/RBAC intent but **did not exercise a live Azure resource**. Provisioning `azurerm_storage_container` still uses data plane from an authorized, private-network-reachable Terraform runner.

Microsoft [Storage Private Endpoints](https://learn.microsoft.com/en-us/azure/storage/common/storage-private-endpoints), [Storage networking FAQ](https://learn.microsoft.com/en-us/troubleshoot/azure/azure-storage/blobs/networking/storage-network-security-faq) and [Azure CLI Blob management](https://learn.microsoft.com/en-us/azure/storage/blobs/blob-cli) require client-specific private DNS and separately authorized data-plane access. [Private endpoint connection troubleshooting](https://learn.microsoft.com/en-us/troubleshoot/azure/private-link/troubleshoot-private-endpoint-pending-approval) identifies both Succeeded provisioning and Approved connection state as material. No Azure credentials are available to CI.

## Decision

1. Add an explicit, **opt-in, read-only** Python standard-library operator CLI `scripts/azure_private_blob_preflight.py`, to be invoked manually **on an approved runner inside the intended VNet/private-network path**, after an approved Azure deployment. Require exact `--subscription-id`, `--resource-group`, `--storage-account`, `--private-endpoint` arguments; fixed pilot container `timestamp-evidence` and private-endpoint subnet `blob-private-endpoints`. Never select a subscription implicitly, auto-approve connections or change Azure resources.
2. Query Azure CLI with argument arrays (no shell, no `--debug`) using the runner's active Microsoft Entra identity. Fail closed on missing/malformed account/PE/NIC metadata, wrong subscription, public network enabled, anonymous/Shared Key enabled, HTTPS-only disabled, old TLS floor, non-Succeeded PE, any manual/pending/extra Blob connection, non-Blob group ID, wrong target Storage resource ID, unexpected subnet, ambiguous NIC/IP or DNS resolving to **anything except** the specific Azure PE NIC's IPv4 private IP in `10.40.3.0/24`. Check the **standard** `<account>.blob.core.windows.net` hostname, not a caller-overridden endpoint. Refuse inherited HTTP(S)/ALL_PROXY variables to keep the observed direct-path claim meaningful; corporate proxy routing requires independent redesign and revalidation.
3. After the control-plane and DNS gates, issue a bounded, read-only `az storage blob list --auth-mode login --num-results 1 --output none`, with no keys or SAS, no blob contents, paths or object identifiers in console output. Catch errors with sanitized fail-closed summaries rather than echoing arbitrary CLI stderr. This proves only that this runner's current AAD principal can perform that LIST through its resolved network path. No object is created or removed; no existing evidence object is read by name.
4. TDD: check in positive and negative `unittest` fixtures first, prove actual RED with the missing CLI implementation on GitHub, then add implementation and run actual GREEN in mandatory backend CI. All simulated Azure CLI/DNS fixtures are **not** real Azure connectivity tests. Keep existing Terraform 36 mock plan tests, .NET, Keycloak, PostgreSQL and frontend regressions.
5. Document exact operator invocation, prerequisites, identity / RBAC boundaries, least-privilege and recovery plan, expected success signal and no-leak output. Production external public-denial probes, real Terraform apply/private runner, actual ACA managed identity uploading/downloading evidence, locked immutability, signed external custody, Log Analytics/WAF/DPIA and QTSP/eIDAS trust remain release blockers under their existing issues.

## Non-goals / release stop

No Terraform provider or storage schema changes, no customer documents or hashes, no Azure changes, no new dependency for the OSS on-prem application, no CNAME/endpoint override, no credential provisioning or environment approval. Neither this tool's simulated tests nor a future successful operator invocation prove a legally qualified timestamp or independent durable WORM retention. Close only #126 once the exact final docs-inclusive `main` SHA has all four GitHub CI core jobs and the combined status SUCCESS; keep parent #18 and security/legal blockers OPEN.
