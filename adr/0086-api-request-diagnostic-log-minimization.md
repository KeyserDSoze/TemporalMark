# ADR 0086 — Minimize ASP.NET Core ordinary request telemetry on the API

Status: **Accepted for scoped pilot #119 only**, 2026-11-19. Parent [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115) and [#113](https://github.com/KeyserDSoze/TemporalMark/issues/113) remain OPEN.

## Reviewed context, threat and supported APIs

Reviewed ADR 0001/0004/0005/0082/0083/0084/0085, `docs/THREAT_MODEL.md`, `docs/NGINX_ACCESS_LOG_PRIVACY.md`, `src/backend/applications/TemporalMark.Api/Program.cs`, `appsettings.json` and `appsettings.Development.json`, `docker/compose.yml`, and `.github/workflows/ci.yml`. The shared .NET 10 API binary runs on OSS Docker/on-prem and is referenced by Azure managed Container Apps. Prior #117 covers **web Nginx access logs only**, not API/Kestrel/ASP.NET Core logs.

According to [official .NET 10 HTTP logging docs](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/http-logging/?view=aspnetcore-10.0), HTTP middleware can log request URL/headers/body when enabled; logging flags are selectable and must not be assumed safe. [Microsoft logging categories and filters](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/logging/?view=aspnetcore-10.0) include `Microsoft.AspNetCore.Hosting.Diagnostics` request-start/completion and request/endpoint routing diagnostics. Request URLs with unexpected SHA256 imprints/tokens and query parameters could be captured in container logs independently of Nginx minimization. No customer request body or JWT needs to be placed in infrastructure access logs; authorized searches already have a separate privacy-minimized tenant event in PostgreSQL (#114). The pilot is not qualified eIDAS evidence.

## Scoped decision

1. Add **code-owned**, environment-independent ASP.NET Core logging filters before `builder.Build()`, suppressing **Information and Debug/Trace** ordinary request diagnostics for `Microsoft.AspNetCore.Hosting.Diagnostics` and `Microsoft.AspNetCore.Routing.EndpointMiddleware` and `Microsoft.AspNetCore.Routing.Matching.DfaMatcher`. Preserve Warning/Error for operational faults. Explicitly disable `Microsoft.AspNetCore.HttpLogging.HttpLoggingMiddleware` category and `Microsoft.AspNetCore.HttpLogging.W3CLogger` messages. Register `HttpLoggingOptions.LoggingFields = HttpLoggingFields.None` as defense in depth, but **do not enable `UseHttpLogging` or W3C logging middleware**. Future middleware added to the application must undergo the same explicit privacy test and approval. This does not block logs written by arbitrary libraries, manual `ILogger` calls or exceptions that include caller values, nor privileged operator runtime overrides.
2. Do **not** read, log, copy or summarize `Request.Body`, `Request.QueryString`, Authorization, cookie, referer, agent or raw URL into a log; avoid adding any request middleware. No new cloud service/dependency, SQL migration, logger provider or append-only audit change. Preserve `/healthz`, normal 401/403/400 behavior, the #116 429 gate, the #114 audit-before-response contract and existing Keycloak/SQL tests. The single shared API binary is used on-prem and by Azure, though **real deployed ACA ingress telemetry** remains separately unverified.
3. **TDD:** first add source tests requiring explicit logging categories and a zero-fields HttpLoggingOptions declaration, plus a **real API Docker stdout/stderr test** using only synthetic query/path/referrer/UA/fake bearer and SHA256-shaped search JSON on unauthorized 401, plus an anonymous 404 with sensitive query. Test must not print logs or live credentials and should assert sentinel non-disclosure. Place after API health in docker-smoke, not before the stack starts. Verify an actual RED stage (source-policy failure) before implementation and then green on real container with existing signed Keycloak A/B tests. Configuration remains narrowly scoped to ordinary request logging, not blanket error/error-trace censorship.
4. No claim that the entire API or upstream external logging is privacy compliant: exception detail, DeveloperExceptionPage, Auth/IdentityModel failure warnings, production custom diagnostic exporters, OpenTelemetry agents, Azure Container Apps managed ingress diagnostics and Log Analytics retention, Keycloak, Nginx exceptional error paths, external WAF/CDN/proxies, GDPR DPIA/retention/erasure and immutable custody remain OPEN (#115/#113/#18/#17). Preserve V015/V016 WebAuthn stop lines and `Unverified` pilot timestamp evidence.
