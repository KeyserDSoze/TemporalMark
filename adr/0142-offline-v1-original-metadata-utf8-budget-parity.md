Current **unqualified v1** producer cannot deliver source `HashAlgorithmOid`, `DigestBase64`, `PolicyOid`, `ProviderId` text if **any** field's original UTF8 byte count exceeds **16,384**, nor if their original UTF8 sum across the entire tenant export exceeds **2,097,152**. But Python offline verifier parses the same manifest without checking either field or batch budget. The 8MiB *serialized JSON manifest* and 80MiB compressed outer ZIP are separate caps and do not imply these limits: many repeated ASCII metadata characters compress greatly. An attacker or a legacy ZIP producer can create a well-formed unsigned v1 ZIP with canonical timestamps/IDs/imprint, intact DER/SHA and original nonblank source metadata that the current official server would refuse to export. This is a cross-runtime **local profile/availability consistency mismatch**, not evidence that a qualified TSA was compromised.

## Explicit alternatives rejected and legal stop lines

- **Rely on the ZIP's 8MiB uncompressed JSON alone:** rejected; source metadata can be individually or cumulatively larger than current app's strict pre-wire original text limits yet below JSON cap (and compress very small on disk).
- **Count Unicode characters or normalized JSON bytes rather than original UTF8 source bytes:** rejected; ASCII and multibyte UTF8 impose different byte costs, and .NET/PG17 already admit original text using UTF8 octets.
- **Rewrite or truncate source, relax server budget, add SQL migrations or change ZIP schema:** rejected. These limits are an **operational unqualified pilot profile**, not an RFC3161/eIDAS textual restriction, and strict current-v1 comparison should fail closed without modifying archival originals.
- **Infer legal qualification, complete-period coverage or source authenticity from passing ZIP limits:** false. No RFC3161/CMS signed policy/messageImprint/trust chain revocation/EU Trusted List verification, independent signed WORM chain, lawful indefinite-retention governance, CAB/AgID or qualified eIDAS guarantee has been supplied. A jointly substituted unsigned manifest and DER can still pass internal checks; remain `Unverified`.
