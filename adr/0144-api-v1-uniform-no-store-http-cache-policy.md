# ADR 0144 — Set HTTP no-store for every versioned tenant API response before authentication

**Status:** Accepted, 2026-11-23 Europe/Rome. Scoped security/PWA privacy child [#186](https://github.com/KeyserDSoze/TemporalMark/issues/186), under open #115/#113 (privacy, ingress) and #20 (PWA delivery). Existing API handlers explicitly set `Cache-Control: no-store` only on POST stamp search (success/429), raw TSV/TSR receipt success and 409, ZIP export success and an early oversized search-body error. **GET `/api/v1/me`, `/stamps`, `/stamps/summary`, `/stamps/daily`, `/audit` currently return private identity, tenant-scoped document metadata and audit actor identifiers without a no-store response header**, and several 401/403/400/404/503 error paths are likewise not uniformly protected. This makes the browser HTTP cache and intermediate caches an unnecessary confidentiality risk, even when Workbox has `runtimeCaching: []`: a PWA service-worker's CacheStorage is separate from a browser's HTTP cache, CDN and proxy. This is an observed source policy gap, **not evidence** that any user content has leaked.

Probe authenticated **200** `/me`, `/stamps`, `/stamps/summary`, `/stamps/daily`, `/audit`, existing successful ZIP/receipt/search; probe unauthenticated **401**, verified non-admin/inactive **403**, malformed **400**, known foreign receipt and unmatched API route **404**, unavailable TSA **503**, and existing per-search 429/body 413/receipt 409 tests. Assert **`Cache-Control` includes `no-store` for every `/api/v1` response**. Use fixed sanitized assertion labels only, never JWT, subject, tenant, document imprint, URI/query text, body, raw DER or ZIP in failed logs. ## Explicit limitations and rejected alternatives

- **Only set no-store on successful evidence downloads:** insufficient; subject/organization membership, counts, imprint metadata, audit actors, unauthorized/malformed response bodies may still be persisted when no explicit HTTP caching policy is present. A single versioned protocol boundary is safer than scattered hand-written endpoint headers.
- **Disable browser Workbox offline shell to fix HTTP caching:** wrong layer and breaks legitimate static PWA offline functionality; retain `runtimeCaching: []` and no SPA fallback on API/OIDC/health paths, and independently protect HTTP responses.
- **Claim that no-store erases existing disk caches or governs third-party CDNs/proxies:** false. It instructs compliant caches not to store *future* responses; malicious clients, already-cached responses, browser extensions, operators configuring upstream logs, unmanaged ingress and edge services remain out of scope. Do not equate it with CSP, WORM custody, signed archive completeness, RFC3161/CMS/QTSP/EUTL verification, independent legal retention, CAB/AgID or eIDAS qualification.
