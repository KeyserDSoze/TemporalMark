# ADR 0079 — Tenant-isolated UTC daily dashboard counts with bounded interval

Status: Accepted for a **nonqualified pilot** dashboard increment, 2026-11-18. Child [#110](https://github.com/KeyserDSoze/TemporalMark/issues/110) of the still-open [#14](https://github.com/KeyserDSoze/TemporalMark/issues/14) admin portal, with #17/#20/#13 remaining open.

## Baseline reviewed

Reviewed ADR [0006](0006-tenant-bootstrap-and-admin-integrity.md), existing `ITimestampRegistry` and `TimestampRegistryService.SummaryAsync`, `PostgresTimestampRegistry` query that binds `organization_id=@org`, the ASP.NET Core `/api/v1/stamps/summary` route with `TenantAdminAsync` authoritative signed OIDC and active membership checks, `src/frontend/src/Dashboard.tsx`, IT/EN `i18n.ts`, existing real signed-Keycloak two-tenant PostgreSQL/HTTP harness `tests/integration/api-tenant-isolation.py`, ROADMAP, threat model and [PostgreSQL date/time](https://www.postgresql.org/docs/current/functions-datetime.html) and [Npgsql supported date mappings](https://www.npgsql.org/doc/types/basic.html). The UI already shows an exact per-tenant **total** for the period; the first 50 list records cannot be used to derive an accurate daily series.

## Decision

1. Add a new authenticated `GET /api/v1/stamps/daily?fromUtc=...&toUtcExclusive=...` returning `organizationId`, period boundaries and `days` of `{dateUtc: "YYYY-MM-DD", count: nonnegative-long}`. The tenant ID is **never accepted from query/body/header**. Apply the identical `TenantAdminAsync` trust boundary used by existing summary, and ensure the PostgreSQL aggregation filters **`organization_id=@org`** plus inclusive UTC start/exclusive UTC end.
2. Bounded service input: both period bounds must be **exact UTC midnight** (`Offset=0`, zero time of day), with one through **31 UTC days**. Reject intervals over 31 days or non-midnight bounds with existing HTTP 400 path **before touching the repository**. Reject malicious returned days outside period, duplicate days, nonpositive counts; produce explicit zero-valued dates for gaps. Never infer a daily total from the first page or from cached frontend records. SQL uses one aggregate query grouped by **`(issued_utc AT TIME ZONE 'UTC')::date`**, NOT server-local `issued_utc::date`; read PostgreSQL `date` as `DateOnly` and counts as `long`.
3. Show up to 31 days in the existing React dashboard using accessible chart bars and labelled day/count values, with IT/EN text. For selected periods longer than 31 days, skip the optional daily-series fetch **without failing the existing summary, list, audit and export controls**; show an explicit text explanation. No new npm or chart libraries. A change of period triggers same bearer-authenticated no-store request. All counts mean **registry records**, not qualified legal timestamps, proof of issuance exactly-once or WORM-preserved evidence.
4. TDD: commit ADR first. Add Business xUnit RED-first with fake registry (multi-day, gaps, bounds and hostile replies) and actual two-tenant disposable Keycloak/PostgreSQL HTTP tests (401/403/400, source tenant, spoofed query/header); then interface/service/PostgreSQL/API/React and localized copy. Real Docker smoke against the signed Keycloak fixture is necessary; do not claim it passed just because an xUnit fake did.
5. Close only #110 after exact **final documentation-inclusive `main` SHA** publishes `temporalmark/ci-4-core-jobs=success` and the four core jobs and new test counts are independently inspected.

## Explicit limitations

At most 31 days, no pagination or materialization of evidence bodies for this count. Period counts are **SQL registry aggregate results**, not attested ledger events or completeness proof; a malicious database owner could omit/alter rows and still return internally valid counts. No billing reconciliation, watermark, independent witness, qualified QTSP/EUTL/UTC(k), RLS retrofit, CAB/AgID launch or legal retention is delivered. Existing OIDC fresh-role governance, Azure/on-prem application parity, pilot `Unverified` and WebAuthn V015/V016 registrar stop-line are unchanged.
