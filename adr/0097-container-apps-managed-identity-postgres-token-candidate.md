# ADR 0097 — Detached Azure Container Apps local managed-identity PostgreSQL token supplier candidate

Status: **Accepted for scoped, nondeployed prequalification [#131](https://github.com/KeyserDSoze/TemporalMark/issues/131)**, 2026-11-20. #128/#18 production migration and state secrets remain OPEN. No Azure apply, approval, live identity or SQL database change.

## Baseline and evidence reviewed

Reviewed ADR 0001/0094/0095/0096, `docs/COMPLIANCE.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md`, `docs/DATABASE_MIGRATIONS.md`, `docs/ENTRA_POSTGRES_NPGSQL_CANDIDATE.md`, current API/Provisioner Npgsql password-based startup, the existing Npgsql 10 data-source candidate and 23 tests, the Azure Terraform current API identity block and PostgreSQL SQL admin password, isolated non-applied Entra-only PostgreSQL candidate and all 20 PostgreSQL migrations. Existing Azure API uses system-assigned identity for Blob and user-assigned identity for **Key Vault**; neither grants application SQL login. Current Azure `administrator_password=var.postgres_password` **still enters Terraform state**, including potential historical snapshots.

Microsoft [Managed identity in Azure Container Apps](https://learn.microsoft.com/en-us/azure/container-apps/managed-identity) documents **local** `IDENTITY_ENDPOINT`/`IDENTITY_HEADER`, an HTTP GET token endpoint, `api-version=2019-08-01`, header `X-IDENTITY-HEADER` to mitigate SSRF, and optional `client_id` selecting user-assigned identity (omitting identity selects system-assigned). It recommends Azure.Identity in general but also explicitly documents direct REST. Microsoft [Service Connector PostgreSQL integration](https://learn.microsoft.com/en-us/azure/service-connector/how-to-integrate-postgres) and [PostgreSQL managed identity connectivity](https://learn.microsoft.com/en-us/azure/postgresql/security/security-connect-with-managed-identity) require token resource `https://ossrdbms-aad.database.windows.net` when requesting from a managed-identity **REST** endpoint; the Npgsql callback receives OAuth library **scope** `https://ossrdbms-aad.database.windows.net/.default`. They are intentionally different syntaxes. The local endpoint example returns JSON `access_token`, `expires_on` (Unix epoch seconds, potentially a string), `resource`, `token_type`, `client_id`. Azure identity possession alone does not create/grant PostgreSQL roles. Microsoft [PostgreSQL Entra setup](https://learn.microsoft.com/en-us/azure/postgresql/flexible-server/security-entra-configure) requires Entra DB-principal provisioning by an approved Entra administrator.

## Decision

1. Implement a **detached**, intentionally unused-by-production `ContainerAppsPostgresManagedIdentityCandidate` in existing `TemporalMark.Infrastructure.Postgres` .NET 10 Infrastructure library, consuming no Azure SDK package, shell commands, Azure CLI, `DefaultAzureCredential`, or live Azure endpoint in CI. It exposes `GetTokenAsync(string scope, CancellationToken)` as a drop-in async callback for the previously tested `EntraPostgresDataSourceCandidate.Create` API, but do **not** wire either candidate to API, Provisioner, migrations, Terraform or on-prem. A caller configures an externally independently reviewed **specific user-assigned managed identity client GUID**; never silently use the Blob system identity or the Key Vault secret identity as a SQL principal. Caller supplies local ACA endpoint and header via confidential runtime environment (e.g., `IDENTITY_ENDPOINT`, `IDENTITY_HEADER`) at a future separately authorized rollout. Do not echo header.
2. Require explicit local **HTTP** endpoint URL with host `localhost`, `127.0.0.1` or `[::1]`; explicit port (no implicit 80), non-empty safe path, no userinfo, query, fragment, DNS alias, external/public/link-local IP, Unix socket, TLS downgrade option or caller-controlled URI. Prevent local DNS rebinding: production HTTP transport has a **pinned loopback ConnectCallback** to literal 127.0.0.1 or ::1, does not perform hostname DNS resolution. Disable ambient HTTP proxies, redirects, cookies, compression, automatic credential headers; bound connect/response duration, max response bytes. In unit tests inject a fake `HttpMessageHandler` through an internal constructor with assembly friend access. This is offline simulation, not a proof of live ACA endpoint path/IPv6 compatibility. The code can be rejected by live staging acceptance if the real environment uses a different endpoint shape; do not weaken to arbitrary remote URLs just to make it work.
3. Every call only accepts **exact** OAuth `scope=https://ossrdbms-aad.database.windows.net/.default`, and constructs local ACA HTTP GET with query `resource=https%3A%2F%2Fossrdbms-aad.database.windows.net`, `api-version=2019-08-01`, `client_id=<approved GUID>`. Set `X-IDENTITY-HEADER` from nonblank, bounded, CR/LF-free runtime header, never place header in URL/query. No external tenant/principal/digest controls these values. Reject HTTP redirects and non-200 responses; no retries or fallback to system identity, ambient development credentials or password.
4. Parse bounded JSON without logging raw response or exceptions. Require `token_type=Bearer`, exact response resource, matching `client_id`, one bounded nonwhitespace ASCII access token, `expires_on` Unix epoch integer or numeric string, at least 2 minutes future and no more than 24 hours future based on injected `TimeProvider`. Return token only to Npgsql callback and never persist, cache, print, trace or include it in exception chains. Fake strings in offline tests demonstrate data flow only, not valid JWT signature/audience. In a real deployment, PostgreSQL must validate the issued token; no claim of detecting revocation in active pooled sessions.
5. **Test-Driven Development RED first**: commit xUnit mocks under existing Provisioner.Tests (no new csproj/package) and run GitHub CI on tests-only SHA to prove compilation fails because the provider class is not implemented. Then implement minimum source; fix observed actual runtime errors without weakening tests. Verify negative endpoint/header/scope/client ID, malformed or oversized responses, cancellation, exception redaction, no ambient proxy/redirect/cookies and detached composition with #130. Test the real CI, all original 59 Terraform mocked plans, Docker PostgreSQL/Keycloak/TOTP/PKCE/HTTP tenant isolation and frontend. No HTTP requests to Azure in CI.
6. Parent #128/#18 remain OPEN: no real Azure Container Apps token acquisition, user-assigned DB identity attachment, SQL role creation/grants, private PostgreSQL TLS CA chain or DNS, least privilege, credentials or token expiry/refresh verified; no API/CLI/migration integration, no state/history cleanup or rotation of `postgres_password`, no CAB-approved DR/cutover. Azure.Identity remains a reasonable future alternative under separately reviewed NuGet lock/update, but not added as a mandatory on-prem dependency here. Do not claim GDPR-DPIA, WORM, independent signed evidence, eIDAS qualification or production readiness.
