# ADR 0075 — Bound synchronous ZIP export input DER byte budget

Status: Accepted for **limited in-memory export resource hardening**, 2026-11-18. [#106](https://github.com/KeyserDSoze/TemporalMark/issues/106), child of still-open WORM/evidence [#17](https://github.com/KeyserDSoze/TemporalMark/issues/17).

## Reviewed baseline

Reviewed [ADR 0004](0004-evidence-time-and-retention.md), [ADR 0074](0074-registry-page-export-integrity-and-unique-ids.md), `TimestampRecord.Validate`, `TimestampRegistryService.ExportZipAsync`, `ITimestampRegistry.ForExportAsync`, the Postgres tenant-scoped registry, existing `TimestampRegistryServiceTests`, authenticated `/api/v1/stamps/export` route, [registry integrity runbook](../docs/REGISTRY_INTEGRITY_READ_GATES.md), the compliance gap register, roadmap and threat model. The synchronous export currently takes at most **10,000** stored rows then buffers a `ZipArchive` in a `MemoryStream` for a single HTTP reply. It verifies org/UTC window, DER SHA-256 and unique IDs, but **does not bound how many raw DER bytes** can be fed to ZIP. Even if each new delegated TSA response is capped at **1 MiB** elsewhere, legacy/corrupted database contents can exceed that, and 10,000 * 1 MiB approaches 10 GiB of source data. A row cap is not a memory cap.

## Decision

1. Explicitly cap a **single retained `ResponseDer` exported into the synchronous ZIP at 1,048,576 bytes (1 MiB)**, matching the existing external provider limit; cap **total source DER lengths across all exported rows at 67,108,864 bytes (64 MiB)**. These are conservative operational constraints for the existing synchronous endpoint, *not* legal timestamp/token size requirements and not the final export-service SLA.
2. After the existing `ExportLimit+1` query and record-count check, validate source byte budgets **before ZIP/manifest allocation**. Perform the byte-budget pass before local hash checks to avoid hashing obviously oversized records. Keep tenant/period/duplicate and `TimestampRecord.Validate()` validation, and use a `long` accumulator with overflow-safe guarded subtraction or checked accumulation. Reuse `ExportTooLargeException`, already mapped by the API to HTTP 413; update its generic operator message to cover both record and byte budgets without disclosing internal data. An empty export and accepted on-boundary 1 MiB receipt remain supported.
3. RED-first in-memory xUnit: reject one oversized (1MiB +1) retained DER, and an aggregate of 65 distinct 1MiB receipts (>64MiB) where each row is individually allowed; assert no ZIP response. Reuse the same test-only DER buffer across independent record IDs to avoid allocating 65MiB in test runner; ensure stored SHA-256 remains consistent, so **only the new budget** causes rejection. Positive test verifies accepted 1MiB receipt and its ZIP content. No tests require a real TSA.
4. Implement only in business service: no SQL schema, authorization, route, provider, DTO or platform-specific changes. Update README, registry operator runbook, threat model and roadmap. **Close only after the actual exact final docs-inclusive main SHA passes 4/4 original GitHub CI jobs** and source/test logs are inspected; older runs cannot attest later commits.

## Residual risk / compliance stop line

This guards **source DER bytes before synchronous ZIP construction**, not memory already used by `NpgsqlDataReader` materialization, ZIP compressed output size, compression-bomb effects on independent extractors, concurrent export volume, ingress abuse, temporary memory duplication during `ToArray()`, or complete cross-page snapshot/coverage. Limit violations return 413 instructing a smaller time window; they are **not evidence that the selected period was fully exported**. A scalable audited streaming/asynchronous export with authenticated manifest/signatures, WORM object lock/legal hold, independent retention/witness, issuer-certificate provenance, GDPR review, historical QTSP status and CAB/AgID qualification remain OPEN #17/#15/#13. Pilot records are always `Unverified`; WebAuthn/registrar SQL V015/V016 remains frozen.
