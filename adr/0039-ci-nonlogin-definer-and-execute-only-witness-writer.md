# ADR 0039 — Non-login definer and EXECUTE-only CI PostgreSQL witness writer

Status: **accepted for non-authorizing synthetic CI access separation ONLY**, 2026-11-16; focused [#70](https://github.com/KeyserDSoze/TemporalMark/issues/70) child of still-open #64/#61. Reviewed ADR 0032–0038, existing separate `witness-ci` PostgreSQL 17 init SQL, xUnit full logical main DB restore, `docs/MDS_CRL_SEPARATE_POSTGRES_WITNESS_TEST.md` and official PostgreSQL 17 [SECURITY DEFINER](https://www.postgresql.org/docs/17/sql-createfunction.html), [role/object privileges](https://www.postgresql.org/docs/17/ddl-priv.html) and [default function privileges](https://www.postgresql.org/docs/17/sql-alterdefaultprivileges.html).

## Problem

The #69 synthetic latest-seal SQL writer was owner-only but invoked with the **witness database superuser account**. A single compromised writing client could bypass the monotonic update function, replace whole checkpoint/audit tables or restore the witness volume. Even in test-only code, exercising a least-privilege writer and a separate non-login function/table owner is a valuable security regression. It does **not** remove the superuser's authority or establish off-host immutable custody.

## Decision

1. In the **CI-only** witness database bootstrap transaction, provision `temporalmark_witness_data_owner` (NOLOGIN, NOSUPERUSER, NOCREATEDB, NOCREATEROLE, NOREPLICATION) and `temporalmark_witness_writer` (LOGIN with a **disposable CI-only password**, NOSUPERUSER/NOCREATEDB/NOCREATEROLE/NOREPLICATION). The writer must not be a member of data_owner, witness DB superuser or the read-only reader role.
2. Reassign ownership of the witness checkpoint and append-event tables, including the owned identity sequence, and the `record_unapproved_highwater_witness(text,bigint,text)` routine to the non-login `data_owner`. Invoke the routine only as a **SECURITY DEFINER** (executing with that non-login owner's restricted table rights). Fully qualify `public.` table objects and set the routine `search_path=pg_catalog,pg_temp`; avoid untrusted schema resolution and dynamic SQL. Restrict the routine to exact validated 64-character uppercase SHA256, positive serial, atomic `ON CONFLICT DO UPDATE ... WHERE new > old`, same-tx append-event insert. Reject stale/equal/equivocated data. No implicit recovery/reset or WORM guarantee.
3. **In a single SQL bootstrap transaction** prevent PostgreSQL's default `EXECUTE` to `PUBLIC` from ever exposing a definer function before revocation. Also `REVOKE ALL ON DATABASE temporalmark_witness FROM PUBLIC` to block implicit TEMPORARY and CONNECT grants for non-authorized roles. Grant only `CONNECT` and schema `USAGE` to writer and reader; `EXECUTE` on the one function to writer; `SELECT` on one latest-checkpoint table to reader. Keep event table and sequence inaccessible. Test inability to write/read/drop/truncate tables, set owner role, create temp/schema objects or use owner privileges.
4. The separate read-only .NET witness reconciler enforces the new *physical table owner* `temporalmark_witness_data_owner`, exact witness DB/reader roles and absence of any writer/SQL DDL grants. It continues to validate original signed seal + manifest via ADR 0033/0034; returns only `UNAPPROVED/SEPARATE_TEST_POSTGRES_WITNESS_NO_IMMUTABLE_CUSTODY`. It is not activated in application/registrar/approver, and no trust root or JWS/CRL validation is introduced.
5. **TDD:** commit ADR then RED real PostgreSQL integration test opening a separate writer account and asserting direct-write denial/owned-function execution. No writer account exists until GREEN; RED CI must demonstrate failure at real Docker integration. Then implement solely in the CI-only SQL/bootstrap, Compose test config and .NET owner identity test. Re-run required live full logical `pg_dump -Fc/pg_restore`, differential two-cluster testing, PostgreSQL V017 security, OIDC/Keycloak MFA. Close ONLY #70 if all 4 exact-final `main` CI jobs are GREEN.

## Explicitly unresolved production security

The CI host superuser **still controls both PostgreSQL volumes, database contents, credentials and disposable test signing keys**; it can directly overwrite or restore the whole witness service, change the definer function or impersonate the writer/reader, so the latest version is **not independently immutable**. Security definer does NOT equal an approved external authority. No production HSM, independent CAB key ceremony, attested trusted signer root, offsite append-only/WORM store, inter-region quorum, physical WAL/PITR, shared transaction atomicity or on-prem OSS/Azure production witness parity is supplied. Parent #64/#61/#57/#55/#53/#44/#50/#46/#38 remain OPEN; unverified FIDO R46 MDS JWS/x5c+CRL/OCSP and actual reviewer-held WebAuthn enrollment remain blocked. V015/V016 issuance freeze and suspended registrar CLI remain unchanged. No eIDAS/QTSP/WORM qualification claim.
