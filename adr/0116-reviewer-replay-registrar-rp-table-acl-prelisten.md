# ADR 0116 — Deny direct runtime SQL access to reviewer replay proofs, registrar intent and owner-pinned RP policy at Entra prelisten

Status: **Accepted for scoped test-first PostgreSQL permission drift screening [#151](https://github.com/KeyserDSoze/TemporalMark/issues/151)** on 2026-11-21. Parents #128/#18 real Azure Entra SQL, #14 tenancy, #38 reviewer-held signed consent, #50 registrar bypass, #17 custody/WORM and #13/#15 eIDAS/QTSP remain OPEN. No Azure SQL provisioning or legal qualification.

## Source, previous decisions, and official SQL semantics

Reviewed ADR 0009/0015/0016/0099/0100/0114/0115; `docs/POSTGRES_RUNTIME_PRIVILEGE_PREFLIGHT.md`, `docs/API_POSTGRES_ENTRA_PRELISTEN_CANDIDATE.md`, `docs/OPERATOR_PROVISIONING.md`, `docs/DATABASE_MIGRATIONS.md`, `docs/THREAT_MODEL.md`, `docs/ROADMAP.md`, current `PostgresRuntimePrivilegePreflight.cs` and real PG17 `PostgresRuntimePrivilegePreflightTests.cs`. Existing immutable V010 creates `public.organization_reviewer_decision_proofs`: token SHA256 digest, request_id, terminal APPROVED/REJECTED type, timestamp, protected by unique columns and a SECURITY DEFINER replay-consumption trigger on V006 enrollment; no direct API runtime ACL. V013 creates `public.reviewer_registration_intents` with issuer, reviewer/registrar subject, 48-byte **unconsumable** nonce, short TTL, and `public.reviewer_registration_rp_policies` with the migration-owner pinned issuer and exact HTTPS RP identity/origin; V013 explicitly REVOKEs these tables from PUBLIC and the runtime, reviewer, provisioner and registrar groups. V015/V016 keep the legacy registrar path SUSPENDED / SQL-owner only; no verified WebAuthn registration, trust or signed human decision is implied.

The opt-in Production `ContainerAppsEntraCandidate` API's one existing read-only catalog prelisten check denies direct runtime rights on V006/V012 and elevated functions, but does not query effective ACL on the above **three owner-controlled tables**. A hypothetically over-granted per-login, inherited or PUBLIC table/column SELECT (e.g. the replay hash or nonce) or mutation/trigger privilege could pass the prelisten check independently of SQL group-membership restrictions. This does **not** prove actual Azure misuse.

Official [PostgreSQL 17 access privilege inquiry](https://www.postgresql.org/docs/17/functions-info.html), [GRANT syntax](https://www.postgresql.org/docs/17/sql-grant.html) and [column privileges](https://www.postgresql.org/docs/17/infoschema-column-privileges.html) describe `pg_catalog.has_any_column_privilege` as detecting effective table-wide or *any single column* SELECT/INSERT/UPDATE/REFERENCES, while `has_table_privilege` covers DELETE/TRUNCATE/TRIGGER. PostgreSQL owner/DDL powers cannot be revoked through these ordinary SQL ACL checks.

## Decision and required RED → GREEN

1. **Commit ADR first to `main`**, then commit tests only (production SQL preflight remains unchanged until genuine RED). Add **27** fixed-parameter real PostgreSQL 17 xUnit cases to the existing disposable-LOGIN preflight fixture (nine per owner-only table): direct table `SELECT`, one-column `SELECT`, direct table `INSERT`, one-column `INSERT`, one-column `UPDATE`, `REFERENCES` on a fixed key column, `DELETE`, `TRUNCATE`, `TRIGGER`. For each case, create a unique disposable LOGIN in `temporalmark_runtime_group` only and `Pooling=false`; baseline preflight passes; grant exactly one unsafe right **to that LOGIN only**; require generic, no-inner, no-identity/credential error on second preflight. `finally` must revoke the direct grant and membership and drop the LOGIN even on expected RED. Never SELECT real reviewer rows or modify reviewer/registrar rows; no privileged routines invoked. Require real GitHub Docker PG17 **27 expected missing-denial failures and 173 prior passing tests / 200 total**. Compilation, connection, test cleanup or SQL GRANT syntax failures are not valid TDD RED.
2. Only after confirmed RED add exactly **21 fixed, read-only effective ACL predicates** to existing already-open-session `PostgresRuntimePrivilegePreflight.Sql` query. For all 3 owner-only surfaces deny direct table-or-any-column `SELECT`, `INSERT`, `UPDATE`, `REFERENCES` using `NOT pg_catalog.has_any_column_privilege` and deny table `DELETE`, `TRUNCATE`, `TRIGGER` using `NOT pg_catalog.has_table_privilege`. Keep all current SQL login/group, function, application data, quota and privileged role denials, and intentional V019 runtime `public.consume_imprint_search_rate(uuid,text)` EXECUTE. Do not rewrite any migration, GRANT, SQL owner or owner data, API route, on-prem Password-mode default, privileged CLI, active Azure Terraform or PostgreSQL connections.
3. Update this ADR and operator, Entra, migration, threat and roadmap documents with real RED and GREEN evidence. Close scoped #151 only after independently checking exact final docs-inclusive current `main` SHA's GitHub CI **backend/frontend/terraform/docker-smoke 4/4**, ci-verdict and aggregate `temporalmark/ci-4-core-jobs=success`. Real PG17 **200/200**, 20 immutable migrations/checksums, full logical `pg_dump/pg_restore` test-only sealed witness (not legal custody), real Keycloak registrar/reviewer TOTP/PKCE, 2-tenant signed HTTP 401/403 and Nginx query/log/413/414/429 privacy regressions must pass.

## Stop line

This is a one-time PostgreSQL catalog ACL sanity check **only** for explicitly configured Production `ContainerAppsEntraCandidate` API startup before HTTP binding. It cannot stop later GRANT changes, DDL/owner bypass, authorize a registrar or WebAuthn reviewer, prove independent signature or preserve legally WORM evidences. Default OSS on-prem and current Azure `Password` mode and privileged CLIs are unchanged. Azure non-admin Entra UAI SQL role configuration, historical Terraform password state remediation/CAB, actual trusted registration/independent reviewer proof, WORM/custody and qualified timestamp issuer verification remain unresolved #128/#18/#50/#38/#17/#13/#15.
