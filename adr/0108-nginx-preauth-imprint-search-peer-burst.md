# ADR 0108 — Scoped, privacy-preserving Nginx pre-auth anonymous search burst gate

Status: **Accepted only for scoped shared-web-image hardening [#143](https://github.com/KeyserDSoze/TemporalMark/issues/143)**, 2026-11-21. Open parents #115/#113 and #18 remain release blockers; #17 WORM and #13/#15 legal/eIDAS qualification remain open. No real Azure ingress/production configuration, DPIA approval, globally distributed rate limit or qualified custody.

## Baseline and threat

Reviewed ADR 0001 (identical portable OSS/Azure application), ADR 0082 privacy-minimized search audit, ADR 0083 shared PostgreSQL atomic **post-authorized** 12 per actor / 30 per tenant UTC-minute search admission, ADR 0084 access-log minimization, ADR 0102 independent Nginx+Kestrel 4096-byte pre-auth search body limits and confidential Nginx 413 error path; docs/COMPLIANCE, IMPRINT_SEARCH_RATE_LIMITING, IMPRINT_SEARCH_BODY_BUDGET, NGINX_ACCESS_LOG_PRIVACY, THREAT_MODEL and ROADMAP; current shared frontend `src/frontend/Dockerfile`, `docker/nginx.conf.template`, HTTP-scope `docker/nginx-privacy-logs.conf`, `docker/compose.yml`, `.github/workflows/ci.yml` and real web/API Python privacy probes. The existing atomic SQL quota is intentionally reached only after a **valid signed JWT and current PostgreSQL tenant-admin gate**, so a bot sending fake Authorization headers can consume Nginx/upstream authentication resources without using SQL quota. At present the Nginx image caps a search JSON body to 4096 bytes, logs only status/method/duration and uses a sensitive-route `error_log ... crit`, but does **not** bound anonymous *request frequency*. The Azure managed ingress and direct Kestrel port are independent trust boundaries.

Official Nginx [ngx_http_limit_req_module](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html) documents `limit_req_zone` in **http** scope, `limit_req` at **location** and `limit_req_status`; `$binary_remote_addr` is the actual directly connected network peer and is not client-supplied `X-Forwarded-For`. [Nginx `proxy_intercept_errors`](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_intercept_errors) normally defaults to off, preserving upstream HTTP errors. [Nginx `error_page`](https://nginx.org/en/docs/http/ngx_http_core_module.html#error_page) can pass a *locally generated* 429 to a fixed named location without revealing the original request URI to the client.

## Decision

1. Implement exactly one **fixed, local, coarse pre-auth burst limiter** inside the **same pinned shared Nginx image** in OSS Compose and referenced Azure frontend Container App. HTTP-scope `limit_req_zone $binary_remote_addr zone=tm_search_peer:1m rate=2r/s;` in the existing `docker/nginx-privacy-logs.conf` file; only the existing exact-match `location = /api/v1/stamps/search` uses `limit_req zone=tm_search_peer burst=12 nodelay;`, `limit_req_status 429;`. The capacity is a pilot safe default, not a regulatory or SLA value. Nginx shares the bounded zone among workers of a **single container**, never across Nginx replicas/regions. Do NOT use forwarded header, tenant ID, JWT principal, digest, query/body/cookie, request line or dynamic configuration in the zone key. An external load balancer can aggregate independent legitimate users into one `$remote_addr`; deployment owners must review trusted edge topology before enabling this as a real production control. Never claim globally distributed identity throttling.
2. Return local denial with generic status **429**, **`Retry-After: 1`** and **`Cache-Control: no-store`**, and no matches/tenant/digest/error detail. Use an internal named error handler for Nginx-generated 429; keep `proxy_intercept_errors off;` on the upstream proxy location so existing **authenticated** PostgreSQL 429 with its server-calculated Retry-After (1–60s) remains unchanged. Keep the exact Nginx route `client_max_body_size 4k`, `error_log /dev/stderr crit`, existing proxy headers, one server-level `access_log ... temporalmark_minimal` and unchanged other API/PWA routes. Suppress request-line-bearing error diagnostics in the local named 429 handler as well; operators must accept reduced incident detail. Do not enable global server-level rate caps and do not modify direct API/Kestrel.
3. **TDD RED-first with live Docker**: commit a new independently guarded Python probe to `tests/integration` and add only its docker-smoke CI step before production changes. Send synthetic 64-character SHA256-shaped text and fake JWT from the CI fixed loopback to both direct API and Nginx. After confirming ordinary unauthenticated small search remains HTTP 401, burst many concurrent anonymous Nginx POSTs while rotating forged `X-Forwarded-For` and require some HTTP 429, correct generic no-store/retry headers, zero sensitive echo, minimal `tm_access` 429 line and no fake URL/bearer/query/body canary in actual web-container stdout/stderr. Direct API remains HTTP 401 and unrelated issue POST/SPA/health are not throttled. Real Docker RED should fail because **the existing proxy returns only 401**. After that, implement minimal two-config change; add mandatory source policy test plus backend CI hook, update docs.
4. Keep V018 privacy-minimized audit, V019 PostgreSQL actor/tenant quota and V020 owner-only cleanup, all immutable migrations, OIDC active tenant-admin and SQL 401/403/429 contracts, on-prem API path, existing Terraform and Azure deployment **unchanged**. Adding this limiter does not make any backend endpoint safe when direct API is exposed; separately approved firewall/private ingress controls #115/#18 still required. No reliance on Nginx as proof of authentication, legal WORM, independent custody, DPIA-approved tracking or QTSP qualification.

## Residual risks and closure

This is per-instance, *network-peer* best-effort, pre-auth input throttling only: no cross-pod/global counter, no trustworthy client-address recovery behind an unapproved proxy, no botnet/IPv6-prefix defense, no TCP connection/body-read time budget, no direct API/ACA managed edge throttle, no Azure Log Analytics ingress/private error log inspection, no approved retention or DPIA, no guarantees for authenticated SQL-backed search or full eIDAS custody. Keep #115/#113/#18/#17/#13/#15 OPEN. Close only scoped #143 after exact final docs-inclusive main SHA success of backend/frontend/terraform/docker-smoke, reporting ci-verdict and `temporalmark/ci-4-core-jobs=success`, with real Docker 429 privacy regression, PostgreSQL 20 migrations/restore, Keycloak registrar/reviewer MFA and two-tenant signed 401/403/SQL 429 tests.
