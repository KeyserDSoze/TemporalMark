# ADR 0087 — Pin Azure application images to immutable OCI SHA-256 manifests

Status: **Accepted for scoped pilot #120 only** (2026-11-20). Parent [#18](https://github.com/KeyserDSoze/TemporalMark/issues/18), security [#115](https://github.com/KeyserDSoze/TemporalMark/issues/115)/[#113](https://github.com/KeyserDSoze/TemporalMark/issues/113) remain OPEN.

## Reviewed baseline and threat

Reviewed [ADR 0001](0001-architecture-and-deployments.md), [ADR 0084](0084-minimized-nginx-imprint-search-access-log.md), [ADR 0086](0086-api-request-diagnostic-log-minimization.md), docs/THREAT_MODEL.md, docs/API_LOG_PRIVACY.md, docs/NGINX_ACCESS_LOG_PRIVACY.md, infra/azure/main.tf, variables.tf, terraform.tfvars.example, README and existing GitHub four-job CI. Terraform reference template currently accepts arbitrary strings in `var.api_image` and `var.web_image`, and example variables contain mutable `:tag` images. The deployed Azure workload could silently change under the same tag without using the API and Nginx images tested in #117/#119. It is not sufficient to independently verify only their local Docker test outputs.

An OCI image **manifest digest** references content by hash rather than relying on a mutable tag; see [OCI registry reference concepts](https://oras.land/docs/concepts/reference/) and [OCI distribution spec](https://specs.opencontainers.org/distribution-spec/). Use [HashiCorp variable validation](https://developer.hashicorp.com/terraform/language/block/variable) and [Terraform plan-only tests with mock providers and expected failures](https://developer.hashicorp.com/terraform/language/tests) (Terraform >=1.8). The [Azure Container Apps provider](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/resources/container_app) accepts an image string. Azure Portal client-side digest input behavior has had reported [compatibility bugs](https://github.com/microsoft/azure-container-apps/issues/1707); no actual Azure deployment success is inferred from Terraform tests.

## Scoped decision

1. Make both `api_image` and `web_image` **mandatory OCI SHA-256 digest references** via Terraform input validation. Accept canonical lowercase `registry/repository@sha256:<exactly 64 lowercase hex>` with no tag component, whitespace, extra `@` delimiter or trailing characters. A registry host with optional numeric port is allowed. Use a bounded-enough syntax gate for this reference template, not a complete standalone OCI parser, and do not accept mutable `:tag` or unspecified digest.
2. **TDD RED then GREEN:** first add tests in `infra/azure/tests/image_pins.tftest.hcl` using `mock_provider "azurerm"` with `run ... command=plan`, synthetic local variables, explicit success for both valid digest refs and `expect_failures` for invalid API and web values. Run the tests in the Terraform CI core job **after** `init` and `validate`. No Azure account, state file, real credentials, key material, secrets, network apply or resources are required; all fixtures are fictional.
3. Update the checked-in Terraform variables example to **obviously fake** 64-character digests, not real manifest references. Operators must build, scan and approve API/web images, derive digests from the approved registry after publish (not hand-invent), confirm architecture-specific manifest/index selection, record exact digest and linked CI/source revision in the controlled release register and run `terraform plan` with the approved parameters. Changing a digest is a reviewed rollout, not a tag retargeting. Do not expose image pull secrets in `terraform.tfvars` or logs; existing reference still lacks an audited ACR/identity pull mechanism.
4. Keep existing on-prem OSS build and development Docker Compose unchanged, and retain same application behavior on both deployment modes. Do not add Azure-only runtime dependency, registry network calls, SQL migration or authentication changes.

## Explicit remaining gates

A digest ensures the *named content reference*, not publisher identity or its safety. **No OCI signing/verification, SBOM provenance binding, vulnerability admission policy, actual Azure pull success, regional failover, immutable artifact repository or CAB release approval** is delivered here. Multi-architecture indexes require separately reviewed platform compatibility. Azure managed ingress/log analytics privacy, WAF, Key Vault/Managed Identity, legal GDPR retention and #115/#113 controls remain open. Azure production parent #18, WORM custody #17, qualification #13/#15, V015/V016 registrar interlocks and `Unverified` pilot evidence status remain unchanged.

## Closure gate

Only close child #120 after independently verifying the exact documentation-inclusive `main` commit SHA has all four core CI jobs SUCCESS, especially Terraform plan-only mock provider negative and positive tests proving invalid tag/unknown digest rejection and valid pinned refs; inspect actual runner logs. Do not treat `terraform validate` alone as sufficient evidence, since it does not evaluate run-time variable values.
