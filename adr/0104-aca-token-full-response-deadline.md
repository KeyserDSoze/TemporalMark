# ADR 0104 — Bound the complete ACA local managed-identity token response lifetime (headers AND body)

Status: **Accepted for scoped offline security fix [#139](https://github.com/KeyserDSoze/TemporalMark/issues/139)**, 2026-11-21. Parent [#128](https://github.com/KeyserDSoze/TemporalMark/issues/128) and Azure [#18](https://github.com/KeyserDSoze/TemporalMark/issues/18) remain OPEN. No live Azure, SQL grant, secret rotation, CAB deployment, or qualified-evidence claim.

## Existing evidence and threat

Reviewed ADR 0001 (shared on-prem/Azure modular .NET 10 architecture), ADR 0097 (local ACA managed-identity supplier), ADR 0100 (nondefault API Entra opt-in and SQL pre-listen gate), ADR 0103 (duplicate JSON response property denial), `docs/COMPLIANCE.md`, `docs/THREAT_MODEL.md`, `docs/AZURE_CONTAINER_APPS_POSTGRES_IDENTITY_CANDIDATE.md`, `docs/API_POSTGRES_ENTRA_PRELISTEN_CANDIDATE.md`, the real `ContainerAppsPostgresManagedIdentityCandidate.GetTokenAsync` and in-memory xUnit tests. The current supplier constructs `HttpClient` with `Timeout = 10s`, then calls `SendAsync(..., HttpCompletionOption.ResponseHeadersRead, cancellationToken)` and streams a 32 KiB-bounded JSON body using only the *caller* token. A hostile or faulty same-container local identity endpoint could send HTTP 200 headers immediately and stall the body indefinitely when the caller token has no deadline; response-size bounds do not bound connection occupancy. A ten-second initial `HttpClient.Timeout` alone **does not cover the later body read**.

Microsoft [.NET HttpCompletionOption documentation (net10)](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpcompletionoption?view=net-10.0) explicitly warns that `HttpClient.Timeout` with `ResponseHeadersRead` applies only until the end of headers and the content read must be timed out separately. [Microsoft Azure Container Apps managed identities](https://learn.microsoft.com/en-us/azure/container-apps/managed-identity) documents the local identity token REST response but does not certify end-to-end response deadlines. Never conflate mock endpoint behavior with actual Azure.

## Decision

1. Enforce one **fixed production 10-second overall monotonic token-request deadline**, beginning before outbound local ACA `SendAsync` and covering *both* receiving headers and streaming the **entire** already-bounded JSON response, including intermittent dribbled bytes. Use a linked `CancellationTokenSource.CreateLinkedTokenSource(callerCancellationToken)` with `CancelAfter(10s)`, pass its token to **both** `SendAsync(ResponseHeadersRead)` and `ReadBoundedResponseAsync` / `ReadAsStreamAsync` / `Stream.ReadAsync`. Do not restart/reset deadline after headers, each byte or token parsing. Keep the existing 10s HttpClient timeout as an independent headers-stage bound, and the 3s connect timeout. No arbitrary Azure network destinations or relaxed TLS, proxy/redirect/cookie restrictions.
2. An **explicit caller cancellation** still throws `OperationCanceledException`, preserving the existing contract. The internally expired overall deadline (or any other transport/JSON error) must **fail closed** through the existing fixed, generic `InvalidOperationException` with **no inner exception** and no raw bearer, `IDENTITY_HEADER`, URI, response, SQL role or hostname in any message. Do not retry/fall back to ambient credentials, SQL password, a previously used token or partial JSON. On timeout, dispose response and HTTP request normally; no background work or cache.
3. Add only one **internal test-factory deadline parameter** for deterministic, fast fake-handler xUnit tests (strictly positive and at most 10 seconds). Do **not** expose an operator/HTTP/tenant-controlled production deadline: the public factory and real API always use fixed 10 seconds. Use the real system monotonic cancellation timer rather than injecting wall-clock `TimeProvider` intended only for checking token expiry.
4. **TDD RED before GREEN:** after this ADR, commit xUnit tests to `main` with in-memory `HttpMessageHandler`, a fake HTTP 200 + correct JSON Content-Type with a content stream whose `ReadAsync` waits indefinitely *until cancellation*, verify short test-only overall deadline fails generically, does not leak canaries, sends once and does not wait 10 real seconds. Include slow headers, caller cancellation while streaming (must propagate rather than generic timeout), success/unique optional field, and invalid test-only deadline validation. Prove actual GitHub backend RED on that test-only commit **before** production source changes; then smallest implementation plus complete CI. Keep all 20 immutable migrations and no NuGet/Terraform changes.
5. Update ACA identity token operator runbook, ROADMAP and THREAT_MODEL; preserve explicit pilot limitations. One offline streaming deadline test is **not** a real cloud token, Entra principal/SQL privilege proof, token-pool cancellation assurance, live Azure network or compliance certification.
