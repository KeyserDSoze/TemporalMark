**Status:** Accepted on 2026-11-24 for focused [#187](https://github.com/KeyserDSoze/TemporalMark/issues/187) under still-open security/resource #115 and delegated QTSP #15. Applies on-prem OSS and Azure **same application code**; not an eIDAS, production WAF or signed CMS qualification.

The **only** valid current unqualified delegated issuance API input is `POST /api/v1/stamps/issue` JSON `digestBase64` representing a canonical 32-byte SHA256, necessarily **44 ASCII chars** (ADR 0072). The upstream trusted request generates its **own** signed-message RFC3161 nonce; the user cannot select provider, policy or signed key. However, the endpoint has no request-body cap equivalent to the separate strict **4,096 bytes** search POST pre-auth gate from ADR 0102. An attacker can add a large, otherwise irrelevant JSON padding property that is parsed before the business 44-char validation. Even without a usable provider, large bodies consume gateway or server resources unnecessarily; this is a pre-auth/authorized resource-policy inconsistency, not evidence of a real attack.

**Explicit newer scope supersession:** ADR 0102 correctly said the *#136 search-specific change* must not cap `/stamps/issue` or other POSTs. This accepted ADR now makes a **separate scoped decision for issuance only** with its own real RED-first regression. It does **not** change the earlier search route's 4096-byte rule, rate limits, private audit or return/status semantics.

## Rejected alternatives, supported limits

- A validation check *inside* `TimestampIssueService` on just `digestBase64`: already implemented under ADR 0072, but **after** HTTP model binding/whole body parsing and not a request-body size guard. It does not prevent large ignored JSON properties, unknown-length chunked inputs, or unauthenticated declared-large bodies at the Kestrel boundary.
- A generic Kestrel/Nginx global 4KiB limit: would inadvertently break other endpoints and future evidence upload/metadata routes; keep exact versioned issuance and search only.
- Rely on `Content-Length` alone: chunked/unknown-length HTTP must trigger enforced Kestrel read-size bound.
- Assume the 4KiB bound secures the whole ingress or ensures RFC3161 qualification: false. A third-party edge, Nginx buffered body, distributed DoS/billing/replay, signer CMS/policy/EUTL, independent WORM and AgID/CAB/eIDAS remain unproven; every locally stored delegated timestamp stays `Unverified`.
