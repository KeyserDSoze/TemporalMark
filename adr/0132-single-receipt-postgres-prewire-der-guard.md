## Gap and narrow decision

`FindByIdAsync` presently selects original `response_der` and `MapRecord` immediately calls `GetFieldValue<byte[]>(9)`, **before** Business can reject an authorized SHA-consistent >1 MiB legacy row using `ReceiptTooLargeException`. Tenant and exact requested receipt ID are already parameterized SQL predicates; no demonstrated cross-tenant disclosure exists. The gap is unnecessarily large PostgreSQL result/wire and Npgsql materialization for a single invalid receipt.

1. Commit this ADR **before tests/source**. Add real disposable PostgreSQL17 xUnit tests against `PostgresTimestampRegistry.FindByIdAsync`, each with unique synthetic organization IDs and server-generated SHA-consistent bytes. A tenant-owned 1,048,577-byte receipt must throw the preexisting fixed-message **`ReceiptTooLargeException` directly at the repository boundary**, not just when passed to Business. Exact 1,048,576-byte, normal small intact bytea and valid exact ID must return unmodified content; absent and foreign IDs must return `null` (404 at HTTP), even if another tenant has an oversized row; Business independently verifies raw DER/hash and pilot `Unverified`. Assert generic errors contain no org/record/digest/fixture data. Confirm **genuine GitHub Actions tests-only RED** due specifically to missing provider denial before source change. Retain real signed-Keycloak A 409/no-store and zero `receipt_download_prepared` for oversized, B 404, and normal A/B 200 original raw DER with exactly one prepared audit per successful download.
2. Only after RED, change **one** parameterized `FindByIdAsync` SELECT, preserving `WHERE organization_id = @org AND id = @id`. Project `CASE WHEN octet_length(response_der) <= @max_receipt_bytes THEN response_der ELSE NULL::bytea END AS response_der` in original index 9, using `TimestampRegistryService.ExportReceiptDerLimitBytes` (1,048,576) as parameter. The comparison deliberately preserves 0-byte legacy data for the existing independent `TimestampRecord.Validate()` integrity gate; it does not reclassify invalid zero length as a size violation. Non-null `response_der` is a schema invariant. If a found authorized row has NULL projected bytea, **before** `GetFieldValue<byte[]>`, throw existing `ReceiptTooLargeException`. A truly missing ID or foreign tenant yields no row -> `null`, never 409. No preflight/fetch two-query race: SQL filter, byte count, conditional projection and row read share one PostgreSQL MVCC statement snapshot.
3. Leave `MapRecord`, Business's **tenant-first / exact-ID / size / independent SHA256 / status** checks, and API's **409/no-store before audit**, 404 for unknown/foreign, 200 exact bytes after successful prepared audit, intact. Do not touch page/search #172 generic error, ZIP #173 specialized **413**, SQL migrations, API success DTOs, ORM mapping, HTTP proxies, Azure or on-prem deployment.
4. PostgreSQL `CASE` prevents an oversized DER **from being projected into the PostgreSQL result field**, so Npgsql never calls `GetFieldValue<byte[]>` for it. It is **not** proof of zero internal PostgreSQL TOAST I/O/CPU, bounded global concurrent downloads, immutable custody, legal timestamp trust or physical storage integrity. Use a real PG17 integration test and correct failure ordering rather than claiming a memory profiler result.
5. After implementation, update this ADR, registry runbook, threat model, roadmap and #174 with exact RED/GREEN evidence. Close only #174 **if the final docs-inclusive main SHA** independently passes all 4 backend/frontend/terraform/docker-smoke jobs, ci-verdict and combined status, Business/PG17, 20 migrations/full restore, signed-Keycloak A/B receipt/ZIP/page and prepared audits, Python offline verifier, Nginx privacy/429/413/414. Keep parent #17 and #15/#13/#61/#64/#18/#38/#50 OPEN.

## Alternatives

- Business-only cap: already exists (#169), but allows SQL wire/materialization first.
- Two SELECT statements (length then DER): rejected due TOCTOU race between checks and reads.
- Reuse page/search or export SQL: rejected due mismatched return shape, different error contracts (500/413 vs receipt 409), and unnecessary scope.
- Stream oversized DER into C# only to count it: rejected because it still sends disallowed evidence over the wire.

## Legal and security stop line

Receipts are explicitly pilot `Unverified`. No WORM/long-term custody, complete-period immutable export, independently sealed audit, signed RFC3161/CMS and historical QTSP trusted-list verification, own TSA qualification or CAB/AgID approval follows. The per-receipt byte budget is an **operational pilot policy**, not an eIDAS or RFC3161 maximum.
